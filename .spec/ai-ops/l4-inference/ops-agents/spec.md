# ops-agents

诊断路径此前**完全不读运行时注册表**：管家端对一张订单发起诊断时，跑的是**烤死在代码里**的提示词。
本节点把「哪一版服务这个 `(租户, operator)`」接到既有机制上（PRD #693 的 ② 号路径）。

## raw source

与 `select_customer_agent` 分开写，而不是给它加一个 `agent_type` 参数。理由是两条路径的语义
**方向相反**：问答路径是「有 KB 才算候选」，诊断路径是「没有 KB 也能服务」（运维方法论就是
提示词本身）。把两个方向相反的谓词塞进一个函数的 `if` 里，得到的函数每条分支都要读两遍才敢改。

## 不变量

- **类型过滤按入口分叉**：consumer 行选不出 operations，operator 行选不出 customer。
  两个入口共用同一条注册表 —— 同名不同入口的漂移方向是**放宽**，所以这条判据只有一份。
- **只做查找、不做授权**：查不到即 `None`，由调用方 fail closed。
- **不回退烤死提示词**：查不到就查不到，静默回退会让"注册表没配"看起来像"配置正确"。
