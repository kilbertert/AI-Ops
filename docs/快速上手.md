# 快速上手

面向新接手的工程师、部署人员和验收人员。从零到跑出第一份诊断报告，再到生产订单诊断和多端 Gateway。

> 只看这一页就能上手。架构原理、安全模型、打包与验收细节见文末「下一步阅读」。

## 这个工具做什么

工程师用一句自然语言描述订单问题，例如：

```text
订单 2079842220423700481 金额不对，帮我排查
```

运行时提取订单号和问题意图，经 `/diag/*` HTTP 诊断接口读取订单、费用、设备与 Redis 队列证据，并在 TDengine 上执行**有界只读**查询，结合生产后端源码整理出的业务规则，返回带证据的诊断报告。**全程不提供任何写操作**：不退款、不重算、不补发、不改订单、不重启服务。

两条诊断路径：

`aiops diagnose` 是统一入口：默认走 Codex agent；加 `--mode deterministic` 走确定性规则。

| 模式 | 命令 | 适用场景 |
|------|------|----------|
| agent（默认） | `aiops diagnose` | 由模型选择只读证据工具并作因果判断 |
| deterministic | `aiops diagnose --mode deterministic` | 稳定复现已知规则结果、离线 fixture、CI 回归 |

## 前置条件

- Python ≥ 3.11
- [uv](https://docs.astral.sh/uv/)（包管理与运行）
- 生产诊断另需：`/diag/*` HTTP 内部令牌、TDengine loopback-only 只读代理凭据，以及一个 OpenAI-compatible Responses API provider key；Phase 3a 后不再保存 MySQL / Redis 凭据

## 第 0 步：安装依赖

```bash
uv sync --dev
```

## 第 1 步：5 分钟离线体验（无需任何凭据）

`init` 会在平台私有路径创建配置模板（密码留空），`diagnose --mode deterministic --fixture` 用内置合成数据，不连接任何数据库，也无需 provider key：

```bash
uv run aiops init
uv run aiops diagnose "订单 TEST-YKC-0001 金额异常" \
  --mode deterministic --fixture examples/fixtures/ykc_amount_mismatch.json
```

内置三份 fixture，覆盖三种典型场景：

```bash
examples/fixtures/ykc_amount_mismatch.json   # YKC 金额不一致
examples/fixtures/ocpp_consistent.json        # OCPP 正常订单
examples/fixtures/missing_tx_data.json        # 交易数据缺失
```

查看解析出的路径与配置（不输出任何凭据）：

```bash
uv run aiops paths
```

输出机器可读 JSON 报告：

```bash
uv run aiops diagnose "订单 TEST-YKC-0001 金额异常" \
  --mode deterministic --fixture examples/fixtures/ykc_amount_mismatch.json --json
```

> 到这里你已经能离线跑通完整诊断链路。下面的步骤需要真实凭据。

## 第 2 步：配置生产数据源

把模板复制成私有配置并填入只读凭据（**永远不要提交这个文件**）：

```bash
set -a
source /path/to/production.env
set +a
```

或用 `--config` 指定一份私有配置：

```bash
uv run aiops --config /path/to/production.env doctor
```

`production.env` 的关键字段（完整模板见 `.env.example`）：

- `AIOPS_HTTP_BASE_URL` / `AIOPS_HTTP_INTERNAL_TOKEN_SECRET`：充电桩 `/diag/*` 诊断接口地址与内部令牌，不要把令牌提交到仓库
- `AIOPS_TDENGINE_URL`：指向 `ops/` 中的 loopback-only 只读代理，**不要**直接指向 OSS REST 接口
- `AIOPS_SSH_*`：可选的 TDengine 本地 SSH 隧道转发，仅支持密钥认证

只检查数据源连通性、表和 Stream，不读订单：

```bash
uv run aiops doctor
```

## 第 3 步：用确定性规则诊断实时订单

用第 2 步配好的只读数据源对实时订单跑确定性规则诊断（无需 provider key）：

```bash
uv run aiops diagnose "订单 2079842220423700481 中途停止" --mode deterministic
```

通常无需传 `--tenant-id`：工具按订单号自动发现订单及其租户。仅当想把查询限定到某个租户时才传 `--tenant-id`；也可以用 `--order-no` 显式指定订单号。需要模型因果判断时，去掉 `--mode deterministic` 走默认 agent 路径（见第 4 步，需 provider key）。

## 第 4 步：Codex-native agent 诊断

agent 路径需要一个 provider key。key 只存放在平台私有 key slot 文件（权限 `0600`），不进 Git、不进制品。

```bash
# 安装 key（交互输入，避免命令行明文）
uv run aiops key-install primary

# 验证隔离的 Codex runtime（不暴露认证数据）
uv run aiops agent-doctor --key-slot primary

# 对合成 fixture 跑 agent 诊断（diagnose 默认即 agent 模式）
uv run aiops diagnose "订单 TEST-YKC-0001 金额异常" \
  --fixture examples/fixtures/ykc_amount_mismatch.json \
  --key-slot primary --json
```

对实时订单跑 agent：

```bash
uv run aiops diagnose "订单 2079842220423700481 金额异常" \
  --key-slot primary --json
```

- 默认把运行阶段、工具批次、合同修复和心跳显示到终端；`--no-progress` 只关闭终端显示，不关闭私有 `events.jsonl`。
- `--json` 时诊断 JSON 在 stdout，进度写 stderr，结果返回 `events_path` 和 `evidence_journal_path`。
- 心跳间隔由 `AIOPS_AGENT_HEARTBEAT_INTERVAL_SECONDS` 控制，默认 10 秒。

中断后恢复同一个 Codex thread，也可在同一 provider endpoint 下切换备用 key：

```bash
uv run aiops agent-resume RUN_ID --key-slot backup --json
```

恢复时会比较当前 `AIOPS_CODEX_BASE_URL` 与运行记录的 endpoint，拒绝把 key 重定向到另一台主机。

## 第 5 步：交互式 shell

连续诊断多条订单：

```bash
uv run aiops shell
# 或用 fixture
uv run aiops shell --fixture examples/fixtures/ykc_amount_mismatch.json
```

在 `aiops>` 提示符输入反馈，`exit` / `quit` / `退出` 退出。

## 第 6 步：多端 Gateway 模式

便携包不应直接携带数据库、SSH 或 provider 凭据。推荐由一台固定服务器运行 `aiops-gateway`，各端通过一次性注册连接同一 workspace。

**服务端**（只在该服务器上保留私有 `production.env`）：

```bash
# 工作区级注册（推荐）：不传 --tenant-id，注册后的设备可诊断任意订单
uv run aiops-gateway issue-enrollment --workspace ops
uv run aiops-gateway serve
```

`--tenant-id` 可选：不传即工作区级（任意订单可查，由 `order_snapshot` 按订单号自动发现租户）；仅当需把设备限制到单一租户时才传。

**客户端**（注册一次即可）：

```bash
aiops remote enroll --url https://aiops.example.com --code-file /secure/gateway-enrollment.code
aiops remote doctor
aiops remote runs
aiops remote diagnose "订单 123 金额异常" --json
```

注册码只能兑换一次，注册成功后不要再次执行 remote enroll。如果不想保存注册码文件，可以省略 --code-file，程序会隐藏输入并交互式提示注册码：

```bash
aiops remote enroll --url https://aiops.example.com
```

注册成功后可删除本地注册码文件。remote doctor 是公开健康检查；remote runs 才会验证设备令牌。诊断结束后可用 remote show RUN_ID 查看结果，用 remote events RUN_ID --after 0 追溯中间事件。

查看与同步 run：

```bash
aiops remote runs                       # 列出最近 run
aiops remote show RUN_ID                # 查看某 run 结果
aiops remote events RUN_ID --after 0    # 增量同步事件
aiops remote logout                     # 清除本机 profile 与令牌
```

> 当前 Gateway 是单节点 MVP，仅适合内网与受控验收。正式公网部署前必须完成 TLS、OIDC/mTLS、Vault/KMS、PostgreSQL 等硬化，详见 [Gateway 架构与部署](gateway.md)。

## 退出码

| 退出码 | 含义 |
|--------|------|
| 0 | 诊断成功 |
| 2 | 配置、运行时或数据源错误 |
| 3 | agent 诊断结论为 INCONCLUSIVE（证据不足） |
| 4 | agent 诊断被 BLOCKED |

## 常见问题

- **`diagnose` 用 fixture 能跑，连真实库就报错**：先 `aiops doctor` 确认连通性；TDengine 必须走 `ops/` 的 loopback-only 代理，不能直连 OSS REST。
- **agent 诊断报 provider 错误**：provider 可能因额度或模型策略拒绝请求，失败会写入 `events.jsonl`，可在不改变事件 manifest 的前提下 `agent-resume` 恢复。
- **想换台电脑看 run 进度**：用 Gateway 模式，不要向每台电脑分发数据库密码。
- **remote diagnose 只显示 interrupted**：使用同一 run ID 执行 `aiops remote show RUN_ID`，新版会显示脱敏的错误类型和错误原因；同时用 `remote events RUN_ID --after 0` 查看排队、worker、provider 和中断事件。

## 安全边界（一句话）

凭据只来自环境变量或私有配置，所有输出脱敏；报告不输出用户 ID、VIN、卡号、车牌号和原始协议 payload；agent 工具层只读，模型命令禁网，不提供任何业务写能力。完整边界见 [README](../README.md) 与 [系统架构](architecture.md)。
