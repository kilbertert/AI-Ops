## 2026-09-23：CD 并发配置修正（PR #397，已验收）

- **来源**：workflow 层首次验收时 run 卡在 `pending` 永不推进。GitHub 明写

## 2026-09-23：41 runbook 试跑——抓到并修复 sync-check 残留污染（PR #386）

- **来源**：在 41 上实跑 #384 修订后的部署流程。试跑时**故意预置陷阱**（在

## 2026-09-16：快捷动作跳转站内页面（#260 规格，切片 #261–#264 全部完成）

**规格**：#260 `spec(assistant): 快捷动作支持跳转站内页面`。

**领域模型变更**：产品快捷动作由一元概念拆为两种形态 —— **提示动作**（经统一助手入口发起预设提问）与**跳转动作**（由客户端导航，不经入口、不创建作业）。判别依据是 `jump_path` 非空。词汇表（`CONTEXT.md`）与 ADR 0006 已记录。

**交付**：

| 切片 | 内容 |
|---|---|
| #261 | `jump_path` 字段进既有自由字段集合（无 DDL、无迁移）；列表每条恒返回，非跳转动作为 `null` |
| #262 | 统一入口防御分支：跳转动作误投时同步澄清、**不创建任何作业**，且置于订单路由之前 |
| #263 | 词汇表、ADR 0006、前端契约 D.1/D.2a/D.4、Gherkin 四条 Rule、QA 用例 SHORTCUT-JUMP-01..10 |
| #264 | 41 部署 `d2c35f5` + 三条 `report_fault` 就地改造 + 公网真实验收 |

**关键设计取舍**：不引入第二判别字段（产品面板文案、领域判断、前端实现三方均收敛到"有路径即跳转"）；不做路由白名单（仓库无权威 H5 路由约定，硬编等于把前端路由表抄进后端）；路径不国际化（名称已由语言字典承担）。

**开发中发现并修复的缺陷**（均已复现后修复并加回归测试）：
1. `PUT` 缺省 `jump_path` 会**静默清空**——只改标签就把跳转动作降级为提示动作。现为：缺省=不变，显式 `null`/空白=清空。
2. `shortcut_migration` 丢弃 `jump_path`，导致平台默认对已有租户副本静默失效。
3. 两层校验对"路径"定义不一致（HTTP 接受 `"/x "`，生命周期层再规范化）。
4. **开放重定向**：`//evil.com` 曾通过 `^/\S*$`；按 RFC 3986 §4.2 `//` 开头是 authority 而非路径。现两层均拒绝。
5. `jump_path` 与宣传 `target_agent_version` 曾可同时配置（死配置 + 活副作用：pin 会把该 agent 排除在客服 agent 选择之外）。

**运维改进**：41 已配置 SSH 密钥登录（`~/.ssh/id_ed25519_41_aiops` + `aiops-41` 别名），后续部署不再依赖现场口令。CI 的 `verify` 迁到自托管 runner（**59s**，原约 4.5 分钟），并关闭该 job 的缓存保存——其 post-job `uv cache prune` 会操作开发机的共享缓存（约 900M）并悬置失败，属破坏性问题。

**真实环境**：41 公网验收 SHORTCUT-JUMP-08/09/10 全部 PASS，证据见 `docs/validation.md`。
