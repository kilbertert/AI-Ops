# 打包与下载

拿到一个能用的 AI-Ops Windows 便携包，有三条路。先看选哪条，再看怎么做。

> Windows 运行要求、首次运行、安全边界见 [便携部署](portable.md)。本文只讲"怎么把包弄到手"。

## 选哪条

| 方式 | 什么时候用 | 前提 |
|------|-----------|------|
| **① 下载 CI 制品**（推荐） | 日常拿最新 main 的包 | 能访问 GitHub |
| **② 服务器中转下载** | ① 太慢（国内网络 gh 下载慢） | 有能访问 GitHub 的服务器 + Tailscale |
| **③ 本机构建** | 改了代码想立刻测，或要 Linux 包 | 目标系统的开发机 |

三种方式拿到的都是同一个东西：`aiops-diagnostics-<version>-<system>-<machine>.zip`（如 `aiops-diagnostics-0.1.0-windows-x86_64.zip`）。

---

## ① 下载 CI 制品（推荐）

每次 PR 和合并到 `main`，CI 的 `windows-verify` job 都会在 Windows runner 上构建并上传 Windows 包。artifact 名是 `aiops-diagnostics-windows-<提交SHA>`，保留 7 天。

**第 1 步：找最新的成功 run**

```bash
gh run list --repo kilbertert/AI-Ops --branch main --limit 5
```

取最近一条 `success` 的 run id（第一列）。

**第 2 步：下载**

```bash
# 方式 A：浏览器（最省事）
# 打开 https://github.com/kilbertert/AI-Ops/actions/runs/<run-id>
# 拉到最下面 "Artifacts" 区，点名字下载

# 方式 B：gh（国内网络可能慢）
gh run download <run-id> --repo kilbertert/AI-Ops \
  -n aiops-diagnostics-windows-<SHA>
```

`<SHA>` 是构建时的提交哈希，出现在 artifact 名里，用来确认你下的是哪个版本。

下完是一个 zip，直接跳到下面的 [解压后怎么用](#解压后怎么用)。

---

## ② 服务器中转下载（gh 太慢时）

国内直连 GitHub 下 artifact 经常很慢。可以在服务器上拉下来（服务器到 GitHub 通常更快），再用一个**临时 HTTP 服务走 Tailscale** 给本机下，速度等于内网。

**第 1 步：在服务器上下载 artifact**

```bash
mkdir -p /tmp/aiops-dl && cd /tmp/aiops-dl
gh run download <run-id> --repo kilbertert/AI-Ops \
  -n aiops-diagnostics-windows-<SHA>
# gh 会解压成目录，把里面的 zip 拷出来改成简单名
cp aiops-diagnostics-*/aiops-diagnostics-*.zip ./aiops-windows.zip
```

**第 2 步：起临时 HTTP 服务，只绑 Tailscale IP（公网不可达）**

```bash
# 查本机 Tailscale IP
TAILSCALE_IP=$(tailscale ip -4)
# 在下载目录起服务
cd /tmp/aiops-dl
python3 -m http.server 10080 --bind "$TAILSCALE_IP"
#（这个命令会前台占住，下完 Ctrl-C 关掉）
```

**第 3 步：在本机（Tailscale 内）下载**

```powershell
# Windows PowerShell：<tailscale-host> 就是 Gateway 用的那个 Tailscale 主机名
Invoke-WebRequest http://<tailscale-host>:10080/aiops-windows.zip -OutFile D:\aiops-windows.zip
# 或浏览器打开那个 URL
```

**第 4 步：下完关掉服务器上的临时服务**（Ctrl-C 或 `kill`），别一直开着。

> 这个方法只把 zip 暴露给 Tailscale 内的机器，公网访问不到；zip 本身不含 API key 或数据库凭据。

## ③ 本机构建

改了代码想立刻测，或者需要 Linux 包，就在本机构建。

**关键限制：必须在目标操作系统上构建。** Codex SDK 携带平台专用原生 runtime，不能交叉构建——Windows 机出 Windows 包，Linux 机出 Linux 包。

```bash
uv sync --locked --dev
uv run python packaging/build_portable.py
```

产出（在 `dist/` 下）：

- `dist/aiops/`：PyInstaller 冻结目录，可直接跑里面的 `aiops`（Linux）或 `aiops.exe`（Windows）。
- `dist/aiops-diagnostics-<version>-<system>-<machine>.zip`：可分发的版本化 ZIP。
  - `<version>` 来自 `pyproject.toml`（当前 `0.1.0`）。
  - `<system>` = `windows` 或 `linux`。
  - `<machine>` = `x86_64`。
  - 例：`aiops-diagnostics-0.1.0-windows-x86_64.zip`。

**构建会自动烟测**：在源码目录外解压 ZIP、以最小 PATH 启动、初始化隔离 home、检查 key slot 和内置 Codex runtime、验证私有路径权限、拒绝制品里的秘密文件、诊断三份 fixture、连本地 mock Gateway 跑 `remote enroll/doctor/runs`。**烟测失败不会产出 ZIP**，先修烟测再重试。

---

## 解压后怎么用

把 zip 解压到目标目录（如 `D:\aiops`），按 [便携部署](portable.md) 的"首次运行"初始化：

```powershell
.\aiops.exe init
.\aiops.exe paths
.\aiops.exe key-install primary
.\aiops.exe agent-doctor --key-slot primary
```

工区级注册一次后，日常诊断只需：

```powershell
.\aiops.exe remote diagnose "订单 xxx 有问题"
```

---

## 提醒

- CI artifact **7 天过期**；要长期保留，下完存到企业制品库，别依赖 GitHub。
- ZIP **不含** API key / 数据库 / SSH 凭据（设计如此）；凭据只在外部 key slot 和服务器私有配置里。
- 当前 ZIP **未签名**；企业广泛分发前补 Windows 代码签名。
- Linux 制品 CI 不上传（`verify` job 只跑测试），需要时走 ③ 本机构建。
