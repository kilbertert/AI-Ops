# 可信业务环境入口验证

判据：已确认跨服务器需求、公司源码调查、RFC8725与nginx官方map/proxy/TLS合同。

| 用例 | 环境/步骤 | 预期 |
|---|---|---|
| ENV-IN-01 | 两个回环临时HTTP服务＋真实nginx；相同用户Authorization分别携带A/B来源 | 只命中各自目标，Authorization保留；凭据不进响应 |
| ENV-IN-02 | 缺来源、错误来源、重复来源头、伪造业务环境头、JWT自报domain | 拒绝未知来源；伪造环境不改变选择；无跨目标调用 |
| ENV-IN-03 | 停止A服务，再请求A/B | A失败不重试B，B响应正常 |
| ENV-IN-04 | 隔离HTTPS服务与合成证书 | 可信CA/域名通过；错误CA或名字拒绝，禁止关闭TLS校验 |
| ENV-IN-05 | 不合法、重复目录记录及配置注入值 | 构建前拒绝，无输出；渲染输出0600 |

每次测试使用动态回环端口和临时数据根，结束关闭本次nginx/服务并删除临时根。
无需公司令牌、生产数据或新公开入口。后端替身只证明分流与传输，不证明用户登录、真实CPMS、Dify模型或跨环境业务准确率。
现役Gateway已有验收skill另在一次性数据根启动验证；本轮不上生产，真实双环境仍待有效目录和访问条件。
