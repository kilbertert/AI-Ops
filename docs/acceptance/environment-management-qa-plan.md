# 环境管理首片验收

依据：用户已确认的2026-11-14公司网关方案。本片交付目录schema升级、受控管理API与原Dify管理页；
环境连接由受管CLI预登记，页面只能修改显示名称与已登记环境/租户准入，不提供任意URL或主机执行能力。
后续公司网关身份适配、真实租户发现与自动开户任务继续按总方案推进，页面不伪装这些能力已完成。

| 用例 | 环境/前置 | 步骤 | 预期/清理 |
|---|---|---|---|
| E1 | 临时私有目录，两个环境同租户编号 | 原CLI迁移；读取schema和准入；升级后尝试旧写入 | 字段/审计保留；不允许旧CLI降级覆盖；清理临时根 |
| E2 | 临时真实Gateway/同源桥，公司身份受控替身 | 匿名、普通租户、未授权平台与仅A授权管理者调用列表/更新 | 鉴权与环境范围有效；无端点/路径/密钥回传；服务关闭 |
| E3 | A/B目录版本一致 | A停用、B访问、陈旧版本重写、注入字段与未登记租户 | A后续准入拒绝，B继续；冲突409/非法输入拒绝，不丢更新 |
| E4 | Dify浏览器组件及受控API响应 | 打开原AI管理页，选择环境，修改名称，保存冲突后刷新，切换另一环境 | 表单不串状态；保存按版本；未验环境保持待验；浏览器退出 |
| E5 | 一次性Gateway skill | 运行observe.py | 启动/鉴权/公开规范/退役路由通过，不证明远端业务 |

新增检查拦截跨环境运维越权、目录降级丢数据和页面编辑串环境；判据来自已确认合同，旧单环境检查没有这些入口。
真实公司身份、Dify原页面部署与第二环境业务验收分别记结果；本地替身不证明它们。
