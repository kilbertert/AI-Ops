# 环境目录草稿QA

本片为P1的目录准备接口，不启用目标环境；P0真实模块与容量条件继续保留。
判据来自已确认手工目录规划及[Feature](environment-directory.feature)。

| ID | 环境/前置 | 步骤与输入 | 可观察结果/清理 |
|---|---|---|---|
| D1 | 临时目录，已生效A、获授权管理员 | API保存A新连接和B草稿，再调用现役环境读取 | 草稿返回版本，A仍旧连接，B未准入；临时根删除 |
| D2 | 两客户端读同版本 | 同时提交不同内容；撤权后重放 | 只有一个新版本，另一409；撤权403；历史不丢 |
| D3 | 空目录和显式全局管理员 | CLI引导，正常会话读/保存 | 可配置第一个环境，不启用业务；不要求目标环境登录 |
| D4 | 未授权主体/恶意载荷 | 换环境、填userinfo URL、config_ref/任意字段 | 403/422且不写草稿，凭据不回显 |
| D5 | 真Gateway一次性根 | 启动并访问新增匿名API、原接口 | 鉴权拒绝，启动/原规范正常；进程清理 |

新增检查仅覆盖原检查没有的草稿持久化、版本冲突和管理授权；复用pytest/真实HTTP和Gateway验证技能。
静态和隔离验证不能证明真实公司登录、远端网络、模型run或知识活性；这些沿P0/P5继续验收。
