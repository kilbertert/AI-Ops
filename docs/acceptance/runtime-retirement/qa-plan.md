# 退役部署与真实业务验收

仅当合并版本、部署、必需检查及下列真实业务用例通过后，开始目录迁移。
本计划补齐本轮交付契约；它不追认先前仅有本地测试的结果为业务验收。

| ID | 环境与前置 | 操作与数据 | 预期与清理 |
|---|---|---|---|
| RT-01 | 本地一次性根 | Gateway 验证技能；旧路由与匿名现役接口 | 旧路由404、现役鉴权401、健康及规范200；清理本次进程 |
| RT-02 | 生产，合并制品与备份就绪 | 核版本、模块摘要、命令、依赖、现役发布绑定 | 成套一致，服务只读；失败恢复旧环境，不覆盖业务数据 |
| RT-03 | 正常C端登录、本人订单、工作流已发布 | 原助手提普通知识问题，再点订单检测；按每个QA回读并独立读CPMS | 原入口结果可读，订单/状态/来源一致；不伪造模型或回调 |
| RT-04 | 正常管家个人登录及范围内订单 | 原助手单订单任务、精确QA/run对账 | Java节点匹配，CPMS证据属于本轮，结果完成可读 |
| RT-05 | 已有合法另一主体及不可见订单/QA | 请求不属于本人的订单/结果，无身份请求 | 拒绝且无正文；不修改用户权限造反例 |
| RT-06 | 有效控制台登录、登记应用 | 从原试用入口发起草稿，核结果与发布前后指针 | Dify/Java对应路线完成，正式指针不变；临时应用按试用生命周期清理 |
| RT-07 | 生产运维配置 | aiops-admin 帮助与只读/dry-run，检查旧命令/模块 | 新命令可用，旧执行器不存在，不运行旧恢复工具 |

真实用例沿用环境手册和对应业务手册。身份失效、无可用订单、供应商/节点失败等均记录未通过，
不使用构造身份、fixture 或其他QA的成功记录替代。原始会话/订单/响应/日志只存私有证据；
仓库只提交经脱敏的结果、版本、时间和缺口。正常问答产生的QA/审计保留，不整库回滚。
