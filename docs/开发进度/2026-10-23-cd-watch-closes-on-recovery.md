## 2026-10-23 · 告警票在恢复时由守望者关闭（#792）

**目标/分支**：`fix/cd-watch-closes-on-recovery`，基线 `5a45567`。

### 一、#792 是一张早已自愈却没人关的票

开于 10-14，最后评论 10-15。而 CD 自 10-23 12:17 起连续 7 次 success。

根因：`cd-watch.mjs` 的 `result.ok` 分支只 `console.log` 然后 return —— 只有开票 /
评论，**没有关闭路径**。

### 二、为什么不只是「关掉 #792」

在 issue 列表上「八天前已恢复」与「仍在坏」长得一样。告警系统的信号是「开着的票 =
有人要处理」，一张早好了却开着的票把这个信号毁掉。

### 三、改法

`recoveryOutcome()` 纯函数四条分支；健康且有开票时**先评论再关闭**。
抽出纯函数是为了能脱离 GitHub API 测试——`announce` 的副作用从来没有单测，
这正是缺陷活到今天的原因。

### 四、判据

`cd-watch.test.mjs` 28 → 32 条；三处变异各自转红一条。
`--dry-run` 现在会正确预览「将关闭 #792」。

### 五、顺手修的

第一版 dry-run 跳过票查询，会对着有开票的仓库打印「CD 状态正常」——
dry-run 的意义正是预览关闭动作，跳过查询等于答非所问。

### 六、待验证

#792 会在下一次 `cd-watch` 运行时（每日）被关闭。**本次合并不会立刻关闭它** ——
要等那次定时运行，或手动跑一次。
