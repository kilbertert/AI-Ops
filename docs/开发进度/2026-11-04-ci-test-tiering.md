# 2026-11-04：CI 测试分档

**里程碑目标**：全量测试 192 秒是 CI 的 86%，而三分之一的提交只改文档。按改动范围
决定测试档位，不删测试。

**当前分支或提交**：`ci/test-tiering`，base 见 PR。

## 已完成内容

`ci.yml` 加一步 `Decide the test tier`：

- 改动全部在 `docs/` 或根层 `*.md` → **738 条 / 32 秒**
- 其它任何情况 → **4141 条 / 192 秒**（保持现状）

判定写成「默认全量，白名单才降级」。理由与踩过的坑写在 `ci.yml` 那一步的注释里，
以及 [本日验收记录](../validation/2026-11-04-ci-test-tiering.md)。

## 为什么选这个而不是直接删

删掉全量测试是唯一一个**会静默退化**的选项：`verify` 是必需检查（ruleset
23760870），删了之后它只剩静态检查。分档的错误形态是多跑三分钟，不是假绿。

- **反向验证**：去掉正则锚点后两条反例转红；其中 `sub/docs/a.md` 是第一版真放过的
  漏洞，被这套测试抓出来并修掉。
- 全量 `4141 passed, 9 skipped in 204.95s`；`ruff check` / `format --check` 通过。
