# 站点说明把通用名词判成编造站名（2026-11-02）

承接同日的[拒收定位记录](2026-11-02-site-answer-refusal-evidence.md)。那一片只加了
`rule=` 日志，把"拒在哪条规则"变成可读；这一片是那条日志指向的真实根因与修复。

## 现象

管家原 H5 问「我有哪些站点？」时，节点已经取到 `cpms_site_search` 证据并上报成功，
最终仍整轮 `OPERATOR_INVALID_ANSWER`。2026-11-02 的两次真实失败（12:04:02Z、
12:05:28Z）在证据、授权、工具链三处都正常。

## 定位方法

取该回合**冻结**的 `execution_manifest.system_messages` 与本轮
`cpms_site_search` 证据，按节点同一条消息序列重放，请求发给节点所用的上游模型，
只重放模型这一步，不再动生产。18 次采样中 **3 次拒收，全部命中
`rule=note_site_name`**：

| 模型写的说明（摘） | 触发片段 |
|---|---|
| `…可以告诉我站点名称或城市关键词，我再帮你缩小范围。` | `可以告诉我站点` |
| `…如需按地点或站名筛选，也可以告诉我。` | `如需按地点或站` |
| `…或直接选择某个具体地点查看详情。` | `站点详情` 一类通用名词 |

## 根因

`operator_conversation.SITE_NAME_SHAPE` 的中文分支是
`[一-鿿]{2,8}(?<!的)(?:充电站|站点|站|充电桩|桩)`：只要 2-8 个汉字紧跟
「站/桩」，就判成**站名**。它挡住编造站名（`我帮你找到了虚构乙站`）是对的，但
「站点名称」「站点详情」「核对站点列表」这类**通用名词短语**同样命中 —— 模型只是在
按提示词追问筛选条件，并没有给任何地方起名。

后果不是措辞问题：`validate_site_note` 抛 `OperatorRefused`，整轮回答作废。所以站点
问答的成功率取决于模型这轮怎么措辞，18 次采样中约 1/6 会因此失败。

## 修复

先在判站名形状**之前**把 `GENERIC_SITE_WORDS`（`站点名称`、`站名`、`站点详情`、
`站点列表`、`站点信息`…）这些**完整短语**整条替换成「结果」，再走原来的形状判据。
收窄发生在短语层，形状层一字未改。

先试过「站字后面紧跟某个字就跳过」的写法（`(?![名称点数列…])`），复审指出它会放行
`虚构乙站详情`：跳过了「详」，剩下的 `虚构乙站` 也就没被看见。整条短语替换没有这个洞
——`虚构乙站详情` 里没有 `站点详情` 这条词，判据照常命中。

另修一处真 bug：英文分支的限定词前瞻写成小写（`the|a|an|…`），而名字分支要求大写开头，
于是 `Your stations` 从来没被排除过。改为大小写不敏感前瞻。这里**不扩大**英文匹配范围：
大写 `Station`/`Site` 后缀与原来一样**不算**站名。

判据方向没有放宽：编造站名仍然拒（`虚构乙站`、`虚构乙站详情`、`天河测试站信息`、
`为您查询天河测试站`）。
