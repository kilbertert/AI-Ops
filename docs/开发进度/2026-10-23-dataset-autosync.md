## 2026-10-23 · 建库同步不再需要人工跑命令（#1056）

**用户原话**：「我需要彻底贯通全流程链路，而不是某一个环节还需要人工跑命令」。

**此前的断点**：#925 让 RAGFlow 的新库**立刻**出现在我们自己的清单里，但 Dify 编排页的
「添加知识库」选择器读的是 **Dify 自己的 dataset 表**。中间横着
`aiops admin sync-knowledge-datasets`，运营看不到、跑不了，于是现象是「我建了库，Dify 没有」。
真机上因此出现过两次。

**做法**：把收敛挂在**选择器打开那一刻**（`GET /v1/dify/knowledge`），不挂定时器。

三条约束，缺一条都是事故：
1. **失败绝不改变清单返回** —— 网关层与引擎层各一道 try；一次 Dify 抖动让运营连已有的库
   都选不到，比「新库没出现」严重得多（这条用例先写、先红，再补的实现）；
2. **同租户 30s 下限** —— 选择器连打几个请求时不能每个都写一遍；
3. **绝不删** —— `orphans` 只进日志，Dify 没有恢复入口。

还有一条：**一次只跑一个 pass**。两次并发会各自决定「要建」，而 Dify 对 `(tenant, name)`
没有唯一约束，输的一方留下重复。

**与 ADR-0096 不是反转**：那条「不自动同步」管的是**正文**（会把打字打到一半的 prompt
推给真实用户）；这里同步的是**建库**，纯增量幂等，不碰任何正文。

**判据**：引擎级 4 条（吞异常 / 失败下限 / 成功下限 / 过了下限重试）+ 路由级 3 条
（每个租户尝试一次 / 同步炸了清单照常 / 没配模板就完全不尝试）。
**两处变异转红**：引擎不吞异常、去掉下限。

**代价**：新增 `AIOPS_GATEWAY_DIFY_EXTERNAL_KNOWLEDGE_API_ID`（留空即不启用）；
清单路由从此有写副作用 —— 这条写进 ADR-0122，免得下一个人把它当纯读接口加重试。

**交付**：本分支。
