## 2026-10-23 · 发布 0.2.0，0.1.0 冻结为指针

**目标/分支**：`chore/release-0-2-0`，基线 `cba561f`。

### 一、版本机制第一次被真正使用

`VERSION` 自 #1037 建立后一直是 `0.1.0`，机制建好但没人用。本次推进到 `0.2.0`，
三处声明（`VERSION` / `pyproject.toml` / `__init__.py`）同步，由
`tests/test_release_version.py` 保证。合入后 CD 首次部署会自动建 `v0.2.0` tag。

### 二、顺手修掉发布说明里的一个假声明

`RELEASE-NOTES.md` 头部说「面向用户、由人撰写」，但 `[0.1.0]` 一节实际是 **509 条**
（266 英文 commit 标题 + 243 中文）的混合转载——与声明矛盾。按决定冻结为指向 git 历史
的指针，人写的新说明从 `0.2.0` 开始。

同时删掉头部一个已失效的数字：「本文件是 580 行 / 524 条」在冻结后不再成立。

### 三、判据

```bash
pytest tests/test_release_version.py   # 4 passed

```

### 四、待验证

**`v0.2.0` tag 要等合入后的 CD 部署才会出现。** 本 PR 只改 `VERSION`；tag 由 CD 建。

### 五、发版暴露的三处「写死版本号」

改 `VERSION` 后三个测试变红，都是**正确的后果**，但其中两处暴露了真实的脆弱：

| 测试 | 原因 | 处理 |
|---|---|---|
| `test_remote_block_renders_and_parses` | 未提交时 `deploy-41.sh` 混用两棵树的版本 | 提交后自愈；**脆弱点另记** |
| `test_receipt_reports_the_version_gap_instead_of_pretending` | 断言写死 `"0.1.0"` | 改为读 `VERSION` |
| `test_gateway_context_digest_is_reproducible...` | `src/` 变了，摘要必变 | 重算锁文件 |

第二处值得记：它钉的是「回执**报告**版本」，而不是「版本恰好是 0.1.0」。写死让每次发版都
红在一个与回执无关的原因上。

**第一处暴露了 `deploy-41.sh` 的一个真实缺陷**：`INIT` 取自目标 commit 的产物（`$WORK`），
而 `FILE_VERSION` 取自当前工作树（`$REPO_ROOT/VERSION`）——两棵不同的树。工作树有未提交
改动时，断言会在一个与部署无关的时刻失败。本次靠「先提交」绕过，未修。
