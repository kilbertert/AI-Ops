# AFK 脚手架升级到 1.7.34：AFK 日志不再被心跳帧淹没

日期：2026-10-27。分支 `chore/upgrade-afk-1-7-34`，基线 `524b7f3b`。PR #1112。

## 目标

`agent-implement-prd.yml` 在 Actions 里刷屏：执行日志绝大多数是心跳，而不是运行情况。
本轮从 `1.7.28` 一次升级到 `1.7.34`，把刷屏的根因修掉。

## 根因（实测，不是推断）

`verbose: true` —— 1.6.5 加的，目的是让 Read / Edit / MCP 这些 sandcastle 类型化
`toolCall` 事件不认识的工具调用可见 —— 的实现是**照写每一行原始 stdout**。

Claude Code 2.1.311 在模型思考期间会持续发这类帧：

```json
{"type":"system","subtype":"thinking_tokens","estimated_tokens":42,"estimated_tokens_delta":4,…}
```

实测（2026-10-27，Claude Code 2.1.311，本机中继 profile，一条真实 prompt）：

| 帧类型 | 条数 | 字节占比 |
|---|---|---|
| `system/thinking_tokens` | 227–342 | **58%** |
| `hook_response` / `init` / `assistant` / `result` | 8 | 42% |

真正的工具调用只有几行，其余是整个可见运行的心跳。

CLI 侧没有开关：`CLAUDE_CODE_DISABLE_THINKING=1` 仍发 232 帧，
`CLAUDE_CODE_THINKING_DISPLAY_UPDATES=0` 仍发 342 帧。该帧属于 stream-json 的契约
（交互式客户端拿它当 spinner），所以过滤器只能放在我们这一侧。

## 已完成内容

`upgrade-afk.sh` 从 `1.7.28` 连续升级到 `1.7.34`，本仓落地的文件：

- `.sandcastle/quiet-heartbeats.ts`（新增）—— 包一层 `process.stdout.write`，按
  **解析后的** `type`/`subtype` 丢弃心跳帧。
- `.sandcastle/quiet-heartbeats.check.ts`（新增）—— 匹配本身、写契约、接线各有断言。
- `.sandcastle/profile.ts` —— `claudeProfile()` 里装一次，七个 runner 全部覆盖。
- `.github/workflows/afk-policy.yml` —— CI 跑那条 check。
- `.afk-bootstrap.json` —— `1.7.28` → `1.7.34`。

同批还带进来 1.7.29–1.7.33 之间与本仓无关的模板修订（审查判据、`-n 4` 等），
它们由同一个 `upgrade-afk.sh` 连续应用，没有可以单独拆出的稳定中间点。

## 已知缺口

- `REPO-MAP.md` 在本仓已移出版本控制（`conflict-surface` 的 `removed` 处置）。
  升级脚本生成的副本只留在工作区，**不提交** —— 第一次提交时把它带了进去，
  被 `Workflow policy` 的 `conflict-surface --check` 拦下，已从索引撤回。
- 过滤器的接线断言是源码级作用域检查，不是执行验证：把安装调用挪进
  `claudeProfile` 内部**声明但从不调用**的嵌套函数仍会通过。彻底修需要调用图，
  即 import `@ai-hero/sandcastle` —— 而那正是该 check 要能在裸脚手架里跑的前提。
  该边界已写进 check 源码，并在检测到该形状时打印 note。
