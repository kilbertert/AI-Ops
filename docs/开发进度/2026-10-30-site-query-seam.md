# 站点查询抽成可复用单元（#1187）

分支 `refactor/site-query-seam`，基线 `42884f1b`。

## 目标

站点查询原来只能从对话回合的完成回调里执行：输入是模型回答的 dict，可见范围靠一个授权
回调，读取、逐行核对、结果对齐与渲染混在同一段里。本片把它拆成一个可显式驱动的单元，
让 #1191（管家工具）与 #1192（C 端接口）用同一份实现，而不是各自再写一遍范围推导。

## 已完成

- **`SiteScope`**：可见范围的值对象。`site_ids` 的三种含义分开表达且不能互相顶替——
  `()` 空范围（不查 CPMS）、`None` 未按站点集合收窄（顶层账号的租户口径）、非空元组
  （员工账号能看到的站点）。`fingerprint` 不参与过滤，只用于逐页复核范围没变过。
- **`SiteKeywords`**：关键词的值对象。`listing` 表达「四个字段全空 = 列举」，
  `params()` 把多条地址词压成 CPMS 唯一的 `address`（取最长，与原行为一致）。
- **`site_scope()` / `site_keywords()`**：把调用者的数据范围和对话协议的四个字段翻译成
  上面两个值对象。账号层面的判据仍留在 `operator_scope` 里，没有复制一份——换入口要换的是
  那套判据，不是「站点怎么查」。
- **`cpms_site_reader(base, bearer)`**：读取函数成为入参。节点代理那条路（节点持令牌、
  网关只放行）因此可以换一个 reader 而不用改查询本身。
- **`query_sites(scope, keywords, read, reauthorize)`**：范围判定（含逐页复核）、CPMS 读取、
  结果对齐与计数口径合流到一处。空范围不发任何 CPMS 请求。
- 三个上限抽成有名常量 `SITE_PAGE_SIZE` / `SITE_MAX_PAGES` / `SITE_MAX_SHOWN`，取值与
  拆分前逐字相同。
- 顺带把四处重复的 `operator_conversation` 惰性导入收成模块级一处（该模块本就是本文件的
  依赖，惰性导入只让类型检查看不出它一定绑定）。

## 缺口与边界

- **未完成业务验收**：没有真实 CPMS 调用、没有真实账号、没有真实页面。本片是纯重构，
  验收判据是「现有断言不改仍全绿」，不是业务结论。
- 四张后续票（#1188 能力轴、#1189 授权装请求目标、#1191 站点工具、#1192 C 端接口）
  都还没开始；本片只让它们的落点变干净。
- `query_sites` 现在抛 `OperatorRefused`。C 端接口（#1192）需要把它映射成自己的错误码，
  这是有意留在那张票里解决的，本片不预先发明 C 端的错误分类。
- 站点查询仍然是「一次列举最多 4 页、展示最多 10 条」，改造没有放宽任何一条上限。
