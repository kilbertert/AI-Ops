# 订单查询三个反馈的交付规格

用户已确认：慢查询覆盖 Dify 与 H5；订单日志指充电事件／设备通讯报文；按方案实施。

## 问题与范围

1. 订单问答直到整轮完成才显示结果，缺少实际阶段耗时；普通查单常扩展成完整诊断，失败重派放大等待。
2. 当前工具只有订单、计费、遥测等证据，通讯报文未接入；历史解释不能冒充本轮报文查询。
3. 管家请求实际在 Java 链执行，Dify 原生日志不记录这些请求。

## 方案与分工

| 工单 | 交付 | 依赖 |
|---|---|---|
| RUN | 同一运行的有界阶段记录；授权后的轮询进度；Dify 原生进度；按需取证和简短默认回答 | 无 |
| COMM | 从已授权订单派生设备与时间窗口，读取并呈现真实报文／事件及覆盖边界 | 无 |
| LOG | Dify 原日志入口展示当前有权查看的 Java 运行记录与耗时 | RUN 的记录合同 |

共用记录留在 `execution/agent_runs.py`：`trace` 为有界列表，每项仅含 `phase`、
`elapsed_ms`、`at`、`status`，工具事件另有 `tool`，结束事件有 `duration_ms`。阶段为 `dispatch`、`tool`、
`review`、`resample`、`completed`、`failed`；事件记录真实发生时间，不推断模型内部思考。
耗时使用单调时钟，持久时间使用 UTC 的 RFC 3339；不加入第三方遥测后端。
标准映射：[RFC 3339 §5.6](https://www.rfc-editor.org/rfc/rfc3339#section-5.6) 的带时区时间，
[HTML SSE](https://html.spec.whatwg.org/multipage/server-sent-events.html#server-sent-events) 的 UTF-8事件帧；
Dify 1.17.1 的 `onThought/mergeStreamingThought` 同 ID 替换显示，最终答复使用独立显示项。
日志只读该合同及已有时间/状态，禁止直接输出快照、令牌、工具参数和原始模型输入。
旧记录没有阶段数据时明确显示“阶段耗时未采集”。

日志入口必须通过当前 Dify 应用访问权和公司身份核验，按 `publication_app_id`、
当前租户与调用者筛选。持久运行元数据与有时效的业务结果交付分开；过期不伪装失败，
撤权后不能从日志重新取得答案或业务证据。首版只展示本人记录，不扩大员工可见范围。

通讯数据的字段、方向与关联判据以实际公司接口实现为准；不能仅凭旧 SOP 认定。
表、字段、行数、窗口由程序固定，模型不能提供 SQL、URL 或越过订单指定设备。
同设备窗口可能混入其他交易：只能明确标为窗口候选，不能假定每条属于当前订单。
报文保留字段采用白名单，未知字段不透传，空结果／截断／源不可用分别说明。

## 非目标

不换模型，不关闭事实复核，不直接投递未经复核的答案，不延长超时掩盖问题；
不修改订单、重放报文或伪造 Dify 原生会话；不扩张数据库重构与通用监控平台。

## 验收合同

```gherkin
Feature: 订单查询等待和两种日志可解释
  Scenario: 查询等待可见
    Given 用户有当前订单权限且执行尚未结束
    When 用户从 Dify 或 H5 原入口查询并轮询
    Then 接口返回真实阶段及已耗时，最终答案仍经过授权与事实复核
    And 简单查单不自动执行无关的费用与过程全套诊断
  Scenario: 读取通讯证据
    Given 当前授权订单可派生设备和订单时间窗口
    When 用户请求该订单的充电事件或通讯报文
    Then 按时间返回实际记录并说明方向、来源与关联及截断边界
    And 无记录或不可用时不以旧摘要代替
  Scenario: 测试记录可见
    Given 用户在受管管家应用完成或失败了一次试用
    When 用户打开该应用原日志入口并刷新
    Then 可见本人 Java 运行的状态、开始时间、耗时与实际工具阶段
    And 未授权应用、其他用户和撤销权限不能返回业务信息
```

## QA 计划

| ID | 环境与操作 | 独立判据 | 清理 |
|---|---|---|---|
| RUN-01 | 一次性 Gateway 数据根，控制上游工具/复核延时并轮询 | 阶段来自受控边界；单调耗时；最终无未复核答案 | 删除临时根 |
| RUN-02 | 原 Dify/H5，同一订单普通查询与明确诊断 | 分阶段计时及工具次数；报告同条件前后值，不将样本当全局分位 | 关闭测试会话与隧道 |
| COMM-01 | 有界上游记录，当前授权订单、不同订单、空行、超限、拒绝 | 接口字段语义；越权不查源；源记录与输出对应 | 删除临时根 |
| COMM-02 | 原入口查真实订单日志，并独立只读查询相同窗口 | 时戳／方向／事件与数据源一致；没有已确认故障不能宣称根因准确率 | 关闭测试会话 |
| LOG-01 | 一次性根，双用户/双应用、权限撤回、过期运行 | 本人当前权限与实际运行账本；无快照或秘密泄露 | 删除临时根 |
| LOG-02 | 原 Dify 试用后打开原日志入口 | 页面显示同次运行，成功/失败均可见；状态来源标为 Java | 关闭浏览器 |

新增长期检查只覆盖上述已发生故障及新的授权/解析/持久化边界；既有检查没有这些合同。
完成基本实现和构建后由独立 Hacker 驱动入口并找反例，默认探索一次、修复后复验一次。
真实功能验收、代码合并、部署及业务准确性分别记录；无工程师确认的真实故障结论写“未完成业务验收”。
