## 二、顺序：节点声明先于网关

证据字段集合是**两端精确相等比对**（`OPERATOR_EVIDENCE_MISMATCH`），所以「网关新、节点声明旧」
的任何一个窗口里，所有订单诊断都会失败。CD 是合并后自动触发的，不会等节点，因此执行顺序是：

1. **CD 运行中**即把新声明经 `dev-host write 41 --artifact-sha256` 传上 41；
2. 备份旧声明 → 原子安装（先写 `.operator-tools.json.new` 再 `mv`）→ 644 / `aiops41:aiops41`；
3. 定点重建节点容器（`--no-deps --pull never --force-recreate node`，**不重建 JAR** ——
   声明是独立 bind mount，字段来自声明）；
4. 等节点上报新摘要。

节点重启后**首次心跳仍报旧摘要**，约 90 秒后才变成 `ad967010…`。这不是故障：
`CapabilityReporter` 每 30 秒一次，而容器冷启动本身用了 49.8 秒。判据要连 `observed_at`
一起看，不能只看 `tools_sha256` 的值。
