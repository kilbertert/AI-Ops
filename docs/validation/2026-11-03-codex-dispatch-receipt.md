## 四、完成实际验收

### 做了

新代码上线后，用真实运营账号跑 **8 次**原问法 `帮我分析这笔单的电费2116…`：

| 结果 | 次数 |
|---|---|

### 失败构成第一次看得清了（本轮补的 `detail=` 取证生效）

| 原因 | 次数 | 含义 |
|---|---|---|
| `json_parse` | 3 | 模型没吐 JSON |
| `unsupported_fact detail=status line=3` | 3 | **reply 第 3 行写了状态** |
| `OPERATOR_EVIDENCE_MISSING` | 2 | 证据工具未被引用 |

### 这个证据推翻了 #1307 的前提

`#1307` 的假设是「模型在事实段外写了**数字**」，所以改成禁数字。
真实成因是**第 3 行写了状态**（「这单已完成」「仍在充电」这类），
而 `check_notice`（查数字）根本拦不到它 —— 是 `check_status_prose` 拦的。
两次拒绝的行长度分别是 155 / 102 / 101 字符。

**我上一轮补的取证，第一次用就否掉了自己之前的判断。**
