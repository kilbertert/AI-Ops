# 2026-10-23 · #1039 证据收口：可独立复核的结论与无法补回的材料

本片不开窗、不新提问、不调用模型、不新增业务取样。它只做两件事：把已有证据收口到
"复核者能自己判断"的程度，并把无法补回的部分如实标出。

## 一、可独立复核的结论（复核者手上有原件即可复现）

| 结论 | 依据 | 复核者能否独立复核 |
|---|---|---|
| 两条 H5 正例的答案与生产 QA/快照一致 | 保存的两份 `result.*.private.json` + 生产 QA 回读与快照摘要自校验 | **能**（Codex 已独立做过） |
| 三个主动 POST 与 journal/nginx 一一对应 | journal 3 条 `assistant_question_result` + H5 访问日志 3 条 POST | **能** |
| B 查 A 的单、B 回读 A 的结果都被拒 | 保存的原始响应 | **能**（见第二节第 1 条的判据更正） |
| 对照：A 回读同两个 QA 成功 | 保存的原始响应 | **能** |
| 恢复关闭成立 | 窗口前后 `gateway.env` 逐字相同、三键计数 0、停用后回读 `CHARGING_STATUS_DISABLED` | **能** |

## 二、四处校正

### 1. 旧 `leaks` 字段无效，已换判据复核

原脚本里 `leaks` 的赋值以 `if False else []` 结尾，**恒为空**，用它证明"无泄漏"等于没检查。
保留脚本原件；对**同一批已存响应**用新判据复核：

| 响应 | HTTP | 命中标记 | 响应体键 |
|---|---|---|---|
| B 查 O2 | 404 | **无** | `code` / `message` / `retryable` |
| B 回读 Q1 | 404 | **无** | 同上 |
| B 回读 Q2 | 404 | **无** | 同上 |

检查标记：两个订单全号、`status_code`、`status_role`、`cpms.chargingInfo`、`observed_at`。

### 2. 排序证据升级，但作用范围收窄

原字段只比较订单**末四位**。找回的完整输出补上了能真正支撑排序的字段（完整 `order_no`、
`created_time`、主键 `id`、可见订单数、`top3`）。**同时降级**：这只能证明"在该主体可见
范围内最新"，**不能**证明"全表最新"——列表本身带范围下推与分页。

### 3. 拒绝行有三个不同的时间，不能互相替代

| 来源 | 时间（UTC） |
|---|---|
| 脚本启动（原 `POST3_UTC`） | 12:48:31 |
| Gateway journal 观察行 | **12:48:35.785** |
| H5 nginx | **12:48:36** |

此前写"12:48:32 的观察行"是错的。三者之间约 5 秒的差是隧道建立、页面加载、填写与点击，
与观察行的 `duration_ms=199` 不矛盾（那是服务端处理时间，不是端到端）。

### 4. 零模型调用必须分两层

| 层面 | 结论 |
|---|---|
| 同版代码路径 | 状态问法命中后**直接 return** 确定性分支，不经过模型路由/通用问答/诊断。源码逐段 + 独立哨兵：状态路径模型入口计数 **0**，普通问答正对照能触发同一哨兵。 |
| 历史供应商实际调用 | **未独立计量**。窗口内无 model/provider/tokens 关键词、`runs/` 无新目录；但指标的 `token_count=0` 是 `record_route_metric` 的**默认值**，不是账单读数。 |

**撤回一个推论**：此前"缺 `qa_id` ⇒ 必须加全链路追踪才能上线"的说法不成立。
关联键能帮助归因，但既不能证明调用记录完整，也不能证明零调用。它**不是**零调用证明。

## 四、下一阶段决策（只准备，未执行）

**有条件具备，但不建议无人值守 7 天。** 现有机制里没有定时器与阈值告警，
没有任何东西会在出问题时把开关关掉。

建议：单租户、**≤4 小时**、同一工作时段、**固定截止**（到点无论有无样本一律恢复）、
**必须有人值守**、每 30 分钟检查一次、零样本到期结束不延长、恢复独立于是否观察到样本。

必须同时接受四条边界：未登记租户可能 404（3 分钟窗口里为 0，但那是未观察到）、
无按人限流、证据文件无自动清理、未知模型事件按"可归因才停用，否则记待核实"处理。
真实请求与测试请求分列；只有测试请求时结论就是"零自然流量"。
