### 授权撤销 → 检索停止（真实页面操作）

客户在页面上把 `shiping1` 的对客授权关掉，然后用网关**同一套判据**
（`owned_libraries` + `require_owned`）复查：

```
撤销前：38676440d37c -> customer
撤销后：38676440d37c -> internal
        38676440d37c -> REFUSED: 所选知识库未授权给客户端使用（内部资料不能交给消费者）
恢复后：38676440d37c -> ALLOWED
```

撤销与恢复各自即时生效，不需要重启。

**结论**：本客户对客资料可得；内部库（`41(1)`，`allowed=false`）、跨租户库均不可得；
撤销后检索停止。来源客户库这一格在本轮没有可测对象（本次开通的客户端来源与目标同租户），
**记为未覆盖**，不按通过计。

## 第 4 项 失败与恢复

### 发现并修掉的缺陷：撤回后重发同一内容会复活版本

真实序列（生产）：

```
撤回        → published=false, rev 9
再点发布    → 200 {"action":"unchanged","version_no":2}
状态回读    → published=true        ← 撤回被悄悄撤销
```

根因：`node_publication.advance()` 与 `gateway_api._advance_route_binding()` 在冻结结果为
`unchanged` 时提前返回，但条件含 `previous.active`。撤回后 `active=false`，捷径不成立，
代码落到 `store.publish()` 把已撤回版本推回 active。

修复（#1274）：判据改成"这一版是否被撤回"——unchanged 且已撤回则拒绝。两端同修。

第二个缺陷（#1276）：拒绝返回的是 **500** `SETUP_UNAVAILABLE`（`NodeRouteConflict` 没有
HTTP 映射）。补 409 handler 后，生产实测：

```
publish while retracted: 409 {"error":{"code":"node route retracted"}}
verify still retracted: True
```
