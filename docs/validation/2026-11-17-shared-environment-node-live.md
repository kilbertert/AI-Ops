## 现场动作与结果

共享服务宿主新增独立环境的两个容器和systemd模板，使用已有项目非登录身份；
平台、存储、模型出口及原节点不重建，目标业务宿主不安装Java/平台。
独立Snail应用、智能体和OpenAPI用户/订阅使用原管理API准备，未修改平台数据库或现役管理员。
节点固定注册名、应用凭据及Gateway回调目标；TLS叶子/信任库为独立配置，旧CA与信任库未改。

| 观察判据 | 现场结果 |
|---|---|
| 新执行组的实际节点注册 | 一个在线节点，固定本环境注册名称，无在飞任务 |
| 制品与服务身份 | jar摘要与锁一致，两个容器使用项目非登录UID/GID，0重启、无OOM |
| 网络 | 节点无egress，出口只在独立callback/egress；现役共享网络均internal，无宿主端口发布 |
| 节点Java信任库→固定出口→目标正式HTTPS | 单次有超时探针收到Gateway403、退出0，保持两段证书校验；未登记业务目标，不计授权成功 |
| 原共享应用/智能体、四个容器 | 原字段逐项保持，容器ID/启动时间一致，原Gateway健康不变 |
| 空闲成本 | 单次节点RSS约201MiB、出口master约7.8MiB；未测worker合计/并发/峰值，不能作为容量验收 |

节点已部署并注册；目标Gateway仍未登记真实业务应用资源，故新节点能力授权和合法run仍待完成。
没有为验证伪造Dify应用、用户身份或会话，也未激活两个测试租户。

## 失败、修复与恢复

首轮在制品传输尚未结束时检查被摘要拒绝；后继等待传输完成，两个包目标摘要均一致。
目标Docker离线导入只恢复镜像内容ID，无仓库引用，原Compose无法识别；#1567使用实测同一内容ID，
本目标Docker存储已验，经典Docker后端未验。不能把manifest摘要普遍等同所有后端的镜像ID。
上述拒绝发生在新配置/应用/容器创建前；未动旧服务。历史失败见[离线镜像回执](2026-11-17-environment-node-offline-image.md)。

第一次Java交互探针模块加载失败且超时，第二次收到422但交互进程未正常退出；两者不计最终通过。
改为带单次超时的Java源码HTTPS探针后收到预期403并退出0，只清理本次诊断进程，服务保持运行。
完整版本、主机/拓扑、配置/镜像/包摘要与回执保持私有；仓库不记录口令或业务会话。

恢复只停止本环境systemd/Compose项目，停用本次执行组并保留新资源/状态作对账，不停共享平台或覆盖业务库。
