# 95制品升级验证

## 合同

```gherkin
Feature: 保留数据的95制品升级
  Rule: 首次重建恢复点不可被后续升级覆盖
    Scenario: 同schema候选健康通过
      Given 首次重建完成且没有在飞请求
      When 从已合并完整制品运行upgrade.sh
      Then 健康返回新构建身份且原数据和首次重建恢复点保留
    Scenario: 候选启动失败
      Given 已运行的旧制品可恢复
      When 升级后的健康失败
      Then 原制品重新启动且失败现场及业务数据保留
    Scenario: 有在飞或schema不兼容
      Given 检查存在未结束请求或数据库迁移需求
      When 尝试升级
      Then 拒绝切换，不清除请求或修改schema
```

执行计划：隔离宿主文件树及服务命令模拟成功/启动失败/在飞/不兼容分支，核前后数据与首次标记；
再以合并制品到95复验版本、准入和知识能力。模拟仅证明脚本流程，真实部署和业务验收待验证。
不改变公司业务数据库索引或数据；未完成业务验收。

本地6项隔离检查通过：成功切换、健康失败恢复、不兼容schema、目录符号链接、额外制品文件、在飞请求。
SQLite与文件字节、首次恢复标记逐项保持；服务/pip为模拟，不冒充真实安装。新增检查防止已运行实例升级丢失数据，
判据来自用户要求保留回退与服务器迁移合同；首次安装检查未覆盖后续升级。独立Hack及真实升级待验证。
