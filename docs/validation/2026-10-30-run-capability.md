## 变异是否被杀死

`test_run_type_decides_not_the_presence_of_an_order_number` 用四行参数覆盖两个字段的
独立组合：

| `operation` | `order_no` | 期望 | 若把岗哨写回 `if run.order_no` |
| --- | --- | --- | --- |
| 订单诊断 | 有单号 | True | True（不红，这一行本来就一致） |
| 无订单回合 | **有单号** | False | **True → 红** |
| 无订单回合 | 空串 | False | False（不红，一致） |
| 订单诊断 | **空串** | True | **False → 红** |

中间两行是这条测试存在的理由：它们只靠「两个字段不一致」成立，而这种状态今天不会被
签发路径产生——所以必须由测试直接构造，不能等真实场景。
