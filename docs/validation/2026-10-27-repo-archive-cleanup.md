### 为什么按标题集合判，而不是按日期判

第一版写的是「不许出现晚于 `2026-10-23` 的标题」，Devin 审查指出它有一个正好盖住目标违规的洞：

- #1015 的标题日期**就是** 2026-10-23（冻结当天），`>` 放它过去；
- 改成 `>=` 又会把归档里**本来就有的**那批 10-23 旧记录全部判红。

所以判据改成基线集合：**出现基线里没有的标题即红，与日期无关**。
删掉旧标题（订正、合并、改措辞）是允许的——归档的正当维护。

## 已知缺口

- README 入链补丁未随本轮提交（stash 在本工作树），六篇孤立文档的索引行下一轮补。
- 本轮只覆盖"归档被追加"这一种形态；**直接改写归档里的旧节**（例如订正错别字）不会被拦，
  这是刻意的：把归档完全冻成哈希会阻止正当的维护。
