# 2026-10-23 · 个人订单查询单租户开放：只读影响核查与变更单（未启用）

本片不开窗、不提交业务问题、不调用模型，只做**只读核查**并交付一份可直接执行的变更单。
变更单：[`single-tenant-enable-change-ticket.md`](../agents/consumer-order-chat/single-tenant-enable-change-ticket.md)。

### 推荐：执行单租户开放（映射形式），不直接常驻全量

依据是验收已经闭合（#1015：真实页面正例 + 真实跨用户拒绝 + 停用回读拒绝），
剩下的是**范围与观察**问题，不是能力问题。

### 实测的影响范围

| 项 | 实测 | 口径 |
|---|---|---|
| 把 `/v1/` 送到网关的宿主配置 | 5 个文件 | `nginx -T` 里 `proxy_pass … 8788` |
| 近 7 天产生问答的租户 | **3 个**（97 / 26 / 3 条） | `assistant_questions` |
| 近 7 天网关日志里的租户 | **2 个** | `faq_platform_decision` 行 |
| 其余租户历史命中新路径的问法 | **0**（6 周、500 条问题） | 用实现的 matcher 离线跑，只计数 |

**三个信号源对不上**，本片把它显式写出来而不是取其中一个：`2084…000` 有问答与指标、
却没有网关日志。所以"日志里只有两个租户"**不等于**"只有两个租户在用"。

### 会变的行为（必须提前知道）

- 未登记租户的状态类问法：普通问答 → **404 `TENANT_ENDPOINT_UNRESOLVED`**；
- `GET /v1/orders/{no}/charging-status` 对目标租户从恒 404 变成**可用**（当前无人调用：全日志 1 次）；
- operator 入口、非中英问法、快捷动作**不变**。

### 没有限流，这是实测不是推测

`nginx -T` 全配置里 `limit_req` / `limit_conn` 的**使用数 = 0**（只定义了 zone）。
单请求最坏 4 次 SQL（`MAX_EXECUTION_TIME=3000`）+ 1 次 CPMS（硬编码 10 s）≈ 22 s，
每个请求占一个 Starlette 线程。共享 CPMS 端点与 OPS 运维工具是**同一个地址**。

### 观察口径：按请求关联，但有盲区

能关联的是"同一秒 + 同一租户 + 同一路径"（#1015 的 H5 访问日志实测能对上 POST 202 与 QA 行），
**没有贯穿全链路的请求 id**。三个已知盲区：拒绝的错误码不进指标行、网关自身访问日志 0 行、
nginx 默认格式没有 upstream 耗时。

变更单给了最小修复建议（复用 `_record_route_metric`，约 3 行），**本片不实施**。

### 一处我自己查错的

`ulink.h5` 的 vhost。**入口选错，观察就是空的**；这类错在没有对照时看起来和"没有流量"一模一样。
