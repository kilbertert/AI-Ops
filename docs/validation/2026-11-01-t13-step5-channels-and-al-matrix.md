## 2. 渠道登记：本轮**没有写声明**

`dual_entry.channels()` 从 `AIOPS_GATEWAY_ENVIRONMENT_MANIFEST_FILE` 读 `[[channels]]`。
41 上该变量未配置，`ops/environments/env-41.toml` 是 **agent 清单**（`[[agents]]`/`[[dify_apps]]`），
不含 `[[channels]]`。

新增一份生产清单文件是一个配置变更，且要能回答两件事才成立：
"这个租户的哪个端接到了哪个渠道" + "证据是什么"。本轮证据只覆盖：

- **Ulink / consumer**：有真实会话、有今日 completed 记录 ⇒ 可判"已接入"。
- **Ulink / operator**：本轮没有真实员工会话（上次正属于 2026-10-31，运行在 `4ec55c7a`）。
- **优链充**：本轮完全没碰。

所以**没有写声明**，两端继续显示 `channel=pending`（"该端尚未接入使用渠道"）。
这符合 J2 要求的"不谎报"，只是还不够格说"已接入"。

## 5. 一处仍未查清的现象（本轮最值得跟进的一条）

服务类问题返回 **409 `CHAT_ROUTE_UNAVAILABLE`**，**稳定复现**（两次不同问法、同一会话）。
而同一条链路的静态条件全部成立：

| 条件 | 实测 |
| --- | --- |
| `consumer_chatflow_enabled` | `True` |
| `consumer_service` 绑定存在 | 是（`07d15c42…` v1，rev 9） |
| 绑定凭据文件 | 存在且可读 |
| 会话语义 | `third-session` 有效（`/v1/shortcuts` 200，Redis TTL 约 25 天） |

按代码（`gateway_api.py:2970`），`chatflow_enabled and platform=="consumer"` 就该进 chatflow
分支；实测走到了链路末尾的兜底 409。**原因未定**，本轮没有继续深入。

影响面：消费者问"怎么开始充电"这类服务问题，现在拿到的是 409 而不是知识回答。
这与今日那两条 `completed` 记录（同样问法！`怎么开始充电？`）**矛盾**——
那两条在 06:25Z / 06:43Z 成功了。也就是说：**同一条渠道、同一个问题，几小时前能答、现在答不了。**

这条比"渠道是否已接入"更重要：它是一个可能新引入的回归。建议单独开票排查，
在查清之前不要把消费者渠道标成"已接入"。
