# 订单事实段跟随提问：四项反馈的核实与修复

日期：2026-11-04。分支：`fix/operator-facts-relevance`；基线 `6f4e2189`。

## 一、四条反馈的核实结果

| # | 反馈 | 核实 |
|---|---|---|
| 1 | 返回数据都一样 | **成立**。同一张单问「电压」与问「电费」，除结尾句外逐字相同（已 diff） |
| 2 | 列出充电桩各项数据不对 | **成立**。事实段无条件列 20 个字段；且问电压时 `voltage` 是 `null`，整行被跳过 |
| 3 | 能不能上下问题关联 | **原来不能**。`history_policy=none`，每次派发用全新 `conversationId`；会话轮次一直记在 `conversation_turns`（生产 207 会话 / 180 轮），但**从没回喂给模型** |
| 4 | 拿不到计费规则 | **属实且是能力边界**。工具清单只有三项（订单详情/充电样本/站点查询），没有费率、电价、峰谷时段数据源 |

## 二、改了什么

1. **事实段跟提问走**（ADR-0201）：按提问原文选主题字段；认不出主题退回全量。
2. **主题字段空值写「未提供」**：问电压而电压为空时，明确说没有，不留白。
3. **会话前文进节点消息**：同会话前 3 轮的**提问原文**压缩成一段，附在用户消息后。
   只能以文字形式：节点要求首次模型调用「恰好一条用户消息」，多插轮次会被
   `verifyInputShape` 拒。只带提问不带事实段，避免模型照着抄数字。
4. **把能力边界写进输出契约**：明说本轮没有计费规则/电价/峰谷时段数据源，
   被问方案比较时明确说不在此范围，不凭常识推算。

## 五、边界

- **未部署**。
- 主题词表是维护中的，不是穷举；漏词会退回全量（安全方向）。
- 会话前文只带**提问**，不带前几轮的事实段与答复 —— 带事实会让模型复述数字，
  而 reply 的非事实行禁数字；带答复则会放大一次错误的传播。
- 计费规则仍是**没有数据源**，本轮只是让拒绝的说法稳定，不是拿到了数据。
