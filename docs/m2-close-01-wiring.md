# 委托执行契约：授权留在 Gateway

日期：2026-10-17。状态：已实现（合成环境验证），**未部署**。

一次**已授权**的读取可以交给可信执行节点代跑。**授权只在 Gateway**；执行节点拿到的
只有一个不授予任何权限的关联编号。本文件是这条跨系统边界上的契约，不是部署说明。

## 1. 链路

```text
客户端 ──身份──> Gateway
                   1. 解析身份（consumer、非代查、self 范围）
                   2. 复用既有订单可见性判定
                   3. 按服务端绑定表签发一条执行记录（run_id）
                   4. 用 Gateway 自己的平台应用凭据发起一次对话（只传 agentId、sid=run_id、一句固定提问）
                      ↓
              编排平台 ──按 appId 调度──> 执行节点
                                           5. 模型点名受控工具（零参数）
                                           6. 节点用自己的凭据回呼领取端点
                      ↑
Gateway <────────────┘
   7. 认节点 → 核对记录/环境/节点 → 用冻结身份**再授权一次** → 才读业务
```

身份只在前两步验证。平台用户编号、会话、提示词、工具参数都不能单独成为业务身份。

## 2. 契约要点

| 项 | 规定 |
|---|---|
| 关联编号 | `run_id` 由 Gateway 生成，高熵、不含身份；经平台的 `sid` 到节点。**知道它不授予读取权限** |
| 节点身份 | 只由节点凭据派生；绑定表里只存凭据的 SHA-256。自报的 node/host 头不参与判定 |
| 记录状态 | `issued → running → succeeded`，外加 `failed` / `revoked` / `expired` 三个终态；固定有效期，不续期 |
| 原子领取 | 每次迁移都是带条件的 UPDATE，以受影响行数判定谁赢；重启不改写 `running` |
| 放行 | 先完成可能阻塞的订单授权，再重读配置与记录，只用重读到的那一份做本地判定；快照只能来自这次决定 |
| 默认关闭 | 未配置绑定表时两个入口都不存在；配置了绑定表就必须同时配好业务地址与逻辑环境，否则启动失败 |
| 请求体 | 两个入口都是**空的严格模型**：多一个字段就是 422，不是「收下但忽略」 |
| 缓存 | 这一组路径的成功与错误响应都带 `Cache-Control: no-store` |
| 版本追溯 | `agent_version` 为 `null` 并标注 `not_wired` —— 不冒充已通过 |

## 3. 失败模式

| 情形 | 期望 |
|---|---|
| 无身份 / 非 consumer / 代查 / 范围不是 self | 401 或 403，不建记录，不打业务接口 |
| 他人订单 / 不存在的订单 | 同为 404，不建记录 |
| 订单授权源不可用 | 503（可重试），不建记录 |
| 请求体伪造 appId / agentId / 环境 / sid / 订单号 | 422 |
| 只持 `run_id` 领取，或凭据错误 / 节点被停用 | 401 |
| 记录已过期、已撤销、已失败，或绑定已改变 | 403，**不释放已算好的快照** |
| 并发领取 | 一个赢家，其余明确失败 |
| 成功后重试 | 返回同一份快照，且不再读一次业务 |
| 上游失败或订单号对不上 | 502，不把未知解释成「充电结束」 |

## 4. 已验证与未验证

B2 的证据是契约回归与受控回环请求；平台、节点均为替身。C 的独立隔离实验另外验证
真实平台服务端与受控节点，报告在该片交付。不能把 C 的证据提前算作 B2 单片已运行的结果。

**未验证**：真实公司身份与授权源、真实业务数据、真实模型质量、跨主机网络、TLS 与部署；
`agent_version` 的发布冻结仍是开放项。**本文件不构成业务验收。**

## 5. 边界

- 节点不直连业务系统，也不用通用 HTTP 工具；它读业务的唯一出口是这个回呼。
- 平台的应用凭据只在 Gateway；节点凭据只在节点与绑定表的摘要里。
- 逻辑环境来自部署配置，不是对调度位置的独立证明。
