# 共享Dify备用HTTPS入口

适用于原HTTPS持续握手失败时的临时服务接入；只修改AI-Ops自有Nginx配置，决策见[ADR0266](../adr/0266-temporary-shared-dify-https.md)。
部署目标、来源IP、凭据和原始网络证据留在私有记录。公网可达与真实应用验证完成前不得写成恢复成功。

## 准备与部署

1. 观察原入口实际请求，保留当前部署。核备用端口未被配置占用，并在宿主私有端口清单登记。
2. 从已合并修订构建，不把工作树文件直接写入生产：

```bash
bash ops/dify-console-bridge/build-service-api-bundle.sh origin/main /private/service-api.tar.gz
```

3. 私有`allowed-sources.conf`只含1～8行`allow <精确IP>;`，不支持网段或任意Nginx指令，0600且由安装操作者持有。
   加入所需业务宿主及本机回环；该清单不代替Dify应用Bearer。不得把用户提供的X-Forwarded-For当来源。
4. 使用`dev-host cp`和制品SHA256到共享宿主；同样对私有来源清单核传输摘要，解包到私有暂存目录。
5. 执行固定安装入口，备份目录必须全新：

```bash
bash <制品目录>/service-api-deploy.sh install <制品目录> <私有新备份目录> <私有来源清单>
```

安装器加锁、核摘要、验证清单、备份两份自有配置，`nginx -t`后reload；失败恢复并再次核语法。
不重启Dify、不改原443/10008入口、不修改公司应用服务。云端端口策略不通时停止并撤回，不能自行扩公网暴露。

## 接口与验收

仅现役客户端使用的info/parameters、图片上传、chat-messages/取消、工作流当前或固定版本运行/取消路径可转发GET/POST，
其他路径404；允许路径的未授权来源403，匿名应用请求由Dify返回401。
HTTPS主机名保持原证书名称，仅连接端口改变；客户端必须完整验证证书，不允许`-k`。
应用API key运行时从受控位置读入内存，不进入命令行、访问日志或回执。

真实验收至少包含多次匿名401、同一正式应用key的200、一次真实流式终局、非授权来源403、管理路径404和原入口回归。
本地测试使用真实Nginx、受信测试证书和HTTP替身，证明来源/路径/鉴权透传，不证明远端网络、模型或知识活性。
只有该调用方通过才可临时配置其Dify地址；工作区/知识管理接口不通过此入口。

## 恢复与到期

```bash
bash <制品目录>/service-api-deploy.sh restore <制品目录> <原备份目录> <私有来源清单>
```

恢复只处理本次两份配置；首次安装时撤回即移除这两个文件并reload。确认备用端口已关闭、原入口正常。
更换/退休入口前仍需实际流量观测；不得用端口监听代替使用情况。
临时有效期48小时，复查原路径后恢复或明确续期；安装器不会定时中断正在使用的服务。
本轮探索过的DNS/边缘代理方案必须按私有备份单独恢复，不把它残留为备用入口前置条件。

## 目标测试账号发现

管理员授权自行查找时，先核测试租户、未锁定测试用户及角色的`client_type`，不读取密码散列或现有用户会话。
若环境已启用公司测试验证码机制，按实际应用登录协议取得新令牌，再经公网`user/info`核用户/租户一致。
后台角色使用`admin`，不能随意填写`APP`；验证码通过后仍可能被角色权限拒绝。
本机UPMS正常登录只证明账号/测试认证和公网身份查询，不等于原浏览器图形验证码流程已验。
可复用资产写入库外age加密清单，保留旧密文备份与解密回读；回执只写asset_id，不公开账号或验证码。
