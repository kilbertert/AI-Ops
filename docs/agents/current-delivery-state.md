## 已修成因与尚未闭环的风险

- 订单状态守卫误拒、有界重派及JSON尾部装饰已分别由 #1323、#1325–#1327 处理。
  [状态复测](../validation/2026-11-03-status-guard-deploy-receipt.md)、
  [重派](../validation/2026-11-03-json-output-resilience.md)、
  [尾部装饰](../validation/2026-11-03-json-trailing-decoration.md)各有不同基线；不把小批成功率合并为稳定性结论。
- 管家路由迁移同时更换了系统协议，且缺一条发布账目；不能说“只换app_id”。
  恢复必须走正常接口、revision递增；不补造历史审计。见[迁移记录](../validation/2026-11-03-operator-route-migration.md)
  与[操作方法](operator-route-migration.md)。
- 费用字段与订单识别已有交付；计费规则数据源、结算状态、关联占枪费订单、非零退款仍有缺口。
  `settlementType` 是结算方式，不能代替结算状态。
- 现役数据面依赖既有SSH隧道。公网TLS重置的具体原因未确定；取证通道可用不等于公网网络已恢复。
- 人工语义准确率、长期稳定性、生产在途发布竞争、原生APK/IPA及全面多语言质量不在本阶段通过范围。
