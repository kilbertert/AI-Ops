# WF01知识资料导入与核对

当前使用动态文档模式。日常在知识库上传/更新资料、触发解析并等待索引完成，即可供使用该库的新问题检索。
无需KB-C-NNN文件名、approved字段、content.json或媒体ID映射；视频地址直接放在相关说明正文中。
更换节点所用库才需要保存/试用/发布工作流，库内资料更新不需要发版。见[WF01手册](README.md)。

## 导入后检查

1. 确认目标工作区/租户及Chatflow节点选择的是预期库，避免把文件传入另一个同名库。
2. 查看文档解析状态；上传成功、chunk_count非零均不能单独代替索引完成。
3. 用真实问法检索，检查来源文档、适用场景和媒体原地址。
4. 在原H5发新问题，核回答、引用、播放及语言；历史问答仍保留当轮快照。
5. 无命中时查索引/选库/问法，服务错误与无资料分开；不靠补审核JSON解决新版检索。

## 工程批量导入（已有授权时）

通过受控kb-service，凭据现场读取，租户固定为授权范围，不打印秘密：

- GET `/kb/knowledge-bases`核目标；仅确实需要新库时POST创建，embedding_model用该租户已配置值。
- POST `/kb/knowledge-bases/{id}/documents`，multipart字段files；留文档ID与文件摘要。
- POST `/kb/knowledge-bases/{id}/documents/parse`，body.doc_ids指定本次文档。
- 分页GET documents核DONE/RUNNING/FAIL；POST search以真实问法检查实际召回。

创建/上传失败先核是否已生成对象，不盲目重复创建；仅清理本次可识别的临时材料，不删除原库。
索引和检索可能消耗嵌入模型额度。资料进入所选库即影响回答来源；不声称经过自动业务审核。
历史内容包生成工具仅保留旧版兼容用途，不作为当前产品上传的必要步骤。
