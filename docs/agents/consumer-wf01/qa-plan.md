# WF01 业务验收计划

当前动态模式与提测范围见[测试交接](../../testing-handoff.md)。CONTENT及审核包发布用例是旧协议回归；
新版以LIVE-DOCUMENTS、KB-PICKER、CPMS-NODES和[多语言计划](../../acceptance/consumer-multilingual/qa-plan.md)为主。

| ID | 环境/前提 | 操作 | 预期 | 清理 |
|---|---|---|---|---|
| CONTENT | 开发机，私有原包 | 生成内容包；独立读工作簿对照 | 53条/7类/双语对应，21项媒体不冒充成品；错文本、错引用、重复ID拒绝 | 留私有输出，原件不改 |
| CHAT | 一次性Gateway、真Dify、合成依赖 | 原提问/轮询API连续三轮，另主体尝试复用 | Chatflow真实执行、上下文接续，跨主体拒绝 | 删除本次栈和数据 |
| KNOWLEDGE | 待发布内容库 | 中英文问法、无命中、服务失败、错租户 | 来源可信；无命中与不可用不同；不跨库 | 不发布草稿 |
| READ | 真实授权主体及接口 | 订单/会话/支付/退款每项查询、超时及越权 | 真实返回可独立对照；缺能力明确不可用 | 只读，无写动作 |
| MEDIA | 与问答关联的真实素材 | 原App显示图片、播放视频、点击人工入口 | 内容适用、可见可播、真实渠道可达，无假URL或已转接文案 | 清理临时素材 |
| SAFETY | 有危险描述；模型不可用 | 发安全问题及普通操作问题 | 安全提示不依赖远端模型；普通指导不误判紧急 | 临时数据根 |
| PHOTO | 本人受控附件 | 上传错误照片/模糊图/错主体附件 | 可读错误码结合知识，模糊追问，跨主体拒绝 | 按保留策略清理 |

初始阶段曾只执行CONTENT；当前各路径必须分别留证，不从内容导出推定通过。
最终必须在原App入口验收，单独Dify预览不能替代。

H5-MEDIA：临时真实nginx，GET签名素材路径应转网关；同路径POST/DELETE及错形状应拒绝，
其余管理路由全部不转。生产部署后原H5回答打开实际图片，错误签名返回网关拒绝而不是HTML。
清理临时nginx与桩；生产保留原片段备份，失败恢复原摘要并reload。

FOLLOWUP：一次性Gateway/真Dify/合成依赖；依次发送操作问题、第一次“还是不行”、第二次反馈。
核对检索实际收到原主题、第一轮追问、第二轮真实渠道且调用数不增加；重启客户端后仍一致。
组件用例补充换主体/过期/改正文/查询中前轮过期、新主题重置与中英文表达；保留私有报告并清栈。

LIVE-ORDER：一次性Gateway/真Dify/合成CPMS，显式live_order_status绑定；本人最新单与指定单POST/GET，
核对单号、来源、一次读取与零知识检索；交错撤权/取消/TTL/改绑，跨用户查询与历史回读拒绝。
随后同会话普通咨询核对上游会话为空；失败不回落节点。清理本次栈，记录真实与合成边界。

BILLING：一次性Gateway/真Dify/合成详情接口；发送本人最新单退款记录问题，核对一次GET、
原GET含部分退款记录/金额/来源/时间且不宣称到账；跨用户、读取中撤权拒绝。
解析用例区分缺失/零/未知码并拒负数/非有限值/错误单号。清栈留私有报告；真实渠道到账未验。

MEDIA-WF01：一次性Gateway/真Dify/合成RAGFlow；原POST/GET得到图片块后实际读取其签名URL，
核对字节及MIME；组件另验视频Range、伪造签名、过期/改内容/停用/取图中撤回。清理本次栈。
真实素材须独立核对内容/语言与适用性，合成图通过不代表业务教程已制作。

PUBLICATION（旧审核内容兼容）：真Dify/Gateway隔离环境，原运营接口发布V1，修改审核副本并试用；原App接口须仍V1。
再发V2、撤回、读旧QA、恢复V1，按51项实链报告核对。临时应用删除，源应用/正式指针不被试用修改。
另验同内容幂等、错误草稿拒绝、试用中撤回、旧路线冲突；模型/业务/目录合成，不算线上业务验收。

PHOTO-WF01：一次性Gateway/真Dify/官方provider，合成模型必须记录收到image_url；
POST photos→questions photo_id→GET，核对识图线索实际进入KB。组件另验元数据/格式/尺寸/限额、
跨人/重复/过期/换版拒绝、模糊图不检索、上传中取消不启动模型。清理本次栈与内存。
真实baoyun只验证无个人信息的错误截图，不替代原App完整业务验收；Dify保留策略单列未完成。

SEMANTIC（对应semantic-routing.feature）：一次性Gateway/真Dify/合成分类器、CPMS和知识服务。
运行`uv run python tools/verify_consumer_chatflow.py --out <仓库外新报告>`：口语最新单应读取CPMS，
随后令前轮过期并在原conversation_id问明确新问题，应再次取数、旧GET410；退出自动清理本次栈。
组件反例覆盖分类故障、非法结构、他人订单、多单、分类/提交期间过期，必须无业务或FAQ回落。

SEMANTIC-MODEL：经授权、具有现用provider配置的受控环境；
`uv run python tools/verify_consumer_intent.py --config <受控配置> --out <仓库外新报告>`。
执行semantic-cases.jsonl固定17句，每句一次，记录模型/源码摘要/耗时与判断。
非取数意图不以order_reference评分，因为它不会参与选单；此判据不放松intent要求。
不得用合成模型的接线结果代替本项；报告不包含密钥，原件保留在私有目录。

CPMS-NODES（cpms-nodes.feature）：先组件红灯验证三种回调范围、缓存交错、旧版兼容，
再用一次性Gateway/真Dify/合成依赖从原App入口驱动知识、口语状态、账务三个问题。
同时核Dify节点执行记录与实际HTTP/业务次数，不以画布存在代替调用发生。
运营草稿关闭状态能力→试用→发布→恢复，逐步核正式行为；删节点/错URL/换凭据引用必须发布拒绝。
撤权/取消/到期/发布变更期间不交付；结束清理本次栈。最后从原H5、现役Dify只读验收，
独立核同轮CPMS快照；凭据与业务原件私有存储。部署前备份原图/发布指针，保留显式恢复路径。

KB-PICKER：隔离真Dify/Gateway、官方插件SDK、合成RAGFlow两库A/B及另一租户库。
原节点配置面实际打开多选框，选择B保存，原试用只读B；未发布App读A，发布后读B，恢复读A。
核Dify工具执行、后端实际库ID/调用次数，空库/异租户/删除库/重放旧凭据/不一致参数拒绝。
最后在现役应用和原App核同一操作；原发布目标文件摘要不变；只清本次临时栈/应用。

KB-PICKER-EDITOR：原版Dify1.17.1以真实Account/editor角色调用dynamic-options，重现403同文案、目录零调用。
修复后editor/owner/admin可读取本节点，normal/dataset_operator拒绝；错provider/action/parameter、私有或跨工作区
credential_id拒绝。隔离栈将浏览器账号设为editor，再完整点击选库/保存/试用/发布/恢复，证明不依赖owner。
线上只读核验现有editor的角色和目录返回；不升级账号角色、不改发布图。结束清理隔离栈。

KB-LIVE：本轮取消FAQ冻结清单，以知识库作为正文和文档媒体的唯一来源。
隔离栈发布一次后，添加无KB编号新文档→App命中→更新正文→新QA反映更新→删除→新QA无旧答案，
全程保持发布版本与服务器内容文件不变。使用KB-C-059原视频素材核视频地址来自召回正文，
反例包含错库、假引用、模型编造链接、取消/撤回以及CPMS回归。真实上线后用现有资料和正常App登录核验，
不为测试直接修改业务库；更新/删除主要在隔离栈进行，清理本次临时应用和数据根。
