# WF01真实依赖整合验收方法

隔离栈由已合并版本的`tools/verify_consumer_chatflow.py`与既有Dify验收启动器起，
仅本次Docker网络命名空间内监听，生产Gateway/节点路线保持原行为。
真实依赖验收与合成回归分别记录，不能用浏览器响应回放声称线上真人端到端。

## 真实依赖连接

使用`dev-host`已声明目标，只读取得当前服务配置位置，按项目服务身份执行固定请求。
中继不接任意URL、任意租户或任意业务方法：仅允许已审核知识库检索、已登记素材读取、既定baoyun模型请求。
凭据只在服务宿主读取并构造请求，既不进入测试DSL，也不打印或进入浏览器。
模型请求有输出上限且不在应用层重试；真实调用次数和usage按实际回执保存。

隔离身份仍是合成主体。审核内容复制到私有临时文件，只有测试租户/环境及库句柄映射到隔离范围，
正文保持审核版；临时内容不得被当生产配置部署。依次从原POST/GET提问、核对已审核标准答案、
取媒体字节。记录真实模型/检索/媒体来源，以及替换的身份/业务订单边界。

结束后停止本次Gateway、Dify compose down、清本次绑定卷、停止中继并检查无队列/进程残留。
日志和响应在私有目录保留，不把业务正文、模型输入或运行凭据提交到公开仓。

## 原App候选验证

从固定修订取真实Vue页面/API，候选补丁在私有目录。逐层执行：

1. 页面脚本的会话/取消/迟到响应、新建；实际API模块的字段序列化、201上传响应。
2. 编译原Vue模板和脚本；将uni组件原语适配DOM，回放上一阶段记录的真实响应。
3. 用浏览器实际点击键盘切换/发送/图片/人工，核对文字、图片字节、会话ID和新建清空。
4. 检查截图与脚本错误；图片使用现有`uni.previewImage`，避免固定小框压缩竖图。

该方法不等于完整uni-app构建、原生文件读取/放大手势、真实登录或公司发版；这些仍由公司发布过程验证。
不自动修改公司仓，不覆盖现役JS包。
