# 客服 Agent 会话验收计划

用户已确认：一个客服决策主体理解问题与上下文，按需组合本人订单和知识工具；
Gateway 负责身份、权限、预算与来源，最终回答自然表达。对应
[可观察场景](agent-conversation.feature)。本计划不是通过回执。

## 范围及判据

| 入口/场景 | 判据来源与可观察结果 | 环境 |
|---|---|---|
| 原提问/轮询接口：状态+账务+知识 | 独立合成 CPMS/知识记录；一次 Agent 执行组合证据，无前置能力分类 | 一次性 Gateway + 真 Dify/官方 Agent 插件 |
| 上一答追问、超过180秒、切换订单 | 已确认会话行为；模型收到已完成问答，实时值重新读，对象不串单 | 隔离栈；真实两端复验 |
| 他人单、跨租户库、撤权、取消、预算 | 现行本人授权和已发布能力上限；拒绝不读数据，不泄露凭据 | 临时数据库/受控上游 |
| 直接自然正文、澄清、未解决、人工、安全 | 已确认产品行为与已审核资料；无需最终 JSON/占位符，不能声称已退款/已接通人工 | 真实模型，记录未覆盖项 |
| 发布/试用/恢复 | 原入口使用固定发布版；草稿不影响正式，历史旧版仍可恢复 | 真 Dify 隔离生命周期 |
| H5/安卓同页两问与新建 | #1353 原始反馈；同页同会话，新建独立，模型确实收到上一答 | 原 H5 与 adbx 驱动原 APK 分别取证 |

长期检查仅覆盖新增授权/持久化错误及已发生的会话丢失；旧单能力测试无法证明组合取数、
不把执行180秒寿命当历史寿命，以及工具参数不会把授权交给模型。平台接线先用合成模型证明，
业务措辞与真实入口另行验证，不把两者混写。未核对真实故障时明确“未完成业务验收”。

## 实施与独立验证

影响范围：原 Gateway 提问/回调/回读、consumer 执行与试用、Dify 发布合同与迁移工具、
现有 consumer_knowledge 插件、会话与执行记录、对应测试/种子及原客户端会话传递。
沿用现有数据表和平台 Agent 工具循环；旧发布版走其原合同，新版显式版本化。
不提供停充、退款、工单或其他业务写工具。

作者完成相关检查、构建与隔离整链后，按[验证分工](../verification-workflow.md)派独立 Hacker：
首轮20分钟，修复后复验10分钟；从原入口独立设计反例，只读业务访问，临时根可以构造测试数据。
记录候选提交、实际尝试、原始证据和未验边界。生产迁移先保存原草稿、正式图、路由及插件标识，
按现有发布/恢复路径演练，绝不直接修改业务订单数据。

## 复现命令与迁移方法

先按[插件手册](knowledge-picker-deploy.md)构建并验签新版consumer_knowledge 0.0.2。
官方Agent策略包从Dify市场按ADR0229固定标识下载并安装，检查manifest.verified、任务终态与工作区列表。
不替换签名信任、不手改插件目录。两个插件分别安装；只有安装响应200不代表已可执行。

```bash
uv run python tools/verification/verify_consumer_chatflow.py --agent-conversation \
  --knowledge-plugin <已签名0.0.2包> --plugin-public-key plugins/consumer_knowledge/signing/public.pem \
  --out <新私有报告.json>
uv run python tools/content/upgrade_consumer_flow.py <原应用草稿.yml> --gateway <可信根地址> \
  --agent-conversation --knowledge-plugin <已安装0.0.2完整标识> --out <新草稿.yml>
```

隔离栈复用原Gateway启动器、官方Dify/provider/Agent与签名客服工具；模型和CPMS/知识/身份合成。
原POST/GET连续两轮，中间令首轮run过期，核对实际模型消息中的上一答、真实业务调用及跨主体拒绝。
报告失败必须区分业务失败与验收脚本问题；检查所有服务完成清理。

生产发布前保存原草稿、精确正式workflow版本、路由revision、模型配置及已装插件标识。
候选保留原业务SYSTEM；只删除带aiops-protocol标记的旧技术协议。早期种子的未标记JSON协议
不能当业务SYSTEM保留，使用明确业务版本作迁移源。模型必须已开启原生tool_call，
不新建同名凭据而忘记切换默认项。调试输出确认模型没有data_grant。

先原Dify预览，检查组合查询与追问，再通过原Gateway发布API冻结新版，原H5新建会话验证。
回退用已有恢复API推进revision，随后恢复草稿；不要倒写旧revision或覆盖运行数据库。
新回调精确路径`/v1/internal/consumer-data/agent`随Nginx制品交付，其余路径不扩大。
新应用开通复用原依赖安装与选库置换，不能复制来源租户的库。
