# 阶段文档与工作区收尾

用于已获授权的阶段收尾。一次文档整理使用一个任务分支/PR，不借清理启动未完成的业务功能。
原始日志、主机快照、分支元数据和未发布材料留私有归档；仓库只写选定的结论与方法。

## 先核证据与归属

1. 在规范checkout执行 `git fetch --prune origin`，记录 `git status --short --branch`、
   `git worktree list`、`git branch -vv`，默认分支只fast-forward。
2. 用 `dev-worktree start docs <任务名>` 建隔离工作树。检查全部工作树的未提交/未跟踪文件、
   分支head、owner和保留原因；不移动用户工作来消除冲突。
3. 用 `gh pr list --state open`、`gh issue list --state open` 读取正文、评论、验收条件与原生子任务。
   不能只按标题、年龄或CI绿灯判完成。
4. 读取current-delivery-state及最新验收记录，分别核对合并、CD、health、正式绑定和业务证据。
   真实环境按env-41-runbook只读取证；文档整理不自动授权生产改动。

## 文档同步

- 当前索引写“现役结论→证据→限制→下一步”，不持续堆叠旧状态。
- 历史validation、进度与ADR保留；已被后继证据改变的活跃手册更新导航与时点。
- 旧长索引可从精确Git修订读取，并在私有归档保留原件；不复制原始内部记录到公开目录。
- 新增当日进度与验收文件，检查链接、命令、退役路径、发布边界和敏感信息。
- 按文档变动运行目录/README检查、formatter、diff检查；不重跑业务场景冒充新业务验收。

## PR与issue处置

| 状态 | 操作 |
|---|---|
| 实现和约定验收均完成 | 留明确证据指针，issue以completed关闭 |
| PR被已合并交付替代 | 说明替代PR与未完成边界，关闭旧PR；不将旧候选再合并 |
| 目标已随正式决定退役 | issue以not_planned关闭，说明不是原规格实现通过 |
| 父票尚有开放验收子任务 | 保留父子关系，不因实现子票全绿关闭父票 |
| 缺真实验收/公司侧证据/产品定义 | 保留并写具体缺口，不能用“待确认”掩盖已知问题 |
| 滞留的历史文档PR | 先保留原文；选取必要事实合入本轮记录，合并后再关闭旧PR |

处置评论只写必要的公开证据，不上传原始日志、账号、主机清单或私有归档路径。

## 分支与工作树退休

1. 先将待清理分支制作私有Git bundle，执行 `git bundle verify` 并记录摘要。
   bundle是恢复材料，不代替已集成证明。
2. 删除前重新检查：本地/远端head未变、没有开放PR或在执行的任务、工作树干净，且归agent所有。
3. 可接受的集成证明：祖先关系、补丁已经上游，或**本地head等于已合并PR的最终head**且合并提交在origin/main。
   squash后有ahead计数是正常的；反过来，PR已合并但本地多了提交也不能删。
4. `git status`不显示忽略文件。另读 `git ls-files --others --ignored --exclude-standard`；
   验收制品和私有草稿先归档校验，虚拟环境/字节码等可重建缓存再随工作树移除。
5. 远端分支独立删除；工作树用 `dev-worktree retire <路径>`。只有本地分支的任务也先核同等证据。
   工具拒绝未集成时保留，不改生命周期元数据来绕过。
6. `dev-worktree preserve <路径> <原因>`登记确需保留的工作；不将preserve当重叠推送豁免。
7. 最后执行 `dev-worktree audit`；分别报告远端分支、本地分支、工作树清理和明确保留项。

部署工作目录、仍有服务引用的路径、历史backup分支和用户未提交工作不按“旧”来删除。
不进行全局docker prune、虚拟环境或缓存扫除。规范checkout与最终Git状态在交接中明确给出。
