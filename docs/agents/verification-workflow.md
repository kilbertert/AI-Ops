# 实现与独立 Hack 的验证分工

本规则适用于交互式开发、AFK 实现、修复与验收。决策见[ADR 0220](../adr/0220-evidence-first-verification.md)。
目标是减少重复和无判据的验证工作；确定性 CI、服务器风险验证、人工判断与既有权限边界继续有效。
本文件是执行约定，不是自动检测所有低价值测试的工具，也不把模型结论设为必需状态检查。

## 实现者

1. 开工前在任务或已有验收计划中写清用户入口、预期可观察结果、必须拒绝的情况及判据来源。
   oracle（判据）来自已确认需求、协议、上游事实或独立业务记录，不能从当前实现输出反推。
   沿调用链检查调用方、配置、资源及既有检查，先完成最小可用功能。
2. 默认不扩张测试体系。新增长期检查前，用一句话说明：拦截什么具体错误、判据来自哪里、
   已有检查为何不足。写在既有任务回执或 PR 中，不另建说明文件。
   权限、金额、持久化、解析与复杂分支仍留下风险匹配的最小行为检查；实现者对它负责，
   可由 Hacker 提供反例。覆盖率和变异验证按服务器政策的风险条件执行，不追求通用数字目标。
3. 迭代时运行能检验当前疑点的最小检查。无新改动、新失败或未解决疑点，不重复昂贵整套验证。
   交付时完成既定检查；同一候选与环境的有效结果可引用，不能用旧版本证据替代新版本验证。
4. 作者完成基本启动、构建和相关检查，再交给另一个会话的 Hacker；作者自查不算独立验收。
   按独立工作派发，不为凑并发槽位拆任务。

以下新增检查禁止进入长期套件：仅为数量/覆盖率目标补用例；复制实现输出当预期；
锁定无外部契约意义的私有调用顺序或文档措辞；堆叠没有不同失效意义的样例。
源码/文件检查只证明其实际保护的打包或仓库规则，不能替代业务行为证明。
测试红灯须分类为行为退化、已批准的需求变化或验证工具故障，再作相应修复；
不能放任红灯或放宽断言过关。既有资产按具体缺陷逐项维护/退役，不整批删除。

## 独立 Hacker

优先使用 `claude-deepseek` 配置的 `deepseek-v4.1-flash`（DeepSeek V4.1 Flash，cliproxyapi
配置别名；用户侧亦简称 dsv4.1f）。这是验收执行角色，
不替代 Devin Review，也不引入另一个必需 AI 审查状态。作者与 Hacker 必须是不同会话；
换模型不等于判据独立，Hacker 先读需求设计输入，再读实现找边界。

派发内容复用原任务和 QA 计划，至少给出：候选提交/构建、入口、范围、判据来源、启动/访问方法、
允许的数据与操作、证据位置和时间预算。访问配方应明确，攻击输入由 Hacker 独立设计。
默认一次探索和修复后一次复验；每次派发写明分钟预算。到期报告未覆盖项，缺环境标“未验”，
不能因没有发现、模型超时或返回空报告而自动通过——“没有发现”只在报告列出实际尝试的
路径与输入时成立；未执行尝试、尝试范围为空或报告不含证据的轮次视同“未验”，
验收信号不得标通过。现有调用器的超时以其实际配置为准。

1. 先从原用户入口驱动核心行为，再围绕本次改动寻找反例。按风险选空值、超长、越权、撤权、
   单位/舍入、并发、断线、重放或路径边界，不机械套用全清单。
2. 可以写临时脚本、构造数据和运行现有检查；默认不修改候选实现或长期测试。
   用临时数据根与获准的只读业务访问；生产写入、故障注入及额外额度不由 Hack 身份授权。
   Gateway 仍按既有技能在一次性根验证；本地替身不证明真实诊断、模型 run 或知识库活性。
3. 每条发现提供：版本、环境/时间、入口、最小输入或步骤、预期及其来源、实际输出、复现方法。
   实测反例与待复现假设分开记录。具体但未执行的反例可交给实现者调查，不能伪称已复现，
   泛泛建议不能直接转为返工任务。
4. 实现者复现并修复已确认缺陷；Hacker 在新候选上重放原反例并尝试未参与修复的新输入。
   Hacker 若亲自修改了被验实现，就成为该部分作者，独立验收需再次换手。
5. 只把值得防复发的最小反例转为长期检查，优先覆盖越权、金额、数据损失和已发生的用户故障。
   转换由实现者在修复轮完成（仍须满足实现者节的一句话说明）；Hacker 只在专门授权的
   写入轮落盘，且该轮之后须再次换手验收。临时探索不强制入库；复用已有 pytest、CLI
   或验证技能，不另建测试平台。

替身要复现有来源的上游行为，包括拒绝；不能为了“更严格”臆造上游规则。
必要时让原错误版本或受控变异触发失败，确认反例确实能拦住错误。

## 调用与结果

本机与 Actions 独立审查的文件/进程边界及复验命令见[审查执行手册](reviewer-execution.md)。
判定修复成功需读反例结果；H1 未闭合围栏曾误放行，不能再按“仅误拒”忽略。

交互式会话使用 `codexhost-delegation` 技能：先查 CLI 帮助、列出并检查目标 harness，再独立派发。
选用现有配置，不修改全局路由；任务回执记录实际模型标识。`deepseek-latest` 是可变别名，
不能只凭别名声称已经使用指定模型；不可用时报告原因，不静默换模型。

没有 CodexHost 连接时，可在已授权的任务目录使用现有 `claude-deepseek` CLI 启动独立会话。
先查 `claude-deepseek --help`。**模型映射由派发者核对后把结论写进任务，Hacker 不读配置**：
工具白名单不隔离秘密——文件可读就会进入模型上下文并随调用上行到供应商。每条派发
边界必须点名禁读路径：`~/.config`、`~/.claude`、`cliproxyapi` 配置、`settings*.json`、
`.env*`、SSH/agent 私钥与令牌文件。已发生一次实测泄露：核对别名的指示把 Hacker 引向
cliproxyapi config.yaml，其中的上游 key 进入了模型上下文；此后一律派发者给结论、不给路径。
例如只读文档/流程验收可使用以下命令；实际程序 Hack 再按任务范围开放必要执行工具：

```bash
# TASK_FILE 和 RESULT_FILE 是私有任务说明与回执位置，由派发者指定。
claude-deepseek -p --model deepseek-v4.1-flash --tools 'Read,Glob,Grep' \
  --output-format json < "$TASK_FILE" > "$RESULT_FILE"
```

这条 CLI 是人工/交互式派发入口，不是新建的后台服务。AFK 的本机 `review-prompt.md` 和
Actions `review/axis-prompt.md` 已有独立执行轮次，读取本规则；`review/prompt.md` 是其后的修复者。
AFK 模型仍由现有 `AFK_PROFILE` 与受控 settings 决定，不能用设置 `AFK_MODEL` 假定已换模：
当前 `claude-deepseek` 沙箱包装器会移除 `--model`。未核对映射的运行只记录实际已知身份。
两条 AFK 链路不因此自动补齐真实环境验收或修复后再次独立执行；负责交付的 agent 补派缺失轮次。

交付回执复用 `docs/validation/`：分别记录确定性检查、Hack 反例、用户路径及未验范围，
写明 Hacker 会话/实际模型、oracle 来源和证据位置。模型“无发现”、HTTP 200、测试全绿
均不能推导全业务可用；没有工程师确认的真实故障结论仍写“未完成业务验收”。
文档流程改动用实际指令入口和角色行为演练验收，不冒充业务界面或订单验收。

先在少量已知缺陷和后续真实任务记录有效反例、误报、总耗时及返工成本，再判断节时效果；
隐藏修复答案的样例用于能力评价，不规定每轮必须找到漏洞。
