# 决策材料：个人订单状态查询要不要常驻开放

日期：2026-10-23
状态：**决策材料，未实施**。生产个人查询目前**关闭**。
产出依据：#976（实现）、#992（H5 转发）、#997（真实页面验收）、
2026-10-23 第二窗口（真实跨用户拒绝，见[验收记录](real-h5-status-acceptance.md)第十三节）。

## 一、三层要分开看（本地接口测试实测，2026-10-23）

开关、地址映射、身份守卫是**三件事**，把它们的范围混成一件事就会得出过度结论。

### 1. 开关：影响**整台 Gateway 的路由选择**

`AIOPS_GATEWAY_CONSUMER_ORDER_CHAT_ENABLED` 读自进程环境，一次 `restart` 后对
整个网关进程生效。它决定"状态类提问**会不会**进入确定性路径"——不是"哪个租户能查"。

### 2. 地址映射：决定**哪些租户能解析业务端点**

`AIOPS_GATEWAY_CHARGING_STATUS_BASE_URL` 支持两种形式，行为不同：

| 形式 | 已登记租户 | 未登记租户 |
|---|---|---|
| `T-1:https://…,T-2:https://…`（映射） | 解析到各自地址 | **`ValueError: TENANT_ENDPOINT_UNRESOLVED`** ⇒ 生产 404 |
| `https://…`（旧标量） | 解析到该地址 | **同样解析到该地址**（不分租户） |

实测（本地，非生产）：

```
registered_T1        → https://cpms.example/charging-pile
registered_T2        → https://cpms2.example/charging-pile
unregistered_mapped  → ValueError:TENANT_ENDPOINT_UNRESOLVED
scalar_UNREGISTERED  → https://cpms.example/charging-pile   ← 标量形式不区分租户
```

**所以**：用**映射**形式时，未登记租户确实拿不到业务端点；但这不能说成"完整、
无副作用的租户灰度"——未登记租户的请求行为**会变**（从原来的普通问答变成 404
`TENANT_ENDPOINT_UNRESOLVED`），这是可观察的行为改变，不是"不受影响"。

### 3. 身份守卫：与租户映射无关，始终生效

`consumer + self + 非代查 + 有 C 端身份` 四条由正式解析器判定，**不受**上述两项影响。
把它和"能不能灰度"混在一起谈，会让人以为某个配置能放宽本人范围——不能。

## 二、现在能限制什么、不能限制什么

| 能限制 | 依据 |
|---|---|
| 只走**确定性只读**路径，零模型调用 | `internal_run_id=consumer-order-chat:<订单号>`；窗口内模型调用 0 |
| 只查**本人**订单（consumer + self + 非代查 + 有 C 端身份） | 正式解析器四条同时成立才继续 |
| 订单不可见时**不返回正文** | 不存在订单、非本人号码均 404，形状相同 |
| 不缓存 | 回答与错误都带 `no-store` |
| 不写业务数据 | 全程只读；`business_mutations: disabled` |
| 停用后**历史快照回读被拒** | `CHARGING_STATUS_DISABLED` |

| 不能限制 | 说明 |
|---|---|
| **按账号灰度** | 没有任何账号级开关；租户层面只能靠地址映射**间接**限制（且有副作用，见第一节 2） |
| 单次查询的频率/成本 | 没有按人限流；每个请求打一次 CPMS |
| 回答的措辞识别范围 | 只有简体/繁体/英文的保守措辞命中；其余落回原路由（可能是模型路径） |
| 证据文件的留存期 | 私有证据当前无自动删除；QA 到期不等于文件删除 |
| 真实存在的他人订单被拒 | 已验（2026-10-23，见第三节）；但仍只覆盖消费入口问答路径 |

## 三、已有证据 vs 仍缺的反例

**已有**（2026-10-23 受控窗口，真实登录身份 + 已部署 H5 页面）：

- 「本人最新一单」与「指定本人订单」两条，均 `202 completed`、页面真的渲染出
  订单号/状态/来源/观察时间；
- 第二条**换用另一张本人订单**，证明是按号走而非回落最新；
- SQL 选单与 CPMS 状态**独立对照一致**；排序用独立判据（可见行严格递减）；
- 缺会话 401、不存在订单 404，均不泄露正文；
- 窗口内**模型调用 0、诊断作业 0**；恢复后配置 sha256 与窗口前逐字相同。

**已补上**（2026-10-23 第二窗口）：

- **真实存在的他人订单被正确拒绝** —— 两个真实登录会话、同租户、不同 C 端主体；
  开窗前用生产查询函数独立确认该订单属于 A 且对 B 不可见。B 用自己的会话查它 → 404
  `ORDER_NOT_FOUND`；**开关仍开时** B 回读 A 的 QA → 404 `QA_NOT_FOUND`；
  对照 A 回读自己的 QA → 200。负例正文不含订单号/状态/来源/观察时间；窗口内模型调用 0。

**仍缺**：

- 越权样例只覆盖**消费入口的问答路径**；operator 入口、工单认领路径等各有独立证据，
  但不在这一条里。
- 原生 APK、真实用户长期行为、CPMS 在高峰期的可用性。
- 页面传 `conversation_id` 时的会话绑定路径（两轮窗口都未走）。

## 四、开启 / 观察 / 停用

### 开启

只改三项，**按产物身份写入**（`dev-host write --if-sha256 --artifact-sha256`），
然后只 `systemctl restart aiops-gateway-41`：

```dotenv
AIOPS_GATEWAY_CONSUMER_ORDER_CHAT_ENABLED=true
AIOPS_GATEWAY_CHARGING_STATUS_BASE_URL=<tenant>:<该租户个人 CPMS 地址>
AIOPS_GATEWAY_EXECUTION_ENVIRONMENT=41
```

**开之前先验一遍候选配置**：只构造 `GatewayServerSettings` 跑 `validate()`。
**不要**构造 app 来探测 —— 那会调用 `recover_interrupted_jobs`，把在飞作业标 failed。

三项缺一即启动失败（`consumer order chat requires its charging status endpoint`），
这是好事：配一半不会开门。

### 观察

| 看什么 | 怎么看 |
|---|---|
| 是否走确定性路径 | `assistant_questions.internal_run_id LIKE 'consumer-order-chat:%'` |
| 有没有意外模型调用 | 该时间段内 `gateway/runs/` 新增目录数、日志里的 token 数 |
| 有没有串单/越权 | 私有快照的 `scope_fingerprint` 与订单号；反例回 404 |
| 用户是否真的问到 | 页面日志里 `/v1/assistant/questions` 的 202 数 |

### 停用与回滚

**先停用、再看回读**：

1. 只撤销上面三个字段（**不要整文件覆盖**，防期间其他会话改过别处）；
2. `systemctl restart aiops-gateway-41`；
3. 验证：历史 QA 回读应返回 `CHARGING_STATUS_DISABLED`；
4. 回落行为：状态类提问回到普通问答路径（`queued`，可能走模型）。

⚠️ **回滚代码 ≠ 停用功能。** 启用期间产生的 QA 里有快照绑定；直接回到旧代码会让
旧会话逻辑重新使用这些快照。要么先停用，要么先独立处理这些记录。

## 五、建议

按当前证据，**可以常驻开放**，但需要同时接受三条限制：

1. 开关本身没有灰度能力；租户层面的限制只能靠**地址映射**间接做到，
   而那会让未登记租户的状态类提问变成 404（行为改变，不是无副作用）；
2. 每个状态提问都会打一次 CPMS，没有按人限流；
3. 真实存在的他人订单被拒**已验**（2026-10-23），但只覆盖消费入口问答路径；
   其余入口的越权判据来自各自的独立证据，不要合并叙述。

若这三条里任一条不可接受，可选的做法是**用映射形式上线**：登记要开放的租户，
其余租户的状态类提问返回 404。这是现成能力，不需要新写白名单或注册表；
但要接受"未登记租户的提问行为会变"这一点，并在开放前把该行为告知相关方。
