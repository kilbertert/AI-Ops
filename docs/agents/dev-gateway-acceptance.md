# 开发网关真实验收方法

在**不部署生产**的前提下，用开发主机上的 `aiops-gateway.service` 跑真实身份 / 真实
会话 / 真实模型的全链路验收。本文只写**可复现的方法**；每次验收的具体结果记在
`docs/validation.md`，当前可行动结论记在 `docs/agents/current-delivery-state.md`。

## 何时用这个载体

要验收的功能**尚未部署到 41**，或部署它需要一并推上超出本次授权范围的改动时。

判据不是「41 有没有在跑」，而是**41 的活动源码是否包含本次要验的代码**——用
`ls -l /opt/aiops-41/src/aiops_diagnostics/` 的 mtime 与目标 commit 的合并时间比。
若 41 的 mtime 早于合并时间，该功能在 41 上**根本不存在**，探它只会得到 FastAPI
默认 `{"detail":"Not Found"}`（我们的错误形状是 `{"error":{...}}`，可据此区分
「路由不存在」与「路由存在但拒绝了请求」）。

> 判据要按功能算，不要按「合并时间」一刀切。同一个 PRD 的不同子票合并时间不同：
> 代码已在 41 里的那部分可以在 41 验，只有不在的那部分才退回本载体。

## 载体

开发主机既有 `aiops-gateway.service`（工作树 `_runners/AI-Ops-deploy`，loopback
`127.0.0.1:8787`）。它是**非生产**实例：可以快进到 `main` 再跑，验收完按下方复原。

## 前置：让它真的能答

开发实例默认配置**缺**第三方会话与部分数据源的可达性（隧道指向的旧主机已下线）。
不补齐会得到 session 无效之类的假失败，容易被误判成代码缺陷。补齐三件事：

1. **真实身份**：`x-third-session` 需要隧道到 41 本机 Redis 的
   `app:3rd_session:*`。平台判定走 UPMS 真实查询，不是 fake。
2. **真实模型**：确认 key slot 可用。默认槽位可能 429；换一个可用的槽位再跑。
3. **数据源可达**：按被测功能涉及的数据面补隧道。

**这三件都是本地环境配置，不是代码缺陷**——补它们不算改仓库，也不该把失败记成
产品问题。

## 快进与复原

快进：把 `_runners/AI-Ops-deploy` 工作树更新到目标 commit，重启
`aiops-gateway.service`，`/health` 确认 200。

复原（**每次必做**，否则污染后续验收）：

- 工作树 `git reset --hard` 回原 commit（该工作树通常是 `state=preserved`，复位后
  保持 `preserved` 不变）
- `gateway.env` 还原：删掉本次加的临时变量，key slot 还原为原值
- 关掉本次开的所有临时隧道端口
- 备份开发库 `gateway.db`，落到一个带时间戳的回滚目录（如
  `_runners/AI-Ops-deploy-rollback-<时间戳>/`）

## 记录纪律

- 结果写进 `docs/validation.md`，并**同时**补 `docs/开发进度.md` 的里程碑条目
  （仓库规则：可交付里程碑更新进度 + 验证记录两处）。
- **明确写出这个载体不能覆盖什么**。在本载体上通过，不等于 41 公网已验收——
  必须单独写一行「仍未完成：41 公网链路 <功能> 验收」，除非另有 41 实测证据。
- 步骤与断言要能被人照着重跑（命令 + 期望值），不要只留结论。
- 环境复原的清单也要写进记录（改了哪些、还原成什么），这样下一个人才敢复用这个载体。
