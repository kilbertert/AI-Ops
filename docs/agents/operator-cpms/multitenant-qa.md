# 多租户管家验收步骤

环境：41 Gateway、36 Dify；前提是已部署现役 Java 管家及原生预览桥。
样本：源租户 A、目标租户 B，各自正常公司登录及有权查看的明确订单。
完整会话和业务原件仅保存于私有证据目录，不入仓。

| 编号 | 动作 | 可观察判据 | 清理 |
|---|---|---|---|
| MT-01 | 复制前后分别导出 A，读取 A 的正式路由；在 B 读取新应用与工具目录 | A 内容与路由不变；B 为独立 UUID，工具 UUID 属于 B 工作区 | 保留新应用；无业务写入 |
| MT-02 | B 公司账号登录，在 B 应用原生预览提交明确订单；按本次 QA/run 关联证据 | 页面完整报告，Java succeeded/matched，双工具成功且归属 B | QA 按正常生命周期保留 |
| MT-03 | 合法 A 会话访问 B 应用、B 订单及 B QA；另做 B→A 对照 | 403/404，响应无对方订单/报告；无登录401与过期410不算通过 | 不扩大成员权限，不伪造令牌 |
| MT-04 | 重跑 workspace/provider 对账，按 UUID 回读应用及登记 | 无重复资源、原路由不漂移 | 无 |
| MT-05 | B 不给订单或写“上一单”；再以无任务凭据直接调工具 | 明确要求订单；工具403且没有业务数据 | 无 |

MT-02/03 缺真实身份或订单时记录“待验证”，不得以管理员跨工作区读取或合成身份替代。
不据成功查询声明历史故障准确率；零采样仅为缺证。
