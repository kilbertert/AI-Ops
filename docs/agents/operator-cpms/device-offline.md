# 设备离线分析：配置、发布与复验

设备离线分析复用原管家Agent及offline卡，业务范围见[QA计划](../../acceptance/device-offline-qa-plan.md)。
`cpms_device_offline`按已授权站点/设备查询；默认近7天，显式窗口须带RFC3339偏移、跨度不超过31天。
`top_devices`前10、未恢复与重叠订单前50，均附总数/截断。状态2/3/5分别统计；同订单去重、离线时长取区间并集。

## 数据源与时间

使用Gateway实际`Settings.from_config`的MySQL只读配置，不使用开发机配置替代首发环境。
`AIOPS_MYSQL_TIMEZONE`须为已经核对的IANA时区；空值时新工具拒绝，旧offline卡仍可按原合同运行。
现役41只读核对：业务容器TZ=Asia/Shanghai、MySQL会话+08:00、事件列DATETIME；不是看时差猜时区。
只读核对方法沿[环境手册](../env-41-runbook.md)：读取实际进程配置，服务身份运行查询，不构造ASGI应用。

事件查询先取范围内当前设备（最多1000），再使用device_id/时间索引；订单使用device_id索引。
新增索引制品为deploy/node-runtime/device-offline-index.sql，须另行批准在线DDL后执行；缺索引拒绝新工具，
不能按当前device_code查询冒充完整历史。此项不由普通Gateway源码CD自动修改数据库。
每类候选最多5000条，超限明确拒绝并要求缩小范围，不以截断样本计算全量占比。
离线读面显式设置当前连接的REPEATABLE READ并启动只读一致快照，不依赖MySQL全局默认；
查询结束回滚关闭，交付前另起连接核当前归属。同一快照计算新结果；历史窗口与as_of分开。已删除设备、
缺归属记录可能不在可证范围；结果带限制及覆盖状态，不能称“全库无离线”。旧摘要保持历史定义，
新增`device_offline`子结果标明不同的时间/对象口径，不混加两组数字。

## 配套发布与恢复

1. 从合并修订取Gateway制品和`operator_tools.json`，按[节点手册](../../../deploy/node-runtime/README.md)
   备份现役工具声明、Gateway执行模板、回调配置与配置、核零在飞。Java使用现有object/request-target/2，不需新增执行器。
2. 完成已批准索引并检查EXPLAIN后，只替换节点挂载的工具声明，保持原属主/权限，重建node使缓存重新加载；确认心跳tools_sha256
   等于合并声明。Gateway执行模板也须由合并声明补齐新工具，保留模型、选项、原工具与属主权限；
   仅更新node声明或Dify目录会被candidate以“CPMS tool missing from node template”拒绝。
   在原页面预览前，用实际DifyDslSource和node_publication.candidate回读校验。
   同时用`tools/content/render_node_callback.py`从合并声明重渲染回调白名单，保留现场Lua/TLS配置；
   用callback服务身份执行`nginx -t`后按节点手册定点重启callback；不要以root校验，
   某些nginx构建会按默认www用户调整临时目录属主，使大证据POST落盘时报Permission denied。
   核client-temp/proxy-temp属主为该服务账号、权限0700；不递归改其他路径。
   遗漏白名单会在工具授权前返回404，不能靠重试解决。
   Gateway标准CD通过后，健康与变更文件SHA一致。
3. 根据已经核对的配置来源设置业务时区，生产配置/服务操作按本任务授权和变更单执行；不改业务表。
4. 登记受控工具目录，原Dify应用勾选新工具并补离线SOP；保存/预览不切正式。原页面发布后才启用。
   不批量给其他租户/应用加工具；旧订单分析仍用其已发布清单。
5. 失败恢复正式历史版与草稿，再恢复对应工具声明/配置及Gateway合并制品；revision递增，禁止倒写账本。

原Dify/管家H5验近7天、设备追问、关联订单、缺条件/越权/撤权，独立核CPMS/只读记录与时间。
未恢复表示“尚无恢复记录”，不是实时探测；重叠仅是关联线索，不证明断电/网络/SIM原因。
设备重启、退款和改单只可给人工建议，绝不由分析工具执行。

## 已验证的业务SOP补充

在目标应用已有SOP后追加以下段落，先预览再正常发布；不覆盖用户原有流程。

```markdown
## 设备离线分析（含订单影响核查）

用户询问设备或站点离线时，按需调用cpms_device_offline，不要求先给订单号。省略时间为近7天；明确时间用带时区偏移的RFC3339，窗口不超过31天。站点和设备必须来自用户或已授权检索。
本场景沿用核心结论、处置建议、简短依据的回答顺序；先简要回答用户问题，默认只列前三台需关注设备，不把返回清单全部抄出。
事实口径：summary.new_events是窗口内新发生的事件数；summary.devices是窗口内离线区间或时间异常候选涉及的设备数，包含窗前已离线者；unknown_duration_devices非0时，必须说明其中有无法确认区间的候选设备，不能把全部设备称为已确认离线。不能用两数相减推出精确已确认设备数，时间异常设备也可能同时有有效区间。必须分开说，不写“这些新增事件涉及这些设备”。open_incident_list.total是as_of时尚无恢复记录的设备数，独立于历史窗口，不是实时探测。quality.unverified_device_records是候选记录数，不是设备数；coverage为partial时明确不完整，不推算全量占比。
排行时长使用top_devices.offline_seconds（窗口内每台设备的区间并集），当前未恢复时长使用seconds_open，不混用。时长为空就说明未知；有known_offline_seconds只能说已知部分。0台未知时长并不意味着每条记录都有恢复时间：未恢复记录按窗口结束或查询时刻截算。
order_overlap.items的record_start/record_end是订单记录起止，绝不能当作离线事件起止。离线工具未给具体离线起止时只报离线时长，不编时刻。站点名称逐字引用，不翻译、缩写或加别名。未恢复不能称为无人处理；不能声称已查未查的设备、日志或报文。时间重叠仅是线索，不证明供电、SIM、网络等故障原因。
追问明确关联订单时，使用已返回的单号接既有订单排查SOP；一轮只查选定订单，多单需澄清。缺证只给可核实的人工建议，不把空字段或退款状态码解释成已经结算、到账或需要退款。

离线关联订单追问只核查用户这轮要求的内容。用户暂不核金额时，不列预付费、费用、退款、结算或币种。仅2条遥测且之后无记录，只能说“此后缺少遥测”，不能确定设备失联、启动成功或排除硬件故障。停止原因字段逐字作为“订单记录为……”引用，不翻译为另一条事实；没有原始报文就无法确认实际停止指令的来源、是否下发或设备是否应答。分析结论只给已知、缺证和下一步人工核实。
```


## 输出口径复核

95实测曾将359437秒写为3.6万秒，并把UTC时间与业务库解释时区混标。目标应用SOP需明确：
每个RFC3339值按其实际偏移标时区；`window.timezone`解释数据库原时间，不覆盖已输出时间的偏移。
时长保留字段完整整数与秒单位，不缩写为万秒、不自行换算天/小时；窗口时长和未闭环时长分开。
正常保存/发布后用同一原问题复验并对照该次工具证据；一条通过不代表所有自然语言事实均可自动保证。
