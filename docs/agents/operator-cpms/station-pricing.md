# 管家站点费用方案

输入明确站点名称、YYYY-MM-DD、同日HH:mm时间窗、电量kWh、可持续功率kW和IANA计费时区。
先确认“普通按量、不用优惠、不预约、不买保险、充完离场”；未给齐时在原聊天追问。
随后只继承同一会话上一条成功计划的用户条件，重新取当前规则，不把旧报价当新证据。

输出包含起止时间、分段电量与费率、电费/服务费/启动费、税率/税额、含税估算、最早开始
的对照费用、节省额及查询时间。按分钟选开始时间，结束显示向上到秒；无法保证硬件达到输入功率。
支持当前规则下四轮按量分时价；同日、未来31天、单次连续充电、无停车模板、零电损或上游默认零。
复杂套餐/停车收费/待生效变更/按时长服务/跨日/夏令时切换需另核，明确拒绝估算。
当前原入口验收重点为中文；其他语言质量不在本片验收范围。

## 部署顺序

1. 合并源码构建并校验节点jar及工具声明；按node-runtime手册备份并定点重建node。
2. 用合并修订的`tools/content/render_node_callback.py`重渲回调。必须保留宿主Lua指令，
   检查新工具名及`station-plan`路径，`nginx -t`通过后更新回调服务；不能只换jar和声明。
3. 标准CD部署Gateway，核health、节点能力/声明摘要与原入口。
4. 无订单管家按声明自动获得专属方案工具，不将它勾进订单诊断清单。消费者仍不可调用。
5. 用原H5与Dify提交缺条件→补充条件两轮，独立读取CPMS费率对照，保存QA与页面。

回退先回旧Gateway，再回节点声明/jar/回调成套恢复点；不覆盖QA数据库或业务订单。
