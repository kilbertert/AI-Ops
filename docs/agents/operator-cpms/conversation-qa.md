# 管家无订单对话与站点搜索验收计划

使用临时Gateway数据根与合成CPMS/身份，Java节点沿用锁定依赖。生产仅在合并制品部署后用
正常公司登录验收；不自签用户会话。原始站点、订单、令牌与截图保存在私有目录。

| 编号 | 输入与前置 | 动作 | 结果 |
| --- | --- | --- | --- |
| C-01 | 已登记应用；问题“订单状态3是什么意思” | 原问答/原生预览/普通试运行，不带订单 | 正常回答；CPMS调用0 |
| C-02 | “帮我诊断这笔订单” | 同上 | 提供单号的对话提示；不读数据 |
| C-03 | “帮我找一下广州天河附近的充电站” | 当前公司身份发起搜索 | 名称地址来自CPMS；地点匹配；无订单调用 |
| C-04 | 空范围、无匹配、超过页预算 | 搜索 | 各自明确说明范围、未命中或结果不完整 |
| C-05 | 混入其他租户/站点、缺身份、超量、取消/撤权 | 查询/回读 | 不交付；凭据不进入模型/日志 |
| C-06 | 有权限订单与既有草稿 | 原诊断及试用 | 双工具取证、最终JSON、节点匹配仍通过 |

站点接口候选为公司`release`的`GET /chSite/page`，分页current/size，筛选name/address；
正式实现前核对响应身份字段与运行制品。查询有硬分页/行数/字节上限，结果直接按数据渲染，
模型只选择业务类别和搜索条件，不生成站点事实或认证参数。

真实验收方法：先通过正常公司登录取得会话，原生预览从页面输入框发送；普通试用使用同源
`/__aiops/trial`提交并轮询`/__aiops/trial/result`。从原生SSE首个`task_id`去掉`aiops_`取得QA，
用它查询同次`agent_runs`，验证唯一run、succeeded/matched、无订单工具及snapshot中的sites。
在服务身份下用当前公司token再次调用固定`/chSite/page`，只比较id/name/address和租户/站点范围。
不要通过“最新成功的一行”关联；会话过期必须正常重登，不能将403记为功能失败或成功。

原生SSE正文用浏览器fetch响应副本读取，避免已导航后的`Response.text()`不可用；副本不修改请求或响应。
页面断言限定助手回答区：Markdown有序列表的序号由浏览器生成，innerText没有序号时先忽略这些
标记与空白，再核完整正文；不能只搜用户问题里的站名。截图、请求与QA记录仅放私有目录。

模型输出探查：若Gateway只留下固定拒绝码，使用失败run冻结清单与原问题，经现役固定模型出口
做单次有界请求，对照stream=false/true。代理令牌从node_config声明下的私有文件现场读，保持
项目CA验证与model-proxy证书主机名，不把令牌放进argv；响应留0600文件。探针只说明格式，
最终仍以原生页面/正式请求和CPMS对照验收。搜索text可丢弃，不参与条件、结果或快照。

完成后清理本次临时根、容器和浏览器；真实QA按业务生命周期保留。记录requirement→场景→
测试/实际结果、源码/制品身份、时间；没有实际执行的项写待验证。
