# 286. 候选管家沿原任务账本创建入口停用的应用

状态：已采纳；接续ADR0285。应用准备不替代执行目标登记和业务激活。

## 决定

已验证知识连接后的operator-prepare复用原资源账本；冻结平台唯一模型模板、SOP/工具及目标草稿地址。
只取平台profile的模型部分，不把41的节点目标复制到其他环境。首片管家使用仓内SOP及当前声明工具，
知识dataset、消费者和正式执行目标在后继步骤装配，界面和回执保持业务未验证。
导入的操作UUID与期望app ID先持久化；未知响应后只按ID回读，换计划仍复用资源，不盲目再次POST。

Dify普通agent-chat导入默认enable_site/api=true，创建后关闭有短时入口窗口。
显式aiops_candidate导入由实际创建服务在首次写入时设置两者false，能力接口声明支持，未配套则拒绝。
普通导入默认和原角色守卫保持；候选不登记正式路由、发布智能体或签发应用key。

## 替代方案

原开通流程可直接复用且一步交付，但首次自动发布，违反候选与激活分离。
创建后再关入口最少改码，但失败/掉线会留下已开放入口，选择创建时即停用。
另建候选资源数据库便于分类，却增加恢复权威；原环境任务和Dify幂等导入足以承载本片。

## 后果

部署须先配套自有Dify候选导入补丁，再更新Gateway与管理桥/Web；旧调用默认不变。
取消和漂移不删除候选资源；已确认但被编辑的应用阻塞，不覆盖草稿。模板更换要新验证，不能拿旧观察当通过。
本片资源齐备只证明准备，真实模型/工具run、内容质量、三业务及完整P4/P5仍独立验收。
