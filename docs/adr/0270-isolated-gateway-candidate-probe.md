# 270. 新环境先运行受限候选预演

状态：已采纳，执行已确认的手工环境开通规划P0/P3。

## 决定

复用现有Gateway wheel及systemd。开发机按目标Python小版本构建锁定依赖的离线制品，
服务宿主只在新目录安装，使用既有非登录项目服务身份、临时回环服务、独立状态根和资源上限。
预演验证制品身份、冷启动、匿名拒绝和双实例健康负载，结束清理自己的单元与状态，旧服务不参与切换。
制品参数只有Python小版本；不包含公司连接和凭据，不在宿主构建代码或访问包仓库。

## 替代方案

- 复用95安装器最省代码，但它固定3.13、路径及旧部署切换，不能用于3.12目标，也会提前承担流量迁移。
- 在客户机复刻整套Dify/Java/平台便于自给，但违背共享平台方向并增加内存成本。
- 只测开发机能更快发现语法错误，却无法证明目标解释器、动态库和systemd约束可运行。

## 后果

先得到可复现安装与清理证据，不因填表或health200启用租户。健康请求不代表三功能负载；
共享节点、正式HTTPS工具往返、业务配置、容量峰值和切流量仍由后续步骤验证。
依据pip/venv与systemd正式接口，具体调用和限制见[预演手册](../../ops/environments/gateway/README.md)。
