# WF01以独立节点编排知识和CPMS，授权仍由网关控制

日期：2026-10-27
状态：已采纳

## 决定与背景

原“检索当前用户适用知识”节点同时触发知识与CPMS读取，产品无法从图上分辨。
新版图使用Dify原生条件、HTTP与变量聚合节点，把knowledge/status/billing分成互斥分支。
Gateway沿用语义分类和授权选单，注入data_kind；节点自己回调对应能力端点，才发生一次业务读取。
调用路径必须与运行记录的能力一致，旧回调与新凭据不能混用，缓存之前同样校验。

cpms_status_enabled/cpms_billing_enabled是Dify字符串环境变量（true/false），条件节点清楚显示其用途。
实际能力取“服务端允许 AND 已发布图开关”，可关闭不可越过授权上限开启。
发布前校验节点、连线、URL、凭据引用及必需结果聚合；不完整图拒绝并显示中文原因。
图与开关一起进入既有不可变Agent版本；只保存草稿不影响App，撤回和恢复复用原管理语义。

试用复用正式语义分类，但订单仍固定为运营明确选定、且对运营可见的单，不自行挑最新单。
试用不是伪装成某个消费者登录。取数仍经过原范围授权，不将调用者凭据交给Dify。
已有callback_version=1的发布版保留回调和旧指纹；发布新图冻结为2，切换后不能用旧回调偷取数据。
无数据库迁移；历史恢复可显式回到旧版本，普通发布不能删光新契约后静默降回旧路线。

## 依据

Dify官方[HTTP Request](https://docs.dify.ai/en/use-dify/nodes/http-request)、
[If-Else](https://docs.dify.ai/en/use-dify/nodes/ifelse)、
[Variable Aggregator](https://docs.dify.ai/en/use-dify/nodes/variable-aggregator)：互斥分支用聚合节点选本次已执行输出。
按现用1.17.1镜像源码和隔离整链验证；环境变量随workflow发布复制，保存用environment_variable_patch，
不能把environment_variables直接提交到草稿同步接口（extra字段会400）。
Nginx三个新回调必须精确location，避免被现役`^~ /v1/`前缀截走并替换凭据。
试用可预期的能力关闭/订单指代/澄清使用稳定码与公开文案，未知错误继续通用失败。

## 备选方案

- 仅改旧节点名称或添加展示节点：最省代码，但无法按节点观察实际取数，不能满足需求。
- Dify直连CPMS并持有业务令牌：编排自由，却旁路个人授权、扩大凭据可见面，不采用。
- 新开发自定义插件：可定制UI，但原生HTTP节点已有所需能力，不增加插件部署负担。

## 后果

本版提供固定业务模板、两个显式开关与可编辑提示词；改安全路径或任意加节点需更新契约，
不声称提供自由业务写操作编排。状态与账务仍互斥，不额外同时查知识。
Dify输入/HTTP执行记录会保存短期凭据，终态撤销不能追回此前可见数据，此限制没有消失。
