# 182. C端状态与账单答复先说结论，再用人话解释每一项

日期：2026-10-30
状态：已采纳

## 背景

2026-10-30 的产品反馈：「内容不是技术解释，是下结论，然后给通俗易懂注释，最起码商务
能看得懂」。

上一片（[ADR-0180](0180-answers-are-plain-text-laid-out.md)）只解决了**排版**：分节、
逐行、去掉微秒。落到 C 端的实际输出是这样的：

```
订单账单：2113549588485718017

订单金额：27.36
支付金额：0.00
退款记录：未退款
已退金额：未提供
查询时间：2026-10-29 12:34:45 UTC

注意：接口未提供币种，请与原订单页面核对。……
（技术标识：来源 cpms.chargingInfo）
```

逐行读了，仍然回答不了读者真正问的两个问题：**这单到底多少钱**、**0.00 是没付还是没扣**。
另外 `未提供` 分不清「上游没这个字段」还是「我们没查」，`cpms.chargingInfo` 与
`status_code=1` 则完全没有信息量。

## 决策

**正文第一段是结论句，其后逐项用人话解释；内部标识不进正文。**

- **结论句由真实存在的值拼**，缺哪项就不写哪项，绝不补一个数字。账单是
  「这单的账单合计 27.36，系统记录的支付金额是 0.00，没有退款记录。」；状态是
  「这单当前的状态是「充电结束」。」。
- **术语就地解释**：支付金额那一行必须写明「账务系统里记的数，不等于银行已经扣款」，
  退款那一行必须写明「有这条记录也不代表银行已经到账」。这是反方向最容易被"优化"掉的
  一句，改词会让用户以为钱已经到账。
- **缺值说成「上游未提供」并给出下一步**（到原订单页面核对），不说成「未提供」这种
  两边都能解释的词。
- **来源写人话**：`cpms.chargingInfo` → 「充电状态记录」，`cpms.orderDetail` →
  「订单账务记录」，与管家报告的 `_SOURCE_LABELS` 同一套说法。
- **`status_code` 整条下线**。原始状态码只留在存储的快照里（`agent_runs.snapshot`）：
  它是排查用的，不是读报告的人要的；正文给「未知」时另附一句「这个状态码不在已知范围内，
  我无法确认它代表什么」，比摆一个 `status_code=999` 诚实。
- **十一语种同形**：`zh`／`zh-Hant`／`en` 由 `consumer_plain.py` 的词表拼，其余八种走
  `consumer_language.json` 的模板；`status_code` 占位符从所有语种一起下线。

新增 `consumer/consumer_plain.py`（叶子模块，只依赖 `consumer_time`）：三条渲染路都要用
同一套词，而 `consumer_language` 被另外两条导入 —— 放进去会形成包内循环边
（`tests/test_readme_architecture.py` 会红）。

## 被否掉的替代形态

- **只改 Dify 的提示词。** 这条路由**根本不调模型**（`docs/agents/frontend-api-brief.md`
  写明「该路径无模型调用」），改提示词对它零影响。只有带「为什么／扣费／金额」的问题才会
  路由到 Dify 链。
- **让模型把五字段重写成一段人话。** 那会把「读到的数字」与「写出来的文字」之间的可核对性
  交给模型，而且要多一次调用。这一层的数字必须来自确定性来源。
- **用 Markdown 加粗/列表。** 前端按 `blocks[]` 分派渲染，不解析 Markdown（ADR-0180 已论证）；
  `**` 会原样显示。层级只能用空行、`·`、短行表达。
- **金额后面直接补「元」。** 接口确实没给币种。补一个单位就是替上游断言了一件事，
  与「金额不证明已扣款」是同一条纪律的反面。
- **把 `status_code` 留在正文括号里「给排查用」。** 排查要的是订单号 + 时刻 + 记录本身；
  原始码在快照里一直有。留在正文只解决了"顺手"，代价是每个用户都要读一段机器话。

## 代价

- **文案即回读一致性键。** `chat_execution.answer_matches_snapshot` 用**当前代码**重算
  正文并与库里存的那一份比对；改措辞会让部署瞬间正在回读的会话落到 `qa_answer_mismatch`
  （节点路线把 run 钉成终态，Dify 路线返回 503）。窗口受 `RUN_TTL_SECONDS = 180` 限制，
  是分钟级而非历史数据。**本次接受这个窗口**：把它换成"读不到就重渲染"，等于让篡改检测
  悄悄失效 —— 那正是 `final_release` 拒绝交付时要拦的东西。
  真要同时满足，得给渲染加版本号并按版本放行，那是另一片。
- **既有测试里「来源必须原样出现」的断言被改写**（`cpms.chargingInfo` → 「充电状态记录」）。
  这些断言原本守的是「读者认得出这段数据来自哪条记录」，改的是指针，不是意图。
- **`en` 仍是代码渲染，八种语言是模板**：一种语言要改两处。这是既有分工，本片没有搬掉。
  搬运会牵动 `localized` 语义与 `test_older_context_*` 的回读判据，不属于本片的收益。
- 措辞是写死的中文/英文/繁体词表；新增语种仍需人工翻译，没有运行时翻译。
