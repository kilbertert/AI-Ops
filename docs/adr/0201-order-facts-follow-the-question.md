# 201. 订单事实段跟着提问走，不把后台整页抄下来

日期：2026-11-04
状态：已采纳

## 问题

用户反馈三件事，实为同一处的三个症状：

1. **「返回数据都一样」**：同一张单问「电压」与问「电费」，答复除结尾句外**逐字相同**；
2. **「列出充电桩的各项数据应该不对」**：事实段无条件列出 20 个字段，读者拿到的不是回答，
   是一张后台页的抄本；
3. 更糟的是**问电压那一版里电压其实是空的**（上游 `voltage: null`），整行被跳过 ——
   于是满屏其他字段把「这一项没有」盖住了，看起来像答非所问。

## 决策

`_order_fact_text` 按**提问原文**选出主题字段，只列这些：

| 主题 | 触发词（示例） | 列出的字段 |
|---|---|---|
| fee | 电费/服务费/账单/支付… | 预付费与各项费用、合计、支付与退款 |
| energy | 电量/度数/kWh | 电量、时长、功率、起止 SOC |
| electrical | 电压/电流/功率 | 电压、功率、设备与枪编号、接口类型 |
| process | 过程/明细/曲线/时长 | 电量、时长、起止时间、功率、SOC |
| stop | 停止/异常/原因/状态 | 状态、停止原因与时间、创建时间 |

两条硬约束：

- **认不出主题就退回全量**（`None`）。词表是维护中的，漏词只会回到旧行为，不会答错主题。
- **主题字段有空值时必须写「未提供」**，不能整行消失。旧行为跳过空值，正是症状 3 的成因；
  但只在**认得出主题**时这样做，否则全量模式会把整页变成「未提供」。

题面判定只看**提问原文**，不看模型输出 —— 模型仍只写开场语气，事实由系统给。

## 被否掉的替代

- **让模型自己决定列哪几项**：事实段是系统写的，交给模型就等于把「哪些事实可信」变成
  模型判断，与 ADR-0190 的分工相反。
- **固定只列费用**：问电压、问停止原因的提问会全部落空。
- **全量但折叠/分页**：前端按 `blocks[]` 渲染、不解析 Markdown，没有折叠能力；
  而在纯文本里「折叠」只能是省略，那比现在更误导。
- **把主题选择做成可配置**：主题边界是产品语义不是部署参数，配置化只会让每套环境
  对同一句话给出不同字段。

## 代价

词表是**维护中的**，不是穷举：出现新问法时可能退回全量（安全方向，但不是最优）。
主题与字段的对应关系是产品判断，改它要像改判据一样给出理由。
