# 209. 订单金额核对保留规则来源和未验证边界

日期：2026-11-04。状态：已采纳。

产品要求在原订单SOP中补充模板与四项金额演算。沿用历史模板工具，新增明确授权的
`cpms_order_billing`读取后台订单详情：旧`getOrderInfoDetail`的模型没有`discountDetails`，
不能只扩字段白名单假装能取到。新工具在订单详情/历史模板交付后才读取，重新核对订单、
租户与站点，只投影金额和受限优惠键，节点与Gateway使用同一声明收证。

Decimal和ROUND_HALF_UP延续ADR0203。公司商城代码先按折后价取两位，再与服务费相减；
八折存8，税率20%存20。普通总费用还包含电损电费、电损服务费和停车费，简式只适用于它们为0。
逐项算术对照之外，另从分项串联税额和应付，避免错误中间值互相印证。

`carRightPrice`是权益优惠总额，可能包含电费与其他权益，不是服务费折扣额；
没有独立记录时只报试算/待验证。后台UI展示值也不自动成为独立证据。拒绝以结果反推规则，
拒绝让模型计算或编造缺失后台值。整单正确性仍依赖计量、模板适用性、优惠资格等证据。

接口读法遵循RFC9110 GET与既有对象授权；JSON优惠字符串按RFC8259拒绝重复键歧义。
金额舍入依据现有公司`collectFee`、`MarketOrderDefaultNct`、`SaveEndOrderNct`，
不宣称适用于所有币种或任意税法。原始公司源码与生产数据保留库外。
