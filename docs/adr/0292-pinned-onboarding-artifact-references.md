# 292. 开通制品引用按合并修订固定并以CAS更新

状态：已采纳；接续ADR0289–0291。读者为环境开通和部署维护工程师，说明控制端制品引用的更新边界。

## 决定

环境references文件只保存登记环境的固定应用包和安装器包引用。`aiops-admin environment-artifacts`
要求调用者已有该环境授权，并在同一目录锁内核对当前文件摘要、目标Python、包内清单及相同的完整合并修订。
制品先复制到受控`onboarding-assets/<revision>/`固定路径；应用包文件名还包含目标Python小版本，避免不同目标的
依赖归档冲突。引用文件再以旧摘要CAS原子替换，旧完整字节保存为
带旧摘要的0600备份。配置引用、环境/主机/配置编号和租户准入不由此命令改变；更新后旧冻结计划必须重新预检。

命令只更新控制端引用，不访问目标主机、不安装、不写运行配置、不激活。摘要过期、备份冲突、制品修订不一致、
清单错误或权限不足均在复制/替换前拒绝；替换后的目录同步失败恢复旧引用，无法确认外部变化时保留备份。

## Alternatives considered

直接把临时上传路径写进references最短，但临时文件可被删除或替换，安装时无法证明引用稳定性。
每个版本维护一份完整references文件可回滚，但会产生多份可编辑真值并使配置引用漂移；不采用。
先复制制品再无条件重写引用能减少CAS代码，却会覆盖并发更新或管理员撤权后的内容；不采用。

## Consequences

控制端可重试同一修订并保留明确恢复点，目标安装器始终读取稳定私有路径，且配置与业务准入保持分离。
每次更新会保留私有备份并可能留下已核验的不可变制品，需要按受控生命周期归档；引用更新本身不代表目标已安装、
网络可达、模型可用或业务验收通过，后续仍必须执行标准安装和现场验收。
