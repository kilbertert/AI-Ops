# 219. 名称和币种归属由程序核对

Status: Accepted

日期：2026-11-05。用户要求完成自然语言SOP改造，原H5验收发现无来源币种和站点别名。

## 决定

沿用一次模型复核：模型识别回答肯定使用的币种、已查到站点名称及别名，并核对其他事实。
现役工具没有币种字段，因此不能将裸金额加币种；站点名称只能来自本轮工具或重新授权的历史
工具证据。程序做集合比对，模型总体allow不能推翻归属判定。否定句和建议中的地点示例由模型
按语义区分，不建关键词路由。历史证据在检查前和最终交付前重新授权。
提示词要求金额缺币种时仅写数值，站名保留原文。响应畸形或失败仍不交付，不增加修复循环。

## 备选方案

- 只返回allow/reject：原失败文本和最小币种反例均被误放行，否决。
- 长篇逐项证明：保留样本测试发现编造原文、误拒历史解释，否决，不部署。
- 关键词禁止“元”或中文站名：会误拒否定句及真实中文名称，否决。
- 恢复字段路径最终答复：ADR0218真实实验已出现虚构索引，否决。

## 代价与边界

一次结构化响应仍1024输出令牌、20秒超时、reasoning.effort=none，工具/Java合同不变。
模型抽取仍可能漏项；程序保证被抽出的实体必须有来源，不声称任意语义已证明。
若工具将来增加ISO4217币种字段，必须同版扩展投影、声明和比对，不能凭常识预置币种。
