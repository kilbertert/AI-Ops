# 295. 候选准备以父任务接续已有资源任务

状态：已采纳；接续已批准P4规划。本片仅把已实现的候选资源准备串联，不安装、激活或自动试跑模型。

## 决定

管理员选有效冻结计划、租户与明确客服来源版本，一次提交candidate-prepare。
父任务复用现有environment_tasks表，记录同计划现场/工作区/知识/连接/双端应用子任务；
环境＋计划＋租户＋来源＋依赖摘要确定唯一任务，刷新与换设备重复提交回读原编号。
现有运维轮询每轮先推进有界候选父任务，再领取原子任务。父任务不占环境执行租约，防阻塞自己的子任务。
父任务持久状态waiting不进入旧执行端的queued/running领取集合，公开返回queued供页面显示；不误派成现场检查。
每次后继入队与记录子编号同一SQLite事务；恢复从持久子编号接续，上游未知继续原子任务对账，不重复开户。
来源/依赖/计划/权限变化或子任务失败均阻止新步骤。取消只撤父任务新拥有的资源子任务，
共享现场检查或原已有任务不被误取消；已发上游请求沿原取消对账合同返回，资源不删除。
父任务observed只代表资源准备，不将安装、业务验收或激活标为通过；独立单步骤入口保持。
旧组件只显示/忽略未知父任务，旧执行端不领取父任务；控制与执行端升级后自动推进，Web最后交付。

## 替代方案

前端依次提交最少后端变化，但关页或网络中断就失去接续，不满足跨设备持久任务。
父任务独占环境长租约易实现串行，却让原子任务无法领取，制造与子任务互等。
新建通用状态机和资源补偿引擎便于扩展，但既有子任务已经承载副作用与对账；只增加父子接续合同。
把准备与激活一次放开最接近完整一键，但当前真实三功能与身份/网络/容量仍不全，不能借串联绕过验收。

## 后果

管理页面从六次分散操作变为一次候选准备，持久进度与部分失败可回读。
15分钟计划窗口仍适用；超时后新计划重新观察，不能通过父任务延长授权或续跑新副作用。
安装、正式入口与能力验收沿P4后继任务单独接续，本片不宣称完整开通完成。
