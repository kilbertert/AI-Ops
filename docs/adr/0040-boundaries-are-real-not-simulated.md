# 40. 试运行的边界用真实现，不用替身凑出来

日期：2026-10-18
状态：已采纳
影响版本：`deploy/m2-live-03/`（`make-certs.sh`、`build-runtime-config.sh`、compose 与 checks）

## 背景

试运行栈要在一个入口上（隔离 Gateway）复用生产的两类东西：**会话身份**（生产 Redis）
与**只读业务依赖**（业务 MySQL、UPMS、TDengine、thirdSession 令牌）。第一版部署件为了
省事走了两条捷径，两条都在审查里被指出，并且都不是「风格问题」：

1. **平台这一跳用回环中继**。`canonical_gateway_url` 规定远端必须是 HTTPS、只有回环可以
   用明文；部署件在 Gateway 容器里起了个 `127.0.0.1:8900 → platform:8900` 的中继，让
   「地址是回环」成立，于是校验被绕过而不是被满足。平台令牌与请求体在跨容器链路上是明文。
2. **挂整份 `production.env`**。Gateway 的设置读取是「环境变量 or 配置文件」，所以整份
   文件意味着试运行实例继承生产里**所有未覆盖**的开关与凭据：路由分类、发布、媒体签名、
   模型供应商。隔离入口因此开放了超出试运行范围的接口，而且新增一个生产开关会自动进入
   试运行。

## 决策

**边界用真实现表达，替身只用于「本机不存在的外部依赖」。**

- 平台讲**真 HTTPS**：`make-certs.sh` 生成本地 CA 与 SAN 含 `platform` 的服务端证书；
  Gateway 通过 `SSL_CERT_FILE` 信任这一个 CA。`canonical_gateway_url` 一字未改。
- 只读业务依赖走**白名单子集**：`build-runtime-config.sh` 只抽会话库、业务库、UPMS、
  TDengine 与 thirdSession 令牌；缺任一必需键就拒绝写文件（不留半个配置）。
- 仍然保留的中继只有一处：**宿主回环的 Redis**。Redis 本身是明文协议，中继转发的是同一段
  明文，没有「把 HTTPS 降级」的含义；它只接一张仅 Gateway 可见的网络。
- 合成验收里的替身（模型桩、CPMS 桩、固定调用者）单独列在 `compose.synthetic.yaml` 与
  启动报告的 `substituted` 里，**不进正式启动命令**。

## 被否掉的替代形态

- **保留回环中继，只加注释说明它是实验性的。** 它最省事，也确实能跑通；但「地址是回环」
  这个前提是校验的一部分，用它来满足校验等于把校验变成一句声明。而且注释不会阻止下一个
  人把它复制到别的部署件里 —— 本仓已经有过「规则只写在作者想到的路径」的教训（ADR-0035）。

- **继续挂整份 `production.env`，另加一份「不要使用这些键」的黑名单。** 黑名单要求列举
  生产配置里**将来**会出现的每一个键；漏一个就是一次静默继承。白名单的方向相反：新增
  生产开关默认不进入试运行，需要显式加进白名单并过审查。

- **把 `canonical_gateway_url` 放宽到允许内网明文。** 那会同时放宽生产的判据，而生产的
  判据正是这条校验存在的理由。

## 后果

更容易：隔离入口暴露的接口集合现在是**可枚举、可审查**的一小份；平台的传输能被独立验证
（`checks.sh deps` 从 Gateway 的网络空间建一条真 TLS 连接并报告版本与校验模式）。

更难：每次新增一个试运行真正需要的只读依赖，要改白名单并重新生成 `runtime.env`；证书材料
要跟着栈走（`/etc/aiops-m2-live/tls`，0600/0700），并且**重建证书会让已加载的网关信任失效**，
所以 `make-certs.sh` 是幂等的。

上限：本地 CA 只解决「这一跳是真的 TLS」，不解决平台自身的账户体系、审计或轮换 ——
平台商业采用仍是后续门。中继仍然把宿主回环的 Redis 映射进栈，这是「依赖在宿主回环」这个
事实的表达，不是让 Redis 走出宿主。
