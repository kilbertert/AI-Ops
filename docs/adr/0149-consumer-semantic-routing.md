# C端语义决策与订单授权分离，快照有效期不等于会话有效期

日期：2026-10-26
状态：已采纳

## 决定与背景

WF01普通文本原来依靠关键词决定是否查单，口语“上一个订单什么情况”会落入FAQ。
改成无工具的结构化模型请求，仅选择能力、订单指代和是否依赖前文；网关仍执行本人授权、
发布开关、唯一目标校验与本轮取数。模型不能返回身份、单号或业务事实。非法结果或模型故障显式503，
不以FAQ或旧关键词掩盖故障。危险/人工的既有快速提示、图片路径及未启用WF01的旧入口保持原规则。

使用既有provider配置和HTTP客户端。格式参考[Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)：
全部字段required、additionalProperties=false；Responses使用text.format，Chat使用response_format。
本地仍严格校验完成态、字段和拒绝/工具输出；官方协议不保证兼容供应商完全实现。

前轮快照过期只使旧上下文不可用：明确的新问题在同一会话建立新运行，不继承上游记忆；
指代旧单则提示重述。有效前文在分类前、分类后及提交时核对；历史正文的TTL与授权保持有效。
失败、取消、换发布版本仍需要新会话。当前代码仍对未过期的前轮执行结果守卫，旧结果失去授权时不会沿用。

## 备选方案

- 增加“上一个/什么情况”关键词：只能修已知句子，仍会误伤“订单状态是什么意思”，弃用。
- 把订单读取交给自由工具调用：扩大模型权限和不确定行为，当前只读能力无需如此改造。
- 在模型故障时退回关键词：用户无法分辨是否真正理解，不采用。

## 后果

每个普通文本请求增加一次分类，1024输出token预算包含推理；无工具、无上游会话、应用层不重试。
20秒是HTTP读操作超时，不是整个POST硬截止。真实语料经受控转发约7–10秒，供应商波动仍可能使客户端超时。
只传问题和经结果守卫核验的上一句问题，不传业务快照或凭据；用户主动写在问题中的数据仍会到模型。
多意图、未知实时信息、多单或不一致指代先澄清。分类语料是回归样本，不代表普遍准确率。
