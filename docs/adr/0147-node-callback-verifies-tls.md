# 节点回调使用项目CA签发的HTTPS

日期：2026-10-26
状态：已采纳

## 决定与背景

管家CPMS工具只接受HTTPS或回环HTTP；现役节点回调使用内部网桥HTTP，不能满足新工具授权契约。回调模板改用现有端口上的TLS，证书由节点已信任的项目CA签发，SAN包含回调地址，私钥只供回调服务读取。沿用精确路径和方法白名单，保留原认证头。

## 备选方案

- 允许工具信任任意内网HTTP：接线简单，但任务凭据可被明文读取，且扩大工具边界，弃用。
- 另开HTTPS端口并长期保留HTTP：迁移可分阶段，但增加监听和防火墙配置；当前可在明确窗口同步切换并恢复，无需新增常驻端口。
- 关闭证书校验：可绕过信任配置，却不能识别真正回调端点，弃用。

## 后果与限制

模板按nginx官方HTTPS配置映射 `listen ssl`、证书、私钥及TLS版本，测试使用真实nginx验证可信请求、未信任证书和明文拒绝。现役切换必须同步节点URL和回调配置，无在飞任务时实施；失败恢复旧配置及URL，不回滚业务数据库。合并模板不等于已迁移服务或已完成管家业务验收。**2026-10-26 已在 41 完成切换**：回调改为 `listen 172.30.41.1:8788 ssl` 并反代网关，节点 URL 改 HTTPS；节点容器内用现役 truststore 的真实 Java 握手得 403（无凭据被拒），明文进该端口得 400，网关本体 200。切换失败两次均由脚本回滚并核到原摘要，改用具显式超时的探针后通过。备份与摘要见`docs/validation/2026-10-26-operator-cpms-tools.md`「现役制品同步」。
