# 0246. 消费者复用账务读取交付订单构成

Status: Accepted

日期：2026-11-11。订单投影已随1.7.1交付，事实约束v2随1.7.2交付；完整性约束v3为1.7.3候选，尚未正式发布。

## 决策与来源

原消费者`read_billing_record`把同次订单详情中的电费/服务费丢掉，只留下总额、支付和退款。
在原`billing`资源上扩展白名单，交付订单摘要、费用、分时与缺项说明；不新增请求、权限、
数据表或计费服务。v6显式启用，callback1–5继续原七键投影，旧plain/facts/reply不接收新证据。
最终答案仍由Agent自然表达；发布图新增指导，既有签名插件原样透传JSON，无需升协议或签名版本。

业务名称沿用ADR0193及父会话核对的`ChOrderInfoModel`/`FeePeriodDetailItem`字段定义。
`time`为分钟、`createdTime`为创建时间；`periodFeeDetail.electricity`在已核对的
`ComputePriceUtils.buildServerBillingPeriodFeeDetail`路径可能由总费用除组合费率反推。
父会话核对的是固定源码修订与两份来源字段形状，不证明该源码修订就是生产构建。
因此不把分时电量当独立计量，`feeRate`只投影来源数值，custom计费单位未核定。

技术映射遵循Python标准库[`json.loads(parse_float=Decimal)`](https://docs.python.org/3/library/json.html#json.loads)
及[`decimal`](https://docs.python.org/3/library/decimal.html)：账务入口显式启用十进制解码，
通用HTTP其余调用仍默认float；金额投影成字符串后才进入JSON响应，避免二进制舍入。
不计算差额，不把总额减支付当优惠，不提供独立计费正确性判断。

每项合法金额最多8位小数、非负且有限；null/缺字段与非法字段分别标明，不补零。
文本最多64字符，分时最多24行并附来源总行数/遗漏数；HTTP源仍限131072字节。
时间字段只接受已知日期/时钟格式，并经datetime/time验证；不允许短文本伪装成时间。
账务专用Decimal包装器将超大指数的构造异常映射为业务不可用，不影响其他HTTP调用。
币种仅接受来源三位大写代码并检查冲突；这不验证货币代码名录，不猜币种、不换算或跨币种合计。

现役v6图迁移保留BASE和前后运营文本、模型、工具、选库和其他配置，只移除唯一完整已知的
本任务v1/v2/v3规则块，再将当前v3放在整份运营文本末尾。已发布v2完整字节保留为迁移输入。
已迁移图幂等；块未知、重复、标记不匹配或超16000字符则拒绝，交给负责部署者核对。

## 被否掉的替代形态

- 只改提示词最省改动，但模型没有上游已给的分项，无法解决实际缺项。
- 复用管家完整计费能力可取更多历史规则，但跨越本人授权与不同执行面，不在本次范围。
- 所有callback统一扩展投影可少一个开关，但旧事实/数字验证器会看到未设计的证据，破坏恢复合同。
- 重新生成生产v6图可统一形状，但会丢失运营后缀；局部精确替换可保持既有业务表达。

## 后果与验收边界

无需新上游请求即可覆盖来源实际提供的构成，继续本人前后授权和8次工具预算。
来源缺项、异常、币种与费率单位仍有限制；24行以外只报遗漏数，需原订单页核对。
本地HTTP→原Agent回调、解析边界、旧合同与迁移检查见[QA](../agents/consumer-wf01/order-composition-qa.md)。
本地合成模型不证明真实模型完整展示或业务计费正确；独立Hack、真实问答及部署由父会话完成。

## 后验限制：数据齐全不代表自然回答可信

1.7.1上线后，父会话真实preview确认费用进入工具，但答复仍擅加币种、把null说成未收费、
未核验就安抚“无异常”，且自行合计出错。实际图为业务前缀+BASE+规则v1+运营后缀，
后缀要求安抚与判断有无问题，位于事实约束之后。仅见completed不足以确认业务答案。

延续原决策，以规则v2明确事实约束优先于风格安抚，并放到整段运营文本最后：仅列来源记录，
不自主合计/税基/差额归因；没有确定性核验结果不下收费正确或无异常结论。
币种缺失/无效/冲突时开头说明且全文金额不用币种单位；null仍是未提供，不能说未收费。
可简洁列零项，按需回答单项，保持v6自然回答与原运营风格，不重算业务或覆盖最终正文。
原始BASE保持不变；迁移仅接受无规则、唯一完整v1或v2，未知/重复标记拒绝，v2末尾形状幂等。
测试证明图迁移与文本保留，不证明模型遵守语义；真实preview及双入口逐句检查由交付会话完成。

## v3：开头不能把缺项概括为齐全

1.7.2真实预览中费用、币种、null和分时已对，但开头仍称“各项都有记录、放心核对”，
与后文占位费未提供矛盾。因此仅在保留v2其余规则的基础上增加两句：开头只总结已取得的分项，
同时点出缺项；有null、非空missing/invalid、币种缺失/无效/冲突或截断时不保证齐全，
不能先概括完整再在末尾补限制，也不能以“放心核对”保证完整性。
仍保持自然回答，无新增validator、审核模型、账务运算或最终正文覆盖。

本轮先冻结v3，再由父会话仅更新两份授权草稿instruction并正常预览。Ulink一轮14.19秒，
已核开头说明币种和占位费缺项，费用/分时逐值一致，未保证全部齐全；另一租户14.16秒，
正文最终核读待父确认。冻结文本不再修改后才推进1.7.3代码PR；草稿预览不等于正式发布或全面业务验收。
