# 128. 节点 SOP 发布为每次运行冻结的执行清单

日期：2026-10-25
状态：已采纳

## 决定

沿用既有 Dify 编辑/发布/试用/撤回/历史恢复入口，以及 agent_versions 与 chat_route_bindings。
部署登记决定某个应用是否交给节点，客户端和模型不能选择节点、租户或供应商凭据。
节点首片只接 chat/completion 编辑器的 SOP 提示词；模型、选项和唯一受控工具来自私有部署模板。
不把任意 Dify Workflow 图转换成 Java 流程，也不宣称模型配置编辑已统一。

发布冻结 SOP 与清单原始字节；版本、路由代次、清单摘要进入本次 run。Java 节点在执行前
以自己的凭据向 Gateway 取得该 run 的清单（无业务数据/模型密钥），核摘要后装配 system 消息。
仍用原有模型/工具守卫逐轮核对，取数与完成通知使用本次清单摘要；正式路由变更、撤回或TTL
失效后拒绝后续领取和交付。试用使用冻结草稿的独立 run，不推进正式指针。

撤回后的已完成节点 QA 与 Dify 路线一致，返回 410 `CHAT_ROUTE_RETRACTED` 且不交付正文；
普通文件绑定删除仍为 404 `CHARGING_STATUS_DISABLED`。复用既有管理行状态查询，仅统一错误说明。

标准映射：清单仍为 m3-exec-config/1，身份仍为原始 UTF-8 字节 SHA-256；Snail-AI 1.1.1
ChatSessionRuntime 在调用线程构建 ChatClient 的既有装配接缝用于绑定每次清单，工具上下文
携带摘要，异步完成闭包保留同一摘要。取数与完成端点不变，新配置端点仅认证目标节点可读。

## 备选方案

- 只更新 Gateway 的期望摘要：节点实际仍读旧 SOP，不能证明发布改变执行，否决。
- 更新一个全局可变节点清单：同进程并发运行会串版本，否决；采用每次执行独立清单。
- 将 Dify Workflow 图翻译成节点流程：会另造编排引擎，本片不实现。
- 从客户端/模型接收 SOP 或模型密钥：绕过发布与权限边界，否决。

## 限制

模型端点/模型/工具仍由部署模板与平台配置共同核对，编辑器这里只编辑 SOP。
撤回阻断业务取数与结果交付；未新增平台取消RPC，不保证已发出的模型请求立即停止计费。
真实 Java 节点已验证；平台、编辑器、模型、CPMS与目录在本片验收中为合成，不是业务验收。
