# 187. 客户端 chatflow 的提示词可以写正文，但数字必须来自本轮快照

日期：2026-10-30
状态：已采纳

## 背景

产品的诉求一直是：**在 Dify 编排页改提示词，就能调整客户端智能体的说话方式**（包括更拟人）。

此前做不到，原因不是提示词不生效，而是**正文被丢掉了**：
`deploy/dify-chat/consumer-service.dsl.yml` 的 `answer` 节点系统提示词第一句是
「仅输出 JSON，恰好两个字段 `kind` 和 `faq_id`」，`consumer_knowledge.final_answer`
也按 `set(selected) == {"kind","faq_id"}` 严格解析。模型写的字只用于**分类**；
用户看到的正文由 `consumer_plain` 按快照渲染。于是"改提示词让回复更拟人"在 C 端
没有任何着力点。

上一片（[ADR-0186](0186-consumer-copy-is-a-published-bundle.md)）把措辞搬成"按租户发布的
文案包"，那解决了"改字"，但**不是**产品要的那个杠杆：它要求人写 JSON、走运维命令，
而不是在编排页改提示词。

## 决策

**给 `answer` 节点开一个写正文的口子：JSON 里可以多带一个 `reply` 字段。**

- 网关只在 `kind=realtime`（本轮有 `live_snapshot`）时接受 `reply`；其它 kind 带 `reply`
  直接拒 —— 没有取数依据的一段话不能冒充知识库回答。
- **不信任模型，只校验三件事**（`consumer_reply.validate_reply`）：
  1. 快照里每个非空金额都必须在正文里出现（数值相等即可，`2.4`／`2.40` 都算）；
  2. 正文里**每一个**数字都必须能在证据里找到出处（快照各字段 + 可核对时间），
     另外放行 0–10 的整数（"第 2 条""3 步"这类计数不构成对金额的断言）；
  3. 不许出现 `cpms.`／`status_code=`／`status_role=`，且必须写出订单号。
- 不合格**整轮失败**，不降级成模板：一份混着假数字的答复比"服务暂时不可用"更糟。
- 不带 `reply` 时行为与之前完全一致 —— 老应用不需要重发，改动不强制任何人跟进。

## 代价（必须写清，这是本片最重要的一段）

**回读的判据弱了一档。** 正文由模型写时，无法从快照逐字重算，所以
`consumer_chat_service.require_result` 对"缓存正文 ≠ 确定性渲染"的情况改成
**用同一套证据校验判它是否仍是这条快照的合法答复**（数字在证据里、无内部标识、订单号在）。
这比"逐字重算"弱：一份**保留了全部数字**的改写会通过。仍然保留的强约束是：
正文必须绑定这条 run、这个订单、这个调用者范围（原有检查一条没动）。

其余代价：

- 每次 realtime 答复多一次模型调用（此前那条路无模型调用），时延与失败面都增加。
- 提示词里的措辞不受代码评审覆盖：文案错字、语气走偏，只能靠读的人发现。
  可执行的那部分（数字、标识、订单号）已由校验兜住。
- `deploy/dify-chat/consumer-service.dsl.yml` 里的提示词是**仓库副本**；线上生效的是
  Dify 里的那一份。改了仓库不等于改了线上，反之亦然 —— 两边要一起改。

## 被否掉的替代形态

- **只把提示词写得更"拟人"，不改契约。** 那正是过去几天做过的事：模型写得再好也被丢掉。
- **让模型输出整段 JSON 里包含 blocks。** 前端只认 blocks-v1，但把渲染形状交给模型等于
  把"用户屏幕上出现什么字节"交给一次随机采样；用 `reply` 一个纯文本字段更小、更好校验。
- **校验里要求"正文与快照逐字一致"。** 那等于禁止模型写字，回到原点。
- **不合格时降级成确定性模板。** 用户会看到一句与他问的问题对不上的话，比明确失败更难排查。

契约见 [acceptance.feature](../acceptance/consumer-model-reply/acceptance.feature)，
执行步骤见 [qa-plan](../acceptance/consumer-model-reply/qa-plan.md)。
`tests/consumer/test_consumer_model_reply.py` 15 条：接受合格正文、拒绝漏金额/编金额/
编时长/内部标识/缺订单号/空/超长、放行小计数、端到端交付与回读、回读拒绝改坏的正文、
无实时数据时不许写正文、老两字段答复不受影响。

**变异验证**：把"每个数字都要有出处"那条去掉，`test_replies_that_break_the_evidence_are_refused`
的两条编造用例变红；把回读的合法性判定改成"直接放行"，篡改用例变红。
