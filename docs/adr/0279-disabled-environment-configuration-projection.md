# 279. 候选配置由草稿投影且不授予准入

状态：已采纳；承接ADR0277/0278，首片只准备候选文件，不安装或激活。

## 决定

管理计划从已保存草稿和固定私有模板生成production.env及schema2环境目录。
公司网关、CPMS、公开入口、执行环境与运行目录路径由草稿/安装档案决定；凭据及本地源仍从模板取得。
候选目录只包含本环境，环境与租户全部停用，管理授权为空；业务执行/聊天配置关闭。
模板禁止重复键、缺值、解析错误、部署身份覆盖和变量插值，保留空值与合法引号/换行。
数据根和进程身份继续归安装器；SQL时区不由业务IANA时区猜测，IANA原值保存在候选manifest供后继核对。

预检公开摘要及分项，不返回秘密/路径；本地受控CLI按同一计划编号导出私有确定性候选包。
导出两次重核授权/草稿/引用、到期拒绝、独占新输出，不覆盖既有文件。HTTP不开放导出路径或安装命令。
目前安装器仅支持单配置事务，候选包明确bootstrap-configuration-only/executable=false，
成套配置安装和实际目标路径核对由后继完成，不能将导出包直接当安装授权或完成回执。

## 替代方案

只比对手工配置与草稿容易复用已有文件，但继续维护两份可以各自改的地址真值。
直接在保存草稿时写生产配置能少一个步骤，却把保存变成上线并让未验证连接影响原用户。
投影时启用草稿里所有租户能立即演示业务，但手填租户不等于真实授权和候选验收。
选择停用候选，后续验证与版本门控激活分开。

## 后果

没有新增目录服务或依赖；python-dotenv既有parser承担格式读取，拒绝`${...}`以避免宿主变量插值。
规范：[python-dotenv文件格式](https://github.com/theskumar/python-dotenv#file-format)；格式不是Shell，
不会执行命令替换。目录遵守已有schema2审计合同，候选revision1不覆盖现役目录版本。
通过仅说明投影规则、文件摘要和已声明配置类型一致，不证明全部设置组合可启动、秘密授权、
任意外部引用完整性、主机/容量/正式网络或业务。生效配置、公司服务和业务数据保持。
