# 0154 — 知识库模型按租户解析，内嵌媒体按资源交付

Status: Accepted

## 背景

图文入库的三条独立事实必须同时成立：解析器读到原文；该租户能解析并调用所需模型；
检索后的图片引用能投影为媒体。实测显示“任务完成”“默认模型名字正确”和
“切片类型是 text”都不能替代这些事实。

## 决策

baoyun 的 OpenAI 兼容端点使用 OpenAI factory；开户同时配置 embedding/chat/vision，
默认模型通过该租户自己的 provider、instance、model ID 设置。运维修复使用原生 API 的
归属校验，不直接把所有 tenant 行指向同一个模型 ID。已有库的 embedding 不批量迁移，
因为历史向量空间需要独立验收。

检索片段携带 image_id 且没有显式 MIME 时，图片提示类型遵循部署版 RAGFlow
`image2id` 的 JPEG 输出；实际响应继续由 MediaProxy 检查字节。父文档扩展名不决定
内嵌图片的类型，显式不支持的 MIME 仍被拒绝。映射 RFC 9110 §8.3：Content-Type
描述当前表示的数据类型，不描述其父容器文件。

## 替代方案

- 给所有租户写同一模型 ID：操作少，但绕过租户归属，运行时拒绝后又静默跳过视觉处理。
- 改用另一 embedding 厂商：可绕开供应商，但当前供应商实测可用，改向量空间会引入重建风险。
- 按 docx/pdf 扩展名拒绝图片：保守但误丢合法的分段图片；图片 ID 已由授权检索返回。
- 仅改 image_context_size 或重启：前者只改变邻近文字，后者不修复模型归属和缺失模型。

## 后果

同名模型可能在多个实例存在，开户必须同时匹配 factory/instance 并检查完整性。
部署补丁绑定原文件摘要，版本升级需要重新核实，不能静默套用。图片没有显式 MIME
时依赖 RAGFlow 编码约定，升级需要复验；字节检查和媒体授权始终保留。

验收要求真实默认模型解析、图片产出、索引终态、检索与媒体下载分别记录。
损坏 Word 关系不能靠模型修复，必须有可证明对应的原图并另存恢复副本。
