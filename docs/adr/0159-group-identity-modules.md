# 身份与范围集中在共享identity包

Status: Accepted

2026-10-29。退役切换验收后按用户要求整理扁平目录，身份规则同时服务C端与管家端。

## 决定

将调用者鉴权、公司令牌/权限、第三会话、范围上下文、查询范围和订单可见性七个模块归入
`aiops_diagnostics.identity`，直接相关测试归`tests/identity`。调用者与验证脚本直接导入新路径，
旧包根不保留兼容转发。仅改变位置和导入，业务AST及既有错误处理保持一致。
`http_auth`仍是独立Dify桥制品的公共头操作依赖，本片不牵动该制品打包。

## 被否掉的替代形态

- 按C端/管家端各建一套身份包：导航直观，但会复制共享范围与权限规则，容易在两端产生不同判定。
- 旧根保留转发模块：可以兼容旧工具，却会保留两套路径；本仓调用者可一次更新，故直接切到新路径。
- 同时移动通用HTTP头和重构节点装配：可以一次收拢更多模块，但扩大服务打包和行为影响面，拆成后续任务。

## 后果

权限实现仍唯一，相关代码和测试可集中找到；原路径的外部工具必须同步导入。
源代码CD需成套替换并核旧模块清除；验收包含本人成功、真实另一主体拒绝和管家个人身份。
目录迁移不代表权限协议重设计，也不宣称历史故障准确率或既有装配循环已经解决。
