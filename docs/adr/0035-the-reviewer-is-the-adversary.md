# 35. 审查者拿到对抗授权：反例，而非顾虑

日期：2026-10-18
状态：已采纳
影响版本：AFK 脚手架模板 1.7.24（`.sandcastle/review-prompt.md` 新增 `## 0.` 一节）；
不改任何运行时代码

## 背景

AFK 的**审查 prompt**（`.sandcastle/review-prompt.md`，由 `planner.ts` 加载）在 1.7.24
之前只要求审查者「读 diff、找可疑处、写测试压它」，**没有说清审查者与实现者的关系**。
本仓的 implementer 与 reviewer 是**同一族模型、跑同一套 prompt**——独立性本来就弱，
而 prompt 没有给审查者任何对抗授权。缺口在这里，不在审查能力上。

同族模板 1.7.23 把这一节写进了 `scaffold/.sandcastle/review-prompt.md`，然后停手了。
那个文件是 bootstrap 的源，所以只到**此后新建**的项目；实测三个已存在的仓
（含本仓）**0 of 3** 收到。这是 ADR 0003 记录的同一形状——规则交付到**作者想到的路径**
而不是**加载它的每条路径**——由 afk-bootstrap 1.7.24 补齐。

## 决策

**本仓的审查 prompt 增加 `## 0. You are the adversary, not the author`，作为审查流程的
第一步（编号流程之前）：**

- 你没写这个改动，你不是来同意它的，你的工作是**让它失败**；
- 产出**具体反例**：让它崩的输入、状态、或序列。**一条 finding 是你跑出来的失败输出，
  不是你持有的顾虑**；
- 真试过之后弄不坏，就说**你试了什么、什么扛住了**——那次尝试本身就是证据；
- **全绿的 suite 不是证据**：这个 diff 里的测试是作者写的，编码的是作者的假设；
  bug 在作者**没考虑到**的那个输入里。先找那个输入。

## 被否掉的替代形态

- **只发给新项目，不补已存在的仓。** 那正是 1.7.23 的样子，也是 ADR 0003 记录的缺陷：
  一条规则只到作者想到的路径。已存在的仓恰恰是**正在跑 AFK** 的那些，缺这条等于
  对抗授权只给尚未开工的项目。

- **用 `cmp` 整文件覆盖下发。** 实测本仓的 `review-prompt.md` 与模板差 **17 行**
  （手工套用的 `uv run pytest` 替换 + 本仓自己的门禁措辞）。`cmp` 守卫会拒绝，
  这一步在本仓静默 no-op。改用**整行锚定**的注入（锚点
  `## 1. Read the diff and look for anything dodgy`，本仓实测**恰好一次**）。

- **同时给 `.sandcastle/review/prompt.md`（两轴之后的修复者）加同一节。** 那是不同的阶段、
  不同的职责——它消费两份轴报告去做修复，不是首轮审查者。scaffold 里它也没有这一节。

- **靠「换模型」取得独立性。** 本机所有 AFK 项目**共用一套模型路由**，做不到。
  所以对抗性只能来自**新上下文 + 这条授权 + 产物必须是具体反例**。

## 后果

- 审查者第一次拿到明确的对抗授权与判据（反例、而非顾虑）。
- **独立性仍然有限，必须说清**：它来自新上下文与这条授权，**不来自模型差异**。
  这条写在这里，免得被读成比实际更强的保证。
- 本决策**只改审查 prompt，不改任何运行时代码**，不影响服务行为；也不改本仓的
  验证命令或测试。
- 代价：审查者可能产出更多「可疑但非缺陷」的条目。缓解是判据本身——要求的是
  **跑出来的失败输出**，不是「这里看起来有风险」。
