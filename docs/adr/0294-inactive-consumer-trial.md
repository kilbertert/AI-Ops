# 294. 客服候选由控制端编排、目标端逐次授权

状态：已采纳；用户于2026-11-20批准124/LTA-CSMS的一次受限只读试运行。接续ADR0291，不放宽普通准入。

## 决定

控制端核对新鲜候选任务、冻结编排与单库归属，继续持有Dify管理凭据、创建和回收临时应用。
目标端只在本机管理HMAC认证后，用真实消费者thirdSession建立最长5分钟的单候选授权。
授权绑定环境、租户、工作区、应用、单库、任务/计划、编排摘要和可选的明确订单；安装/配置指纹变化即失效。
共享控制端通过目标已有HTTPS客服回调逐次核验会话并读取本人订单；公司会话不交给Dify、模型或控制端。
知识仍经控制端既有候选单库连接，逐次复核任务与归属；不写永久customer grant。
完成或取消后关闭目标业务读取，结果在原窗口内仍须重新核权；重启丢失授权、失败不转正式路径。
媒体与正文共用本轮授权生命周期：成功完成后仅在原窗口内读回，取消立即拒绝正文与媒体，
包括取消落库失败或媒体取回期间撤权。无试运行会话的既有候选知识连接合同保持。
网络核权与完成状态回读结束后，再检查本地取消标记及租约，防等待期间的撤权漏到最终交付。
本机CLI显式以回环作为HTTP来源连接本机监听地址；部署监听桥地址时也不扩大入口允许来源。
候选权限来源不可用映射为明确503；候选运行未产生工具证据时拒绝成功交付，不能用模型的缺资料措辞补造取数。
既有Dify回环转发器允许最多32条并发连接。流式回答与反向工具核权共用它时，串行转发造成互相等待；
额度耗尽的新连接立即关闭，已接纳连接继续，结束或异常释放额度。每条连接仍现查容器地址，不缓存权限。
编排摘要仅在本候选通道忽略Dify导出补回的变量自身selector；变量值及其他行为字段严格核对。

RFC6750第5节映射为TLS、随机短期Bearer和禁止URL携密；此令牌不是OAuth登录或JWT。
沿RFC8725第3.12节的互斥验证原则，候选令牌只用于候选回调，不能用于普通问答或旧回调。
临时应用的发布仅为了既有Service API执行，不推进任何正式应用、AI-Ops路由或版本；源候选入口保持停用。

## 替代方案

临时启用整个租户最省代码，但会把普通用户带入未验资源，故拒绝。
把共享Console管理密钥复制到目标可复用原预览，却扩大管理权限和秘密范围，故不采用。
让控制端直接访问目标数据库可减少一次回调，却破坏本环境会话和本人授权，故沿原HTTPS工具入口读取。
增加Console超时不能消除等待循环；另加转发端口或业务隧道会制造第二条连接合同，故在原转发器修复并发。

## 后果

普通准入、正式路由和持久知识授权不变；新增仅内部管理动作和现有回调上的独立候选凭据分支。
必须配套部署控制端与目标端；失联、取消或清理失败如实失败，不能把技术候选试跑当原App/H5或业务准确率验收。
