# 192. 站点代理保留身份和分页字段，证据单独裁剪

日期：2026-11-02
状态：已采纳，随配套节点与 Gateway 交付

真实 Java 经 Gateway 的验证发现：管家代理先构造订单路径便因缺订单号失败；
候选站点响应又缺分页字段；消费者再次领授权会丢失已经读取的证据。
直接返回合成 CPMS 的 Java 验收覆盖不到这些接口之间的差异。

决定：

- 代理返回 `code/data` 信封，分页保留 `records/total/current/size`，行保留已校验的
  `tenantId/id/name/address`。Java 再核租户及站点，生成证据时只取声明字段。
- 两个代理共用站点响应投影；管家越界行拒绝，消费者同租户非本人站点过滤，规则不合并。
- 授权 `site_ids`：数组表示明确集合，`[]` 表示零站点，`null` 仅表示已经 Gateway
  核实的全租户管家范围。缺字段仍拒绝；不能用空数组同时代表无范围和全范围。
- 身份判据跟随工具声明的用途，订单工具仍必须有订单号；不能用缺订单号放宽订单校验。
- 消费者相同工具、参数及范围的再次授权保留已读证据；范围变化换授权，旧凭据失效。
- 参数与答复关键词可忽略空白和大小写作连续匹配，查询值取用户原文以保留地名空格；
  不接受重排或跨片段拼造地址。回调路径从同一声明生成完整正则，不允许任意可选尾段。

JSON 的数组与 `null` 是不同值，依据 [RFC 8259 §3](https://www.rfc-editor.org/rfc/rfc8259#section-3)；
这里的业务映射沿用现有 `SiteScope` 的 `None/()/集合`，不是 RFC 规定的授权语义。
旧节点不接受 `null`，因此全租户场景必须配套升级；不把这份授权向任意旧节点降级。

验证为真实 Java 授权→Gateway 代理→合成 CPMS→Java 证据→Gateway 接收，另有真实 TLS
回调白名单测试。没有增加公网出口或通用代理。部署与恢复同时考虑 Gateway、节点、回调配置。
