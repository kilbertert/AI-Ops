# 发布权由公司权限码裁定，发布审计按人记账

日期：2026-10-14
状态：已采纳
影响版本：PRD #772 D（子票 #780）；`publish_audit_ledger`、`AIOPS_CONSOLE_BRIDGE_LOGIN_PROXY_URL`

## 背景

「发布到 AI-Ops」这一跳原来按**Dify 自己的** owner/admin 角色放行。那是"谁在这个 Dify
工作区里是管理员"，不是"公司认可谁把东西发上生产"：它不随公司人事变动而变，发布记录里
也看不出是**哪个人**发的。PRD #772 D 要求把放行判据换成公司权限码，并补一份按人的审计。

到本票为止，公司身份闭环（#778 登录代理）已经落地，映射表里有"公司用户 ↔ Dify 账号
↔ 最近一次登录的权限码"。缺的是把它接到发布那一跳上。

## 决定

**两层，各管一件事：授权放行的**判据**换掉，审计的**记录**补上。**

### 1. 桥：配了映射来源 ⇒ 公司权限码裁定；没配 ⇒ 过渡行为不变

发布桥（`dify_console_publish.py`）新增 `AIOPS_CONSOLE_BRIDGE_LOGIN_PROXY_URL`，
三态都有明确语义：

* **留空**：维持现状（固定工作区内的 owner/admin）。**身份闭环上线前就是这个状态** ——
  PRD 明确要求"过渡：不提前切换"。
* **配了**：放行判据改为「登录代理说这个 Dify 会话对应的公司用户持有发布权限码」。
  于是"谁能发"由公司体系一处决定。
* **配了但代理不可达**：**拒绝**（fail-closed）。**不退回 owner/admin** —— 那会把
  "核对不通"悄悄变成"按旧规则放行"，而这两件事的后果完全不同。

### 2. 登录代理：一个只回答"能不能发布"的只读端点

`POST /__aiops/publish/check`：验**我们自己签的**会话 → 按 Dify 账号反查映射 →
答 `{allowed, reason, company_user_id, company_username, dify_account_id}`。

**只回布尔与发起人，不回权限码全集。** 桥需要的是"能不能发布"；把运营的权限码清单
交出去只是扩大泄漏面，而没有任何用处。

### 3. 网关：发布审计账本，成功与被拒都记

`publish_audit_ledger` 是**追加写**的表：一行一次发布**尝试**。

* 成功：`published`（内容变了）/ `unchanged`（点了但内容没变）。两者**必须可分辨** ——
  否则"某人点了一百次但什么都没发"与"发了 0 次"在账本上看起来一样。
* 被拒：未绑定 404、上游拒绝 502、发布门 409。**被拒的尝试也记** —— "谁试过把什么
  发上去"正是审计要回答的问题之一。未绑定的 `app_id` 没有任何租户可归，租户留空而不编一个。
* 发起人走**请求头**（`X-AIOps-Initiator` / `-Name` / `X-AIOps-Dify-Account`），
  **不进请求体** —— 请求体仍然只准一个 `app_id`（`extra="forbid"`），所以这次改动
  没有放宽爆炸半径。有测试直接断言发起人字段进不了请求体。

## 发起人字段**不是**授权依据

授权在**桥**那一侧已经完成（公司发布权限码）。网关收到的"发起人"是审计元数据：

* 缺失 ⇒ **照常发布**，审计里记成未知；
* 伪造 ⇒ 只会改变账本**记录**成谁，不会改变**能不能发布**；
* 写账本 best-effort ⇒ 磁盘问题不挡发布。

这条分开是刻意的：把审计字段读成授权字段，会让"加一个头"变成一次提权。

## 被否掉的替代形态

* **让桥直读登录代理的映射数据库。** 那要求两个服务共享一个 SQLite 文件（权限/身份边界
  消失），而"验会话"这一步本来就只有持 `SECRET_KEY` 的代理能做。用一个只读端点把
  **判据**问出来，比共享存储小得多。
* **代理不回发起人，让桥自己填。** 桥手上只有 Dify 会话，反查映射要的就是代理的库；
  而"谁签的会话"这件事只有代理知道。
* **把发起人放进请求体。** 一次 `extra="forbid"` 的服务器端约定就该维持：请求体能自报
  的东西越多，"以任意租户发布任意正文"的口子越宽。
* **未配映射来源时也 fail-closed。** 那会让身份闭环上线前**所有**发布停摆 —— 与 PRD
  的过渡要求相反。未配 = 明确选择旧规则；配了但查不通 = 不能确认，两者不同。

## 后果

* 身份闭环上线（#783）时，把 `AIOPS_CONSOLE_BRIDGE_LOGIN_PROXY_URL` 一填即切换；
  回滚就是把它清空。
* 运营看到的拒绝从"Dify 角色不够"变成"公司账号没有发布权限，请联系公司管理员" ——
  指向的是**该找谁**。
* 审计能回答"谁在何时把哪一版发上了生产"，含**被拒**的尝试；这是 ADR-0021 留下的
  "个人级审计"债的落地。
* 权限码快照来自**最近一次登录**，不是实时读取：代理无法在操作者本人未登录时去公司问
  他的权限（#779 已把"失权 ⇒ 下次登录即封禁"那个窗口定死，会话寿命是它的上界）。
