# 224. 证据 data 比对只认出处：派生形状字段移出逐字核验

日期：2026-11-05。

Status: Accepted（PRD #1380 第三步 #1382 合同清单 C1/C10，用户确认方案后实施）。

`record` 的 live 路径把节点上报的 `evidence.data` 与网关代理取数时投影的
`expected["data"]` 做**整体深相等**。`data` 里混着两类东西：上游原值
（`records` 行、`total`、订单字段——出处核对本身）与**派生形状字段**
（`truncated`/`samples_returned`/`sample_limit`/`absence`/
`ordering_guaranteed`/`complete_timeline`——网关投影时一处算定的注解）。

派生字段的问题不是措辞，是**双实现**：同一公式网关算一份、Java 节点
按 `OPERATOR_OUTPUT` 合同重算一份（`CpmsToolAcceptance` 实测该侧按
`total > rows.size()` 逐字重建）。站点计数有三个口径——上游 total、
关键词过滤后行数、展示上限——任何一边的分母漂移，比对都必然不等，
每一次真实运行以 `OPERATOR_EVIDENCE_MISMATCH` 失败。这正是「确定到
可以逐字核验的事实被交给两份实现各自生成」的死锁形状。

而且节点回报的 `data` 比对完即弃：快照存的是 `task.evidence`（网关
自己投影的那份），深相等保护不了任何东西，只制造拒绝面。

决定：比对收敛到出处。`_provenance(data)` 剥掉派生形状字段后做深相等，
原始行与上游原值仍逐字核验——节点谎报取数内容仍被同一道闸拒。派生
字段回报与否、回报成什么值都不影响判定，网关投影照常进快照。

节点侧不必改：`OPERATOR_OUTPUT` 仍可要求节点重建派生字段（无害），
但网关不再依赖它的公式；Java 后续可简化成回显，属它的仓、它的节奏。

## 备选方案

- 把派生字段放进代理响应让节点回显：一处实现、逐字保留，但要么改
  Java（节点重发版），要么容忍响应形状双写——比网关单边收口更重，否决。
- 仅对站点/样本工具收窄，其余工具照旧：按工具白名单是多一张表；
  派生字段集合在所有工具的 `data` 里互不相交，全局剥除一次到位，否决。
- 完全去掉 `data` 比对只查形状：`records`/`total` 是出处证明——
  节点报的数字必须就是它从授权代理拿到的数字，去掉比对等于放弃
  「没撒谎」这条保证，否决。
