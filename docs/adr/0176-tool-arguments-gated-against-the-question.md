# 176. 工具可以有参数，但参数由网关对照提问原文放行

日期：2026-10-30
状态：已采纳（设计定型，尚未实施）

## 决定

工具可以声明参数。**模型提议的参数值，只有在网关侧被证明是用户提问的字面子串时才被放行。**

判据直接沿用 ADR-0165 已经在用的那一组（`operator_conversation.validate`）：

- 每个参数值长度 1–80，去掉空白后非空；
- `casefold()` 后必须是 `run.question` 的 `casefold()` 子串；
- 不含 `%`、`_`、`\`、`\r`、`\n`（这些字符在 URL 编码与日志里各有含义，一律不接受）。

范围、租户、站点集合、分页上限、请求路径**仍然全部由网关决定**，参数只能影响过滤器。

同时：`node_publication.py:205-210` 现在强制 `input_schema` 必须为空对象，这条要改成
「`input_schema` 的参数集必须恰好等于声明里登记的那几个」——**不是取消校验，是把校验对象
从「必须为空」换成「必须是声明集合」**。

## 依据

零参数是整个工具边的基石：`ControlledChargingStatusTool` 的注释写着「模型不能提交订单号、
租户、用户、URL、agentId 或 run_id」，`CpmsReadTool` 对任何非空参数直接
`refused("arguments_forbidden")`。这个边界很好用，它的代价是**工具只能做无需参数的事**。

站点搜索需要关键词。而关键词不能由网关自己产生：

- 网关从自然语言里用正则提取地址，做不到——中文地址没有可枚举的边界，
  ADR-0165 之所以把提取交给模型，正是因为这个；
- 关键词也不能由用户在前端表单里先选好——那已经不属于「自然语言问答」这个入口了。

所以真正的选择不是「给不给参数」，而是「参数由谁产生、由谁放行」。ADR-0165 的答案
——模型产生、网关对照原文放行——对模型输出的结构化字段已经跑通，把它扩展到工具参数，
是复用一条已被验证的判据，而不是新开一条。

## 被否掉的替代形态

**保持零参数，关键词在签发时由网关固定进 run。** 最强的地方是它完全不打破现役的边：
参数面为零，`input_schema` 校验不用改，`CpmsReadTool` 的 `arguments_forbidden` 不用动，
一句话就能说清安全性质。它输在两件事：一是网关必须自己从提问里解析关键词，等于把
ADR-0165 明确交给模型的那一步搬回正则，而它当初被交出去的理由（模型理解自然语言、
网关不理解）并没有变；二是模型无法追问细化——用户说「太远了，再近一点」时，run 已经签发，
关键词已经固定，这一轮只能重来。

**模型给任意参数，网关不校验。** 最强的地方是简单：把 `input_schema` 放开就完事，
模型想传什么传什么。它输在「模型能选的就不是授权」这条线上——ADR-0091 与契约 §3.4 的边界是：业务输入只能来自网关的授权记录，不能来自模型参数。
放行不加判据，等于把这条边界换掉而不承认。

**工具参数只允许枚举值**（例如分页序号、站点 ID 白名单）。最强的地方是可穷举校验：
合法集合有限，越界即拒，不需要任何文本判据。它输在站点搜索的核心参数是自由文本地址词，
枚举不成立；而给模型一个站点 ID 列表让它选，等于先把它允许看见的全部站点交出去。

## 后果与验证

- 新增一条可测边界：**参数必须是提问原文的子串**。它对「模型自己编一个地址词」和
  「模型把上一个用户的地址复用过来」两种情形分别变红。
- 多轮连续调用的组合面**未验证**。ADR-0165 的判据在「每轮一条输出、`name` + 至多 4 个
  地址词」的形状下成立；工具化之后模型可以在同一轮里连续调用、每轮换一个词，每轮都合法
  但合起来超出用户提问的范围。这是 P3 落地前必须单独设计并验证的一点，不能因为单轮判据
  成立就认为整体成立。
- `input_schema` 的校验对象改变，`node_publication` 与 `ops_provider` 的 openapi 生成
  都要同步；两侧推出来的参数集必须逐项相同，否则就是一个「Dify 显示一个参数、节点要求
  另一个参数」的漂移。
- 参数值进入 CPMS 查询参数时要按 RFC3986 编码（ADR-0165 已定），且 `name`/`address`
  在 `GET /chSite/page` 上的过滤器语义由公司侧定义，不由本决定改变。

方案与分期见 [工具架构](../agents/operator-cpms/tool-architecture.md)。
