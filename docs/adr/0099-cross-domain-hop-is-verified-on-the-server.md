# 99. 跨域一跳的验收看服务端，不看浏览器

日期：2026-10-23
状态：Accepted
影响版本：`.claude/skills/verify-aiops-gateway/scripts/observe_knowledge_open_closed_loop.py`（新）、
`ops/dify-console-bridge/dify-console-publish.conf`（注释更正）

## 背景

「Dify 知识库入口 → RAGFlow」是一条**跨域**链路：`dify.ranlei.work` 上的桥回 303，指向
`kb.mall.qushiyun.com` 上的一次性票兑换端点，兑换再 303 到 RAGFlow 并种下会话 cookie。

它一直用浏览器验收。2026-10-23 一天里，浏览器判据**连续误判两次**：

| 看到的 | 实际 |
|---|---|
| 新标签 `tab.url` 是空串 | 303 指向另一个域，跨域后读不到 URL。被读成"没跳转" |
| `fetch` 该 URL 回 401 | 顶层导航回 303。`fetch` 与顶层导航的凭据行为**不同** |
| 新标签停在 `about:blank` | 窗口确实在导航（303 → 跨域），只是脚本拿不到结果 |

三次的形态不同，根因是同一个：**判据依赖了"浏览器肯把跨域过程中的状态告诉我"，而那条路
本来就不保证。**

更糟的是它**误导排查方向**：第一次误判后我去"修"一个没坏的跳转，在 `about:blank` 上耗了
很久；桥日志那时已经写着 `303 + target=https://kb.mall…/hop?ticket=…`。

## 决策

**这条链的验收判据放在服务端，在 HTTP 层跟完整一跳。**

```
① 桥：无会话                          → 401
② 桥：有会话                          → 303，Location 指向 …/knowledge/hop?ticket=…
③ 兑换：真票                          → 303 + Set-Cookie 落在目标域
④ Set-Cookie 的域与跳转目标同域        → ADR-0093 的那条决定
⑤ 兑换：同一张票第二次                 → 404/410（一次性）
⑥ 兑换：假票                          → 404/410（可区分的拒绝，不是 5xx）
```

这六条与"用户点一下"**等价**：用户能进 RAGFlow，当且仅当②给了票、③把票换成会话。

**浏览器不再是判据，只是可达性的旁证。** 需要浏览器时，判"用户能不能点得到、点得到之后
有没有反应"，不判"跳转有没有成功"。

## 这条判据自己的两个坑（写在脚本注释里）

做这个判据的时候，脚本本身也差点给出错误答案：

1. **`urllib` 默认跟随 30x。** 第一版把 303 读成了 200 判失败 —— 而 303 **本身就是**要验的
   东西。必须 `redirect_request → None`。
2. **`dict(response.headers)` 丢重复键。** `Set-Cookie` 恰恰可能多值，而它正是③的判据。
   改成按小写键分组、多值拼接。

**一个判据的实现细节就能让它反着说。** 这两条不写下来，下一个人改这个脚本时会再踩。

## 被否掉的替代形态

- **继续用浏览器，但改用 `response` 事件抓 303。** 能做，但那就等于在浏览器里重建一遍
  HTTP 客户端；而且 `response` 事件对**重定向链**的可观测性本身也因浏览器而异。
  直接用 HTTP 客户端更短、更确定。

- **在浏览器里读 `window.location` 判断跳转。** 跨域之后 `window.location` 是受保护的，
  读不到 —— 这正是误判的来源。

- **只验桥（②）不验兑换（③）。** 桥给了票但兑换坏掉时，用户仍然进不去。③才是
  "会话真的落在目标域上"的那一步，ADR-0093 的全部意义在那里。

## 后果

更容易：这条链坏了，一次脚本运行就能指出是哪一段（桥 / 兑换 / 一次性 / 假票），
不用再靠"我点了，看起来没反应"。

更难：**脚本需要一份只读的会话 cookie 文件**才能跑全六条。这是必然的 —— ②要一个验过的
会话，而它只能来自真实登录。没有它时脚本只跑①（无凭据 401），并在输出里明说跑了哪几条。

上限：判的是**服务端承诺**（303 + Set-Cookie），不是"RAGFlow 页面渲染成功"。后者仍要在
浏览器里看一眼 —— 但它已经是一个**很短的、不跨域的**判断了。
