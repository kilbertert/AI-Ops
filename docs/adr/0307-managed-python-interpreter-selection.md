# 307. 受管解释器枚举覆盖/usr/local既有root维护安装

状态：已采纳；修复通用安装的兼容缺陷，不改业务架构。目标主机的系统默认python3可能是平台旧版（实测3.6），
而/root维护的/usr/local已装3.13；原合同只白名单`/usr/bin/python3[.11–.13]`并由task.py与发布worker固定`/usr/bin/python3`，
导致符合应用包小版本的解释器在场仍被拒绝。不允许手建`/usr/bin`符号链接或改公司系统Python绕过。

## 决定

解释器合同保持为「受管root拥有、组/他人不可写的已安装Python3.11–3.13，且与应用包小版本严格匹配」，
候选位置由`/usr/bin`扩到`/usr/bin`与`/usr/local/bin`两个受管bin目录下的`python3[.11|.12|.13]`。
固定包probe.py自举枚举：符号链接解析后的目标须是普通文件、root拥有、不可由组/他人改写且可执行，
全部父目录同此要求；带小版本名与实际小版本不一致拒绝，裸`python3`接受任一受支持小版本。
选择返回的是已核验的解析后绝对目标，小版本探测、venv创建与下游执行只经过它，候选链路上的
可写中间目录或链接跳在核验后无法再重定向执行，也无须逐hop核中间链接归属。
选择顺序为`/usr/bin`先于`/usr/local/bin`、裸`python3`先于带小版本名，重复指向同一目标的链接自然去重，
原Ubuntu `/usr/bin/python3`条件与结果不变。

`install.py --python`仍显式给路径但按同一枚举校验，不接受任意可执行路径；
`task.py`执行按现役账本小版本自动选择并把选中解释器传到venv与`apply`复核，`apply`不因上游已选而省略校验。
远端驱动脚本解开固定包后`import probe`由包内`managed_python`选出`install.py`/`task.py`的运行解释器，
不再在worker中硬编码`/usr/bin/python3`；驱动脚本本身只依赖PATH可解析的`python3`且语法回退到3.6可执行。
`recover`/`preflight`/`register-runtime`/发布事务继续沿账本venv绝对路径，不新增解释器决策点。
probe.py内部nsenter轻量HTTP脚本保留`/usr/bin/python3`，其语法在平台旧版上可执行，不属本合同选择面。

## 替代方案

在`/usr/bin`补符号链接或改公司系统Python：绕过的是平台的根维护边界，把兼容成本转嫁给不属本片的系统配置。
只放宽apply的正则而task.py/worker仍固定旧路径：选中解释器传不到底，95实测仍会失败，是本片明确排除的形状。
把候选目录做成任务或表单可配：普通提交即可指定任意可执行路径，失去「受管已安装」这一安全边界。
远端驱动继续用`sys.executable`：与已自举的`python3 -`同一解释器可行但无法核受管归属，
由固定包内枚举把解释器信任决定收敛到与venv选择同一处。
`managed_python`按次优先裸名：是既有Ubuntu默认行为的延续，不是新偏好；带小版本名仅作其后的候选。

## 后果

系统默认3.6但/usr/local有受管3.13的主机（95实测形状）可按同一合同完成候选安装、登记与发布，
解释器选择与校验只存在于固定包probe.py，worker/CLI/probe三入口共用，无平台专属分支。
用户可写、非root拥有、父目录可改写或小版本不符的路径在apply与枚举两层都被拒绝；
选择失败按原合同分类为安装前拒绝，不落入安装事务。
安装器与远端驱动脚本同一合并修订出包，旧目标主机行为不变；本决定不回溯解释器对95现场既有实例。
