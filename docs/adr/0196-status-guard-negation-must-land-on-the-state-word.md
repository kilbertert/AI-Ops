# 196. 状态判据要求否定词落在状态词上，不是同子句共现

日期：2026-11-03
状态：已采纳（线上故障驱动；部署后验收待执行）

## 问题

管家订单诊断在 41 上**时好时坏**。同一张单（`2116050516255272961`）72 次运行里 53 次失败，
用户看到 `诊断失败：OPERATOR_DIAGNOSIS_FAILED`。日志里最集中的一条是
`operator_answer_rejected reason=unsupported_fact detail=status line=3`。

## 根因

`consumer_facts.check_status_prose` 的否定分支判的是**同子句共现**：
否定词（未/没有/无法/不…）与状态词（充电/供电/结束/完成/异常…）出现在同一子句即拒绝。

而管家提示词明确要求：*「监测0条必须明确缺证，不能推断无故障」*。模型照写，得到的是：

| 模型写的句子 | 共现判据看到的 | 实际语义 |
|---|---|---|
| 我这边暂**未**取到本次**充电**的过程样本 | 未 + 充电 | 否定「取到」，不是否定订单状态 |
| 本次**没有**取到**充电**过程明细 | 没有 + 充电 | 同上 |
| 我**无法**仅凭现有记录判断费用是否**异常** | 无 + 异常 | 否定「能判断」，不是断言异常 |

**两端规格互相矛盾**：提示词要求写缺证，判据一看到缺证里的「未/没有/无法 + 状态词」就整轮拒绝。
用户观察到的「不稳定」是概率现象 —— 模型每次措辞不同，撞上这条判据约四成。

## 证据

按失败 run 的 `execution_manifest` 在节点同款模型出口上重放 10 次真实调用：

- 修复前 **4/10 被拒**，拒的全是上表那种缺证句子；
- 日志里该形态的字号（`len=53/57/63/65/81/90/94/96/99/100/101/102/148/155`）与重放一致。

## 决策

否定词后面（允许状语）**紧跟**状态词才算改写状态：

- `订单还没结束` / `未充电完成` / `尚未完结` —— 仍然拒绝（真状态改写）；
- `未取到…过程样品` / `没有取到…明细` / `无法判断…是否异常` —— 放行（缺证说明）。

对照组各写一组测试，防止修法退化成「把判据放松到什么都不拦」。

## 被否掉的替代

- **在提示词里禁止这类措辞**：等于禁止写缺证，与「监测0条必须明确缺证」直接冲突。
  提示词改不了判据与提示词打架这件事。
- **只在管家侧换一套判据**：`check_status_prose` 是消费者与管家共用的一份（ADR-0098 起），
  分出第二份就是让两个入口对同一句话给出相反结论 —— 这正是本仓反复记录的那种漂移。
- **删掉否定分支只留断言形式**：`订单没有结束` 会漏放，而它是最典型的改写状态。

## 复审订正（同一 PR 内）

第一版只允许**状语**夹在否定词与状态词之间，漏放了 `订单没有在充电`、
`订单尚未开始充电` 这类句子（它们在改动前是被拒的）。修法：允许集补得体貌标记
（在/正在/开始/继续/处于），但**不收实义动词** —— 「未**取到**充电样本」的「取到」
正是要放行的那一类，两者的区别是「否定落在体貌上」还是「否定落在动作上」。
这批句子已写进对照组测试。

## 代价

否定词与状态词之间若有长状语（`尚未全部核对完成`），仍可能被误拒。这条判据本来就是
维护中的词汇表，不是对自然语言的穷举；本轮把它的**误拒面**从「任何提及缺证的句子」
收窄到「否定紧贴状态词」，没有声称零误拒。

## 顺带补的取证缺口

`json_parse json_syntax` 此前只记形态，分不出「上游 max_tokens 截断」与「模型自己拼错」。
现在多记 `len=` 与 `closed=`（是否以 `}` 收尾）：截断的形状是长度贴着上限且不闭合。
仍然不记原文 —— 回答是用户可见文本，可能带单号与金额。
