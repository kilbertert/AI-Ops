# 276. 控制台路由使用活动登录绑定的环境

Status: accepted（实施已批准手工环境开通规划§6）

共享登录进程按环境构造现有LoginService，各自独立映射数据根；保留默认环境原数据根。
凭据文件只提供环境ID与秘密，名称/公司网关/Gateway来自权威环境目录。地址在启动时冻结，
停用逐请求生效，改址拒绝并要求重新配置；不把任意请求URL转成受信连接。
验证码randomStr在内存绑定环境、5分钟过期、提交即消费；多环境模式必须先获取验证码。
活动会话归属由现有各LoginService会话哈希账本解析，不新增另一个持久会话/租户目录。

发布检查在既有身份响应中补环境与固定Gateway；管理桥验证活动会话后按环境取自己的服务凭据，
对发布/预览/管理/知识入口统一选择本次请求的设置。浏览器环境字段仅参与首次登录选择，不能改变已登录调用的目标。
每环境operator-token交换凭据独立，不能用A的服务key换B的用户令牌；退出撤销本地活动绑定。
重启仍要求正常重登，沿用ADR0268；旧单环境配置不改变协议前置或数据位置。

替代方案：每环境复制一个浏览器域名/控制台运维面过多；按浏览器cookie或环境头直接选业务上游不能证明登录来源；
让共享JWT逐个环境验签/user-info会把同号用户当同一人。选用既有登录服务实例＋活动绑定，保持权限检查在原模块。
应用资源准备和目录激活仍分步执行，未配套环境不在登录选项中；不宣称本片完成一键开通。

规格依据：[RFC8725 §3.8–3.12](https://www.rfc-editor.org/rfc/rfc8725.html#section-3.8)的身份/受众互斥验证，
映射为同号主体在不同环境不能复用活动绑定；不更改Dify JWT格式或公司接口。

知识导航保留cookie-only合同（新标签可无Referer），知识同步保留同源POST+cookie合同；管理写请求仍要求完整CSRF双提交。验证码申请在原有锁内限制每来源最多30个未消费占位，全局4096/5分钟过期，上游失败释放占位；不再增加一份限流状态。

登录已切多环境而桥仍单环境时，桥检查活动身份响应并拒绝，不能落回默认Gateway。代理不可达时也无法确认环境，HTTP入口拒绝；这是对旧试运行故障回落的有意收紧。

静态桥同样拒绝代理报告的无活动身份，防止已退出的跨环境会话落入旧试运行调试回退。
