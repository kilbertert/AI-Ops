# 240. 执行进度与业务结果分别记录

Status: Accepted

用户批准三个反馈按方案实施。运行进度与后续日志页共享有界元数据，存入既有运行账本的独立列；
结果快照仍由原授权与事实复核路径交付，进度不能证明业务成功。时间戳遵循RFC3339，
耗时以单调时钟计量并在终态冻结；轮询发现运行期限已到时展示过期。

## 被否掉的替代形态

- 将阶段放入业务快照：无需新增列，但证据和最终回答覆盖快照，会丢失前面的阶段。
- 仅写进程日志：实现少，但无法稳定关联页面请求，进程退出后页面也无法回读。
- 未复核回答先流式交付：能更早看到文字，但会改变既有结果交付承诺；采用独立进度显示项。
- 延长超时：能让更多长请求完成，却不能解释阶段、减少不必要取证或消除重复执行。

## 后果

每次运行最多128条阶段记录，不含原始参数、模型输入、令牌和业务证据。
普通查单默认简短按需取证；明确诊断仍可按SOP选择工具。此策略需要正常发布才作用于已发布应用。
观测写入故障只记一次告警并停止该轮后续观测写入，不阻断业务收尾，因此阶段缺失不能解释成没有执行。
保留模型与事实复核，阶段可观测不等于延迟已达标；真实入口需要另做前后对照。
