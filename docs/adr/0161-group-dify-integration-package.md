# Dify集成归包与独立服务入口成套交付

Status: Accepted

2026-10-29。Dify协议适配、工作空间、登录和发布模块集中到dify包；模板资源同迁。

## 决定

25个模块直接使用新导入路径，旧包根不保留转发。Gateway走原CD；独立发布桥和登录代理各用
自己的完整部署包。发布桥安装同时修改现役ExecStart模块段，备份/恢复代码与单元，保留原身份和环境。
登录代理升级手册要求相同配套动作，并明确重启使近期令牌映射失效，须正常重登。

## 被否掉的替代形态

- 保留旧入口模块转发：方便旧单元，但形成长期双路径；本仓可成套更新制品和单元。
- 将独立服务合到Gateway：可减少发布包，却改变进程、权限和部署边界，超出目录迁移。
- 只改Python导入而不改资源/服务单元：本地导入能过，独立宿主下一次部署会启动失败。

## 后果

集成代码集中可导航；模板、打包与单元必须同一修订交付。旧生产服务保持原完整包，
不因Gateway新包部署而假称独立服务已升级；本片不改协议、凭据或业务数据。
