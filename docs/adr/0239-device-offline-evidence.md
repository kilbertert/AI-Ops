# 239. 设备离线分析共用受控事实与确定性计算

Status: Accepted

2026-11-10用户确认：第一阶段三项为智能客服、异常订单分析、设备离线分析。
离线分析扩展原offline卡并供原管家Agent调用；模型按SOP选择范围和解释，程序授权、取数、计算。

同一只读快照冻结as_of，DATETIME由明确配置时区解释，输出RFC3339时间。
窗口[start,end)纳入窗前持续离线，按设备归并重叠区间；当前未恢复清单独立于历史窗口。
订单按2/3/5分组且唯一去重，缺终点不能补成0，重叠只表示相关性。旧offline字段不静默改义。
依据RFC3339 §5.6与MySQL InnoDB一致性读；多个连接不声称同一快照。

## 备选方案

- 只加统计SQL：最少接线，但原管家Agent没有离线工具，无法自然询问与追问，故补同一工具入口。
- 新建离线专用模型/平台：可独立演进，但复制当前SOP循环/权限/作业，故复用既有实现。
- 仅按状态5关联：兼容旧失败率卡，却漏掉离线处理产生的2/3；新口径分组，旧指标不改。
- 缺租户或结束时间时猜测补全：结果更多，但越权与伪造确定性不可接受；缺证明确返回。

有界读取超过上限时拒绝给出全量统计，来源缺失不当零。平台事件时间不是物理断网瞬间；
未记录恢复也不等于即时在线探测。历史中被引用设备/订单必须重新校验当前归属。

现役事件表仅device_code索引，先限定当前授权设备再取记录；历史编码漂移/已删除设备可能缺证，
明确范围与覆盖状态。新子结果不改旧摘要；历史依赖私有存储，模型仅收到实际展示的证据。
