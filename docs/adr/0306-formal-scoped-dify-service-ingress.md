# 306. 将既有受限Dify HTTPS登记为第二环境正式服务API入口

Status: Accepted（用户2026-11-22明确批准；只更新用途与记录，不重启或激活目标）

## 决定

第二环境原共享Dify HTTPS仍间歇握手重置；既有受限备用入口有认证与流式证据。
将该同域名、已分配端口的入口登记为该环境正式服务API入口，替代
[ADR0266](0266-temporary-shared-dify-https.md)对它的48小时临时生命周期；原传输与授权边界不变。
不新增端口、域名、隧道、代理进程或公司改码，不改变已登记精确来源、固定API路径、
主机名/证书验证及应用Bearer鉴权，不开放控制台/内部管理。

本次不修改目标配置或重启：目标正式客服配置尚未启用，后续须沿中央唯一配置引用CAS及原安装器事务应用。
入口获准不等于租户可用，真实身份、本人订单、双向工具、负载容量与发布准入仍分别验收。
原默认入口保留并继续排障；故障归属尚未确定，不将一次错误SNI重置推导为某运营商全面阻断。

## 被否掉的替代形态

- 等原默认入口修复：不增加任何接入面，但已有反复重置且无修复窗口，会持续阻塞已可运行的受限路径。
- 不断续48小时：沿用临时恢复最容易，却让实际长期依赖无稳定运营身份；本次通过明确批准消除这种漂移。
- 专属SSH业务隧道或另一通用代理：可绕开路径问题，但违背模块接入方向并扩大运维/鉴权面，仍不采用。

## 运维与恢复

AI-Ops入口负责人维护既有来源、TLS和路径范围；按原监控及使用情况观察，不新建轮询服务或自动到期关停。
来源/证书/依赖变化及启用新业务环境前重验受影响链路；原默认入口修复后先验证，再另行决定迁流量和退休。
撤回本决定恢复临时治理需明确记录，不删除在用入口；真正关闭前仍须观察流量、准备替代路径和回退。
额外端口是该正式接入的运营成本，目标网络策略或出口IP变化时须重新核对；不因此关闭TLS或扩大来源范围。
