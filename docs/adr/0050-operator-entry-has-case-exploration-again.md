# 管家端恢复「客户案例」动作：**入口面**与**能否出卡**是两件事

日期：2026-10-19
状态：已采纳（**对 ADR-0031 的显式反转**）
影响版本：`shortcut_lifecycle._BUNDLED_SHORTCUTS["operator"]`、`docs/agents/frontend-operator-handoff.md`、
`docs/agents/env-41-runbook.md` §3.1-ter；恢复 #427 的交付面

## 背景

ADR-0031（2026-10-16，#803）把 `case_exploration` 从 `operator` 种子里删掉了。
它记的**机制**是对的，今天依然成立：

- 平台行不允许携带 `target_agent_version` —— `_validated_fields` 对 `PLATFORM_SCOPE`
  抛 `platform shortcuts cannot bind a tenant agent version`；
- 而 41 上 `operator` 侧当时**只有平台行**；
- ⇒ `_promo_route` 在该入口解析不出宣传智能体 ⇒ 每次点击都是一张
  「客户案例服务暂时不可用」的空卡。

用户于 2026-10-19 判断这个决定下得不应该，要求恢复。

## 决定

**把 `case_exploration` 加回 `operator` 种子**，并按**两层数据**让它真的能出卡：
**平台行给可见性 + 租户行给绑定**。

反转的不是机制，是从机制推出的**结论**。ADR-0031 从「平台行绑不了 target」
推到了「这个入口不该有这张卡」；实际只有前一句成立 —— 后一句把
**绑定位置的限制**读成了**入口能力的限制**。

同一份代码里就摆着反例：`consumer` 侧今天跑着的正是这条路。
41 实测（本次只读复核）：

```
__platform__ / consumer / case_exploration   published  target=NULL
1942105476598861824 / consumer / case_exploration  published  target=agt_ed443cae…#v2
1942105476598861824 / operator / case_exploration  published  target=NULL   ← 只有平台行
```

`list_effective` 的合并规则是「已发布的租户行覆盖同 code 的平台行」——
**平台行给可见性、租户行给绑定**是这个表设计里的常规形状，不是补丁。
`consumer` 从来就是平台行 + 租户行两条一起用的。

## 被否掉的替代形态

- **（a）只恢复种子，不建租户行。** 技术上是本次改动的全部代码面，也可以独立发布；
  但用户看到的是**按钮回来了、点下去还是那句「暂时不可用」** —— 恢复了一个
  没有效果的入口，比不恢复更容易被误读成"已经修好了"。否掉：两件事一起做。
- **（b）只把 41 上那行 `disable` 撤销（`enable`），不改种子。**
  否掉的理由与 ADR-0031 否掉自己的 (c) 完全对称：**种子决定将来，数据行决定现在**。
  只翻数据行，每个新租户仍会缺这一行（虽然本轮 `seed_bundled` 在启动路径上没有调用方，
  但那是当前事实，不是可依赖的契约）。
- **（c）改 `_validated_fields`，允许平台行携带 `target_agent_version`。**
  否掉：那不是恢复，是把一个**安全边界**拆掉。平台行跨全部租户可见，
  让它钉某个租户自己的智能体版本，等于让一个租户的智能体去服务别人的入口 ——
  这正是 `select_promo_agent` 只在**请求所属租户内**解析的那条约束在挡的事。
- **（d）前端硬编码按钮、后端不管。** 否掉：那是把"后端没有这个动作"伪装成
  "前端有这个按钮"，点下去落进普通问答 —— ADR-0031 的「后果」一节已经记过
  这个既有偏差，本次不再加一层。

## 后果

- **代码侧（本 ADR 的交付面）**：`operator` 入口的动作集回到**三条** ——
  `case_exploration`(10) / `smart_diagnosis`(20) / `operations_review`(30)。
  种出来的是 `draft`，发布仍是运营动作。
- **数据侧（不随合并部署发生）**：41 上按钮会在合并且 CD 部署后立即可见
  （那行平台行一直是 `published`），**但卡片仍出不来** —— 该租户的 `operator`
  入口没有租户覆盖行。补这一行见 `env-41-runbook.md` §3.1-ter，
  绑定值需运营指定（见下条）。
- **内容语境是一个仍未解决的欠账**：现成可绑的宣传智能体（`agt_ed443cae…#v3`）
  绑的库是重卡流量平台的**销售物料**，文案面向终端客户。
  ADR-0031 把它记成"给运维看是错的语境"；**这个判断本次不推翻** ——
  用户要的是"恢复这个入口"，而"出卡"与"文案合适"是两件事。
  ⇒ **内容侧待产品复核，记为未完成项**，不由本次改动声称已解决。
- **版本选 v3 而不是 v2**：`consumer` 侧钉的是 `#v2`，而 v2→v3 的唯一差异是
  **输出语言**（v3 要求四个段落标题用请求语言书写，不照抄提示词里的中文，
  见两版快照的实际 diff）。恢复时选新版本；**不**顺手把 `consumer` 侧的旧钉子
  一起升级 —— 那是另一件事，混进来会让这次回退不可单独回退。
- **`consumer` 侧零影响**：种子、数据行、问句模板均未动。
