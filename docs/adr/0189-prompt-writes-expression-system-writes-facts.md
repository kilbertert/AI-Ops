# 189. 提示词写表达，系统写事实：四条事实判据与三类新出口

日期：2026-10-30
状态：已采纳
相关：[ADR-0187](0187-consumer-chatflow-prompt-writes-the-reply.md)

## 背景

ADR-0187 给客户端 `answer` 节点开了写正文的口子（`reply`），判据只有三条：金额"该有的都在"、
正文里每个数字都能在证据里找到、不含内部标识。当天实测这条判据**拦不住三类错话**，而它们
都不是"数字不对"：

- `合计 20，付款 27.36`：两个值都是真的，**标签互换了**。数字集合比对发现不了。
- `每小时 3 元`：`3` 落在"0–10 的小计数豁免"里，于是凭空造出一个单价。
- `已到账` / `未结束`：金额与状态都"在证据里"，**断言的方向反了**。

同时另外三处也还够不到提示词：客户端的澄清／无结果／转人工仍是固定文案；管家找站的正文被
模板整段覆盖，提示词只能决定"查什么"、决定不了"怎么说"；而迁移脚本
`--live-documents` 会**无条件覆盖** answer 节点的 SYSTEM —— 那正是运营写提示词的地方。

## 决策

### 1. 事实判据从"数字对不对"换成"这句话把哪个值说成了什么"

新增 `consumer/consumer_facts.py`，四条判据，逐条对应上面三种错话：

| 判据 | 判据的形状 |
|---|---|
| 金额标签绑定 | `合计/总额/订单金额` 后最近的数字必须等于 `order_amount`；`支付/付款` 对 `recorded_payment_amount`；`退款` 对 `recorded_refund_amount`。字段没有值时，标签旁出现数字即拒 |
| 货币断言 | 带货币单位的数字必须等于快照里的某个金额；**不再享受小计数豁免**（`3 元` 是价格，`第 3 条` 是计数） |
| 到账/退款/扣款承诺 | 肯定形式一律拒；否定形式（`没有退款记录`）放行 —— 那正是我们要说的话 |
| 状态方向 | 快照 `finished` 时不得出现被否定的"结束/完成"；`charging` 时不得出现肯定形式 |

两条实现细节是判据的一部分，不是优化：**订单号先等长掩码再找近邻数字**（否则
`订单号 ORDER-A-1，账上记的支付` 里的 `1` 会被绑到"支付"上），**只看"标签在前"且不跨子句**
（否则 `退款 0。第 3 条是退款说明` 里的 `3` 会被绑到"退款"上）。

金额为 0 时，"没有这一项"与写出 `0` 等价（`covers_zero`）：要求模型必须写 `0` 只会逼它说
一句不自然的话，而读者要的事实是"没退过"。

### 2. 澄清／无结果／转人工的正文交回提示词，判据更硬

这三类出口**没有任何本轮证据**，所以判据与 realtime 相反：**一个数字都不许出现**，不许写
链接，不许出现"已提交/已退款"类执行声明；客服入口行仍由内容包给、系统追加。长度上限 600。

`unavailable`（服务故障）与 `safety`／`photo_unreadable`／`followup` 保持系统输出：模型没有
故障信息，让它描述故障只会多一个错处；紧急安全提示不能依赖模型成功。

### 3. 管家找站：模型负责语气，系统负责事实

节点调用 `cpms_site_search` 取得当前账号可见的真实结果后，可以写一两句说明；**说明里不许有
数字、价格、距离、空闲状态，也不许重抄结果里的站名地址**（`SITE_FORBIDDEN` + 站名地址比对）。
名单、数量、截断范围、无定位限制与来源由 `render()` 按证据写出，说明只能排在它前面。

没有调用工具就写了说明 → **整轮失败**（`OPERATOR_SITE_NOTE_WITHOUT_EVIDENCE`）。以前是静默
丢弃那段话、照常交付站点；改成失败的理由是：静默丢弃会让写提示词的人以为它在生效，而它一次
也没有出现过。**没有任何文字因此被交付**，这比改动前更严。

### 4. 迁移只做初始化与受控替换

`--live-documents` 三分支：SYSTEM 为空 → 初始化；与模板逐字相同 → 幂等；不同 → 拒绝并说明
`--replace-system`。拒绝发生在任何其他改写之前，不会出现"环境变量改了、提示词没改"的半迁移。

## 代价（必须写清）

- **判据仍是启发式的，不是证明。** 它拦的是"值挂在错标签上""编了钱数""承诺到账""状态说反"
  这四类**可机械判定**的错话；一句每个值都挂在正确标签上、但因果关系说反的话仍会通过。
  业务准确率只能由真实故障案例验收，不能由这里替代。
- **"只看标签在前"是判据的一部分。** 写成 `27.36 是合计` 这种语序时不参与绑定（数字仍要过
  "每个数字都要有出处"那条）。换来的是不再误伤 `第 3 条是退款说明`。
- **找站风格依赖模型先调工具。** 真实模型是否稳定"先取数再写说明"只能在真实环境验；没调
  工具且没写说明时仍走系统模板（可用，但风格固定）。
- **`unavailable` 时提示词没有着力点**：服务故障的措辞仍是系统的。
- 客户端每次 realtime/clarify 答复的正文都不在代码评审覆盖内；可执行的那部分（数字、标签、
  方向、标识）已由判据兜住。

## 被否掉的替代形态

- **用第二次模型调用判分。** 那只是把"能不能证明"换了个模型，而且给每次答复加一次调用与
  一个失败面；判据能写成确定性的就不该交给采样。
- **要求正文与确定性渲染逐字一致。** 那等于禁止模型写字，回到 ADR-0187 之前。
- **找站继续用固定模板。** 那样"改提示词就能改表达"在找站上不成立，16 格样本里有两格写不出来。
- **无证据的找站说明静默丢弃。** 见上：会让提示词作者误以为它在生效。
- **迁移默认覆盖 SYSTEM，只加一个警告。** 警告在 CI 日志里没人看，而代价是运营的措辞。
