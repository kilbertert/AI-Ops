# 235. 开通依赖按已发布来源和系统声明收敛

日期：2026-11-06（北京时间）。状态：已采纳（用户确认机制修复及完整交付）。

真实事故：运行工作区已升级知识插件0.0.2，开通却先读取独立全局配置安装不存在的0.0.1；
目标CPMS目录仍为旧版，开通仅拒绝并要求人工逐租户迁移。应用运行与开通准备拥有不同真源，
导致“升级验收通过”不等于“升级后能开通”。

决定：知识插件精确标识取自所选来源发布图，不再接受独立全局默认；官方Agent策略仍由
发布合同固定，模型凭据仍来自平台批准profile，不能复制来源客户秘密。
每次开通/失败重试重新核验实际依赖。CPMS目录是统一声明的派生物：同Gateway、无共享鉴权、
只含系统路径的受管旧目录可收敛并回读，陌生地址/自定义工具等冲突保留。
目录以OpenAPI的`x-`扩展保存自身规范JSON摘要：完整生成物可跨后续输入schema变更继续收敛，
摘要与内容不同则拒绝；无标记旧目录仅接纳已知空输入或当前声明。摘要是漂移检测，不是授权凭据或签名，
持有工作区管理权限的人仍可编辑，不把恶意重算摘要视为新增安全边界。
目录更新不改变正式应用选用工具或授权，副本开通仍只建草稿，不替换已有正式入口。

插件是工作区共享的可执行代码，与可重建目录不同：安装回执必须被精确版本回读证明；
同plugin_id其他版本冲突不能冒充安装成功，也不能为副本擅自降级/切换正在运行的共享代码。
此类兼容升级仍走平台插件发布流程，页面给明确错误，不要求逐个租户猜原因。

依据：Dify1.17.1官方PluginInstallFromPkgApi、PluginInstaller及实际安装清单；
[OpenAPI3.0.3 §4.8](https://spec.openapis.org/oas/v3.0.3.html#specification-extensions)允许`x-`扩展；
servers/paths/operationId与security界面沿用现有provider合同；
[ADR-0181](0181-a-tool-is-a-declaration.md)和[ADR-0232](0232-consumer-agent-conversation.md)。
拒绝“启动时扫描修改所有租户”，它扩大副作用且无法保持旧发布兼容；采用任务内收敛并记录失败。
