# H5仅增加签名素材GET转发

日期：2026-10-25
状态：已采纳

## 背景与决定

WF01回答通过既有`MediaResourceSigner`生成同源`/v1/media/{signed_id}`。
原H5窄转发没有这条路径，浏览器加载图片会返回静态首页。增加一条GET location，
ID限制为生成器实际输出：`media_`+32个base64url字符+`.`+24位十六进制签名。
签名真实性和当前QA/发布版本仍由Gateway判定，Nginx只决定路径能否到达。

沿用ADR-0092和Nginx官方`ngx_http_proxy_module`的无URI proxy_pass语义：
原路径、查询和Range头透传，不新增数据协议；继续关闭缓存与自动重试。
生产图片输入仍关闭，不因回答可以显示图片就开放上传。

## 备选方案与后果

- 转发整个`/v1/`：会暴露未声明管理面，拒绝。
- 前端改为任意外部媒体地址：改变来源与访问边界，现有签名代理已足够，拒绝。
- 不改转发：文本成功但图片始终拿到HTML，不满足原App业务表达。

真实Nginx检查有效形状GET可达；POST/DELETE、错形状及其他Gateway管理路由均不转发。
部署前保存原片段，失败恢复原摘要并reload；这不证明素材内容正确或App已发布。
