# 253. 可信入口分流到独立业务环境Gateway

Status: Accepted

2026-11-13用户要求同一AI平台兼顾不同服务器上的租户，并授权继续着手解决。
公司JWT未提供已验证的服务器字段；应用市场platformCode/SaaS映射存在但现役目录为空且未证明CPMS语义。

采用每环境独立Gateway、登录代理和数据根，共享Dify与现有业务合同。可信环境入口使用既有nginx，
通过每环境独立的来源凭据映射到静态上游。它不解码用户JWT、不按JWT字段选URL；对应Gateway仍验证用户身份。
来源代理须覆盖客户端来源头，用户不能持有此凭据。未知或重复凭据拒绝，无默认目标；失败不重试其他环境。
每个上游使用自己已有的公司来源密钥；可信环境标签由入口覆盖。远端上游只允许HTTPS并验证CA与主机名。

替代方案是单Gateway中增加环境配置与逐表多维主键，改动跨身份/会话/工作区/运行数据；
现有单环境作用域无法承载同ID碰撞，先复用进程/数据根隔离减少迁移风险。
不引入第二套模型循环、通用动态代理或前端任意URL字段。公司目录核实后只更新同一受控接入清单。

依据：RFC8725 §3.8～3.10；nginx官方map、upstream、proxy_pass及proxy_ssl_verify文档。
第一片只生成和验证接入配置；真实数据面、控制台路由及生产启用必须单独验收，不宣称跨环境已经上线。
