# 283. 新环境先准备候选工作区，未知创建只对账

状态：已采纳；接续ADR0282，后继资源准备不复用旧客户首次自动发布。

## 决定

同冻结计划的未过期现场观察通过后，管理员选择草稿中明确租户，原任务账本和后台执行端准备候选工作区。
复用ensure_workspace与环境/租户唯一映射，使用共享Dify服务凭据；不登录或修改目标公司的业务服务。
已发出创建而结果未知时，后台只对账：单命中补映射，多命中拒绝，零命中仍待核对；不能用列表暂时为空推断创建失败。
原客户开通默认恢复行为保持，只有新准备路径启用显式保守恢复选项。

## 替代方案

直接调用旧客户开通能连应用一起创建，但首次自动发布会在候选业务验收前切正式路由。
按新计划重复创建容易实现，却可能把已创建但回执丢失的工作区变成永久孤儿。
把资源ID交给浏览器或执行宿主报告最省接线，但无法证明归属；选择中央使用固定Dify接口亲自创建与回读。

## 后果

新资源保留作对账，不在失败/取消时删除；准备结果只能表示工作区候选就绪，应用/知识/网络/业务仍pending。
未知任务不能自动通过，多命中或不确定结果要求后续人工核对；这是不重复创建的成本。
原site-preflight回执与运行准入保持，任务方法限定workspace，不开放任意HTTP/SQL/shell。
HTTP POST按[RFC9110§9.2.2](https://www.rfc-editor.org/rfc/rfc9110.html#section-9.2.2)不天然幂等，
[SQLite事务](https://www.sqlite.org/lang_transaction.html)保护短账本更新，远端调用不持写事务；不声称全局exactly-once。
