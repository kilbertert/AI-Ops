# 329. 安装制品传输共享有限预算，不要求大包在65秒内上传

状态：已采纳。适用受管候选安装、冷安装与登记执行端的制品搬运，不改变业务准入。

## 问题

19MB应用制品在慢链路上需要约250秒上传，原worker每次`dev-host cp`都在65秒中断，
导致未派发任务反复失败，即便900秒计划和原安装窗口仍有余量。
等待网速恢复不提供持久能力；直接手工预装或改生产脚本也不是页面开通。

## 决定

搬运阶段共享400秒单调时钟预算：单次上传最多300秒，小包构建、来源读取和私有目录
检查各保留65秒上限，均不超共享余额。新执行还以冻结计划剩余时间减60秒限制搬运；
只读观察独立使用400秒预算，不续签旧计划。

一次执行从stage前计840秒预算，搬运结束后远端动作使用剩余时间，最多800秒，
保留20秒向中央回报。原执行端服务880秒上限和900秒租约保持，预算耗尽进入原未知
结果对账路径，不伪报安装完成。依据Python `subprocess` 的 `timeout` 行为，超时只影响
本次子进程；不能由其推出远端已停或没有副作用，派发后仍须原冻结只读观察。

SHA256、主机公钥、私有归属、原`dev-host`操作和完整制品检查保持；搬运后仍经
中央`authorize`复核取消、权限和有效期，过期不能因上传已完成而越过派发闸。
目标只运行合并制品中的原安装器，不引入另一个上传平台或业务SSH隧道。

## 被否方案

- 等待链路达到指定速度再重试：能避开一次失败，但不能使慢链路环境可开通。
- 单次上传无限等待或扩大业务计划：掩盖阻塞并占用worker，不符合既有取消/期限合同。
- 手工预传、跳过受管上传：不能证明真实页面路径，且丢失固定制品和归属校验。
- 本次新增断点续传/缓存目录：当前单包可在已有计划内完成，先修有限预算，不另造状态机。

## 后果

新鲜计划内250秒上传可完成；单包超300秒、共享预算耗尽或计划余量不足仍明确停止，
不会派发安装。超时或摘要失败保持原结果/恢复语义，现场升级仍须现有明确授权。
只修执行端预算，原API、配置和返回字段不变；慢链路不再必须达到19MB/65秒的吞吐。
