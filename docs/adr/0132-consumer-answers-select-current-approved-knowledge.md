# 132. WF01答案选择本轮已审核知识

Status: Accepted

## 决定

Dify Chatflow负责判断用户问题与选择FAQ，知识检索通过本轮一次性凭据回调Gateway。
复用短期grant和Dify执行记录；不同用途的grant不可互用，回调固定已授权QA的问题、语言、
租户与知识库集合，不接受回调重定向问题或扩大范围。取消/过期/换绑在读前读后均阻断。

RAGFlow负责召回，运营内容快照负责可交付标准答案。只有本轮召回且快照已审核的FAQ可交付；
Dify返回kind/faq_id，不生成实时业务事实或素材URL。缺取数记录、未召回ID、额外字段一律拒绝。
无命中与知识服务不可用分别呈现；未接实时能力明确不可核实，不用静态FAQ推断状态。
已审核内容文件同样进入绑定摘要，同路径改内容也会阻断旧结果/会话。

本地明确安全/人工请求先于订单、知识和模型处理。安全文案不包含特定电话号码、时效或操作命令；
人工渠道只读受控配置，不把显示入口说成已转接。不新增任何退款、停充或自动建单能力。

## 替代方案

- 只把原Markdown导进Dify最省事，却无法阻止草稿/原始升级规则被直接当用户答案。
- 让模型自由改写退款/收费条目更灵活，但目前没有逐事实核对能力；首片选择已审核标准答复。
- 用公司会话或整租户密钥回调能少一张授权记录，但会扩大权限，沿用单次短期授权。

## 约束

原内容草稿必须另经内容审核产生发布快照，本片不自动批准原件。媒体尚不签发；
知识库元数据过滤不假装已实现，发布库及审核内容需收窄到实际适用范围。
协议沿用Dify HTTP节点、现有RAGFlow检索和JSON；业务只读工具在后续同一主线补齐。
