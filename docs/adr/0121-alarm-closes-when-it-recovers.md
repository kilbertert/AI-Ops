# 121. 告警票在恢复正常时由守望者关闭

日期：2026-10-23
状态：已采纳
影响版本：`.sandcastle/cd-watch.mjs`、`.sandcastle/deploy-state.mjs`、
`.sandcastle/cd-watch.test.mjs`

## 背景：一张开了 8 天却早已自愈的票

`#792`「CD 状态：有部署尚未发生或连续未成功」开于 2026-10-14，最后一条评论是 10-15。
而 CD 自 10-23 12:17 起连续 7 次 success。

`cd-watch` 每天在跑（当天跑了 3 次），每次都判定「CD 状态正常」——然后**什么都不做**。

```js
if (result.ok) {
  console.log("CD 状态正常");
  return;          // ← 这里
}
```

它只有 `announce()`（开票 / 评论），**没有关闭路径**。

## 为什么这是个缺陷，而不是「留着让人看一眼」

在 issue 列表上，**「八天前已恢复」与「仍在坏」长得一模一样**。下一个人读到它，只能
重新查一遍 CD 状态才知道该不该管。告警系统的价值在于「开着的票 = 有人要处理」；
一张已经好了一个星期却还开着的票，恰好把这个信号毁掉。

这与本仓已有的一条判据同型：`cd-watch` 自己的注释写着「一张未关的票本身就是『还没
处理』」——那句话只在票会被关掉时成立。

## 决定

CD 恢复健康时，守望者给每张开着的告警票**先评论、再关闭**（`--reason completed`）。

四条分支，做成纯函数 `recoveryOutcome()` 以便脱离 GitHub API 测试：

| 输入 | 结果 | 理由 |
|---|---|---|
| 取数失败 | `unknown-keep-open` | 读不到 run 时，我们对 CD 一无所知，不构成恢复 |
| 仍有告警 | `still-alarmed` | 正常路径，不关 |
| 健康、无开票 | `nothing-to-close` | 无事可做 |
| 健康、有开票 | `close` | **这条是本记录的全部内容** |

**先评论再关闭**：只关闭会让读者猜是什么修好的；评论才是检索得到的东西。

### 关闭评论必须陈述**实际成立**的判据

第一版写的是「最近 N 次已完成的 CD 全部 success」。那是**不成立的**：`assess()` 的
`ok` 只要求「连续失败 < N」且「无超时未完成的 run」，`[failure, success, failure, …]`
这样的窗口也是 `ok: true`。评审指出后改正（2026-10-23）。

这条值得单独记，因为它的形状很常见：**把「阈值未触发」写成「一切正常」**。前者是判据
的真实含义，后者是一个更强、且这次运行从未检查过的断言。写进 issue 时间线的每一句话，
下一个人都会当成事实引用。

## 备选方案与取舍（被否的路线）

- **让人手工关。** 被否：#792 证明了它不会发生——这张票开了 8 天，期间 `cd-watch`
  跑了约 200 次。依赖人记得关，等于没有关闭机制。
- **由 `cd-watch` 直接删除告警票。** 被否：删除抹掉「曾经出过问题」这一事实。关闭保留
  时间线，检索仍能找到。
- **恢复时不评论、只关闭。** 被否：见上，读者无从判断是什么修好的。
- **把判定写进 `announce()` 内部。** 被否：那会让它无法脱离 GitHub API 测试，而这正是
  这个缺陷活到今天的原因——`announce` 的副作用从来没有单测。

## 后果

- `--dry-run` **也查询**开着的票，只读、不执行。第一版在 dry-run 时跳过查询，于是
  预览在一个有开票的仓库上打印「CD 状态正常」——那正是它该报告的东西。
- `#792` 会在下一次 `cd-watch` 运行时被关闭，并留下一条「已恢复正常」的评论。
- 测试从 28 条增到 32 条；三条新变异（去掉任一条 `if`）各自让一条转红。
