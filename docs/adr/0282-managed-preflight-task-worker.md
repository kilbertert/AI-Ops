# 282. 中央现场预检任务与受管执行端分离

状态：已采纳；接续ADR0281，仅现场预检，不开放安装、资源准备或激活。

## 决定

中央沿唯一目录授权与独立草稿SQLite保存冻结任务，按环境、目标、动作和计划摘要去重；租约失效是待核对，
新租约只重新运行可重复的只读preflight，旧租约不能写回。取消在动作边界生效，保留已经取得的证据。
旧客户开通账本的启动失败/租户单字段互斥仍维持原合同，不直接承担新环境任务。

采用独立运维执行端，通过原aiops-admin、dev-host与合并固定安装器取证，再以独立内部HMAC和租约报告。
部署SSH私钥不进入业务Gateway，浏览器不能指定命令、地址、服务身份或提交passed。中央不复用Dify发布密钥，
新密钥未配置时拒绝新任务，原管理和业务入口不变；读旧任务仍重核目录授权。
后台定时任务只选一个待处理现场预检，继续按原lease与冻结输入取证；过期/撤权队首明确结束，不阻塞另一目标。
中央受管传输调用已部署CLI，以Gateway服务身份读取自身配置并访问本机内部HMAC；密钥不传执行宿主，
不新增公网管理路径，SSH只作为运维通道。原定编号HTTP入口仍兼容，部署与业务激活分开。

## 替代方案

把内部队列暴露到公网可让执行端直接轮询，但扩大管理面且需要另一次入口批准；
把SSH放进Gateway可直接复用同步页面调用，但扩大业务进程主机权限；让页面上传结果最易接线，但没有可信执行来源。
不另造通用工作流引擎，也不把只读重查可重复性推广到安装/开户；后继动作须各自有实际对账与恢复合同。
## 后果

独立表可被旧版忽略，回退保留任务与回执；租约、HMAC时间窗与[SQLite短事务](https://www.sqlite.org/lang_transaction.html)沿现有平台合同，
HTTP重试按[RFC9110§9.2.2](https://www.rfc-editor.org/rfc/rfc9110.html#section-9.2.2)理解为服务端去重，不声称POST天然幂等或端到端exactly-once。
