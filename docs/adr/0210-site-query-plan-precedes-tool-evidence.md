# 210. 地点词在工具取证前确定，代理共用查询实现

日期：2026-11-04
状态：已采纳

#1351部署后的真实运行仍把`address=广州天河`发给CPMS，结果为0；最终答案却已有
`address_terms=[广州,天河]`。旧修复只改query_sites，实际节点代理直接调用cpms_get，
根本没有经过该函数。测试替身不执行地址过滤，还把地址写成连在一起的汉字，因此无法发现断点。

## 决定

站点工具在调用前接收`address_terms`数组：最多4项，总长度不超过80；每项必须是用户原话中的
连续片段。模型选择完整地点词，Gateway冻结它们，逐词读取CPMS并去重；最终答复必须使用同一组词。
Python声明和Java节点共用`model_input_schema`，依据JSON Schema的array/items/maxItems语义。
依据：[JSON Schema数组](https://json-schema.org/understanding-json-schema/reference/array)。
这是协议表达能力的修正，不是新增地理数据源。

管家代理、消费者代理和直接查询共用read_site_pages，保留逐页授权、租户/站点校验与输入上限。
节点每词最多1页/50行，最多4次请求，输出不超过50行，页面最多10行；直接查询每词最多4页。
多词计数读全时为去重行数，未读全时只作上界并标记截断；不能向用户宣称精确总量。
原address字符串仍按字面兼容，不把旧调用偷偷拆成任意二字词。

部署必须同时更新节点jar、挂载的工具声明和Gateway；旧节点不能运行数组参数。
无订单管家清单按当前声明生成；订单清单未启用站点工具时发布指针无需变更。
若某个已发布清单已含旧站点schema，必须走正常发布更新，不能改写历史版本。

## 备选方案与边界

- 仅在SiteKeywords中切字：实际代理仍可能绕过，而且“广州天河”任意滑窗会造出“州天”。
- 仅调整提示词：工具仍只有一个字符串，信息在取证前没有落点；结果仍依赖绕过路径。
- 全租户扫描后让模型挑站：扩大取数与泄露面，不符合现有按任务授权的证据链。
- 引入行政区或拼音库：当前真实站点行政区编码为空，不能据此完成地理一致性验证；另行设计。

本片延续ADR-0207的关键词候选搜索语义，不声称行政层级交集、距离排序或全语言地名解析。
没有可匹配完整关键词时应澄清；“没有关键词匹配”不能推断城市没有充电站。
