# 88. 订单判定被拒时向公司实时店铺确认一次，而不是让令牌快照一锤定音

日期：2026-10-22
状态：已采纳
影响版本：`src/aiops_diagnostics/caller_auth.py`（`ScopedOrderAuthorizer`）、
`src/aiops_diagnostics/gateway_api.py`（装配点）

## 背景：两个「当前店铺集合」不同源

公司令牌里的 `shop_ids` 是**登录那一刻**的快照：

```java
// TokenController.java:186-187
if (CollUtil.isNotEmpty(sysUser.getShopIds()) && sysUser.getShopIds().size() < 10) {
    payload.put(SecurityConstants.DETAILS_SHOP_IDS, sysUser.getShopIds());
}
```

而公司列表接口 `/chOrderInfo/page` 带 `@ShopDataScope(realTime = true)`，**每次请求**
都去 `/shopuser/getShops` 取当前值。

于是「登录后店铺绑定被改」会产生一个窗口：管家端列表里出现了新店铺的订单，提交诊断时
AI-Ops 按旧快照判成「不属于」。窗口一直持续到令牌过期重登。

顺带一个公司自身的上限让快照更不可靠：只有店铺数 `< 10` 才写进令牌，店铺多的账号
**根本没有**这条声明 —— 同一份代码在同一环境下有两种语义。

41 上实测：182 个有店铺绑定的账号里，**88 个**落在「令牌带快照」这一支。

## 决策：快照说「能看」就直接放行；说「不能看」时才确认一次

```
查（快照范围）
 ├─ 命中        → 放行（正常路径零额外请求）
 └─ 未命中
     ├─ 口径是 organ 且有 B 端主体 → 向 /shopuser/getShops 实时确认
     │    ├─ 确认可见 → 放行，并记 order_authorization_stale_shop_snapshot
     │    └─ 确认不可见 / 上游失败 → 维持拒绝
     └─ 其它（self / all / 无 B 端主体）→ 维持拒绝，不发请求
```

## 备选方案（为什么没有选它们）

- **备选一：解析时一律实时查店铺。** 最直接，但会让**每一个**管家端请求多打一次公司
  内部端点，并把该端点的故障引进所有请求（503）—— 直接违反 ADR-0009 决定 2
  「不再调 `/shopuser/getShops`」的动机。既有测试
  `test_the_operator_entry_does_not_query_when_the_token_carries_shop_ids` 正是钉住
  这一点的；本轮先按这个方案改过，被该用例与一批 `shop_directory=None` 的用例拦下，
  已回退。
- **备选二：不接受回退，改由公司把列表也用快照。** 需要公司侧改动，且公司自己的
  `realTime=true` 是为「绑定改完立刻生效」设计的，让它退回去是拿业务正确性换一致性。
- **备选三：缩短令牌有效期。** 只是把窗口变小，不消除；而且令牌生命周期归公司管。
- **备选四：把自己缓存的店铺集合做成短 TTL。** 仍有一段时间的不一致，只是换了一个
  窗口；而且引入了「授权范围的 staleness」，需要先定可接受上限 —— 比现在这个问题更大。

## 为什么回退方向是安全的

- 回退只可能把 `False` 变成 `True`，且判断依据是**公司此刻的权威答案**（与列表接口
  同一个来源、同一个端点）。
- 判定仍走同一套 `QueryScope` → SQL 谓词，租户边界没有放宽，站点映射没有绕过。
- 回退只在「本来就是拒绝」的路径上触发，正常路径的行为逐字不变。

## 已知代价与边界

- 被拒的请求会多一跳（公司端点 + 一次站点映射）；命中快照的请求零成本。
- 公司端点不可用时**保持拒绝**，不把上游故障变成放行。
- 这条只覆盖「店铺绑定变了」；站点归属（`ch_site.shop_id → id`）若在登录后被改，
  回退查到的仍是当前站点映射，同样覆盖。
- 不覆盖：订单本身所属站点在 `ch_site` 里不存在（41 实测 210 单），那与店铺无关。

## 验收

- `tests/test_operator_order_authorization.py` 五条：快照命中不查、过期快照回退后放行、
  回退不放宽、`self` 口径不触发、上游失败维持拒绝。
- 变异复验：去掉回退分支，后三条转红（已实测）。
- 41 只读对照（74 个有订单的代理商账号，公司口径 vs AI-Ops 判定）：逐单 0 差异 ——
  说明回退是**兜底**而非日常路径。
