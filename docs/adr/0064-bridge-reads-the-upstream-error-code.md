# 63. 桥不再按 HTTP 状态猜上游的意思：错误码随失败一起回来

日期：2026-10-20
状态：已采纳
影响版本：`src/aiops_diagnostics/bounded_http.py`（`HttpFailure.code`）、
`src/aiops_diagnostics/dify_console_publish.py`（`_request` 重建错误 body、试运行的
404 按码分流）、`src/aiops_diagnostics/dify_trial.py`（平台哨兵租户）

## 背景

2026-10-20，用户报告两件事：Dify 与运行时"没打通"，以及 `aiops-41-ops-methodology-agent`
点「试运行」返回「未登记注册」。逐层实测后，它们是**三条独立的缺陷**，其中两条都表现为
"看起来像某个别的原因"：

| 现象 | 第一眼结论 | 实测根因 |
|---|---|---|
| 点试运行 ⇒「没有登记成绑定来源」 | 绑定表坏了 | 网关回的是 `404 ORDER_NOT_FOUND`（订单范围），桥把**所有** 404 都当成 `DIFY_APP_NOT_BOUND` |
| 平台账号（`system`）什么都试不了 | 权限不够 | 平台账号的 `tenant_id` 是哨兵 `-1`，被当成一个租户下推 ⇒ 范围为空 ⇒ 每张单 404 |
| Dify 侧检索永远 502 | 知识库没配 | 上游 embedding 供应商欠费（`insufficient_user_quota`），网关把它折叠成同一句「temporarily unavailable」 |

第三件是外部条件，不改代码；前两件是**同一类错误**：把"上游说了什么"压缩成一个 HTTP
状态码，然后在调用方按状态码重新猜一遍语义。

## 决定

**上游信封里的机器可读错误码随失败一起往上走，桥按码分流，不再按状态猜。**

1. `bounded_http.HttpFailure` 增加 `code`；`classify_http_error` 从
   `{"error": {"code", "message"}}` 里取它。**错误码与人类可读 detail 必须来自同一次
   响应体读取** —— `HTTPError.read()` 是一次性流，分两次读第二次拿到空串，而那种失败
   是静默的（`code` 永远是空，调用方会以为"上游没给码"）。
2. `dify_console_publish._request` 在上游非 2xx 时**重建**一个与网关同形的
   `{"error": {...}}` body，而不是返回 `None`。这样桥与任何读 `error.code` 的下游
   不必知道这条 body 是重建的。
3. 试运行的 404 分两种说法：`DIFY_APP_NOT_BOUND` ⇒「这个智能体没有登记成绑定来源」；
   `ORDER_NOT_FOUND` ⇒「这张订单不在你的可见范围内」。**认不出的 404 报"未确认"
   （502），不猜。**
4. `TrialInitiator.from_headers` 把 `tenant_id == "-1"` 判成"没有可用身份"，退回
   固定调试租户（ADR-0028 §3 已论证过的既有行为）。**不是**把 `-1` 当成"平台看全部"：
   本服务没有任何跨租户可用的数据源支撑那个含义。

## 被否掉的替代形态

- **把 `-1` 当成"平台可见全部租户"**。听起来更"正确"，但它是**放宽**：`-1` 在充电库里
  没有任何订单行，要让它"看全部"就得新建一条跨租户查询路径，而那条路径今天不存在。
  一处 fail-closed 的身份判定，比一条没有数据源支撑的放宽安全。
- **桥保留"所有 404 = 没登记"**。它把运营指向绑定表，而真实原因在订单范围 —— 一句话
  把人送到错误的地方，且两句都"看起来很合理"，这是最难自查的一类。
- **在桥里 `parse` 上游 body 的文本再判断**。文本是给人看的，会变；码是给机器看的。
  认不出的码就该报"未确认"，而不是拿文案做匹配。
- **把 embedding 欠费也映射成独立错误码让运营看见**。方向对，但那是 kb-service 与
  RAGFlow 之间的事，网关拿不到那个码（它只看到 `502 upstream_error`）。本轮把它如实
  记进 `validation.md`，不在网关里编一个它看不见的结论。

## 后果

- 桥的错误文案从此**依赖上游给码**。上游不给码 ⇒ 「未确认」，运营看到的是"去核对"，
  而不是一个可能是错的断言。这是有意的降级方向。
- `HttpFailure` 多一个字段，调用方不读就没有影响（默认空串）。
- 平台账号在试运行上**回落到调试租户**，与"未映射账号"同一条路 —— 这意味着平台账号
  能试运行的范围与调试租户相同，不是全部租户。这条与 ADR-0028 的取舍一致。
- 一处仍未收口：`-1` 作为**租户**出现在别的入口（例如发布审计的 `tenant_id` 列）时
  仍会被照抄。本轮只改了"把它当查询范围"这一处，因为那是唯一会产生错误答案的地方。
