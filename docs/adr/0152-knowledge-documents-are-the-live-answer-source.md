# 知识库是知识正文与关联媒体的唯一来源

日期：2026-10-27
状态：已采纳（用户明确替代ADR-0151的“仅审核FAQ交付”范围）

用户要求在知识库加入资料、Chatflow配置使用该库后，App即可检索回答，不再手改服务器审核/发布/媒体清单。
当前RAGFlow已经实时检索；失效发生在Gateway只按文件名匹配冻结FAQ副本，KB-C-059虽命中仍被丢弃。
审核副本只有手工state字段，并没有真正的审核工具；它不能成为拒绝用户已确认业务体验的理由。

## 决定

新版WF01使用本轮检索的脱敏正文，由Dify整理成用户语言的回答并选择来源；Gateway只允许本轮来源ID，
媒体取自这些来源的真实关联资源或正文中现有视频链接。复用检索层媒体解析和原App blocks，不让模型生成URL，
不再要求KB-C-NNN命名、entries白名单、media_ids映射或新资料重新发布。

只有工作流图和所用库随工作流发布版本固定；库内文档新增/更新/删除在完成索引后影响新问题。
每轮保留当次检索快照以支持引用、历史与并发一致性，不把这个快照变成额外的内容准入/审批步骤。
单轮凭据、租户/库范围、本人订单、取消/撤回/过期守卫保持；实时业务仍由CPMS分支读取，知识文档不能授予业务写操作。

callback_version=4与knowledge_answer_mode=documents标识新输出协议；一次迁移原Chatflow提示词，之后运营只维护库。
旧版保留兼容以支持显式回滚，新版不读取content_file；发布快照只保存原环境和租户身份，无FAQ/媒体正文副本。
原人工入口使用已有App/站点提示，不在知识库同步任务里新增审核平台。

## 备选方案

- 新增审核CLI或自动生成content.json：继续重复维护正文/视频，不能满足“加资料即可用”，不采用。
- 直接贴原始chunk：会把双语问法、元数据和整段无关内容交给用户；采用模型基于来源组织回答。
- 模型自由填写视频URL：不必要，正文已有地址，复用确定性媒体提取与引用校验。

## 限制

资料进入所用知识库即进入回答来源；内容正确性由资料维护承担，本版本不再声称人工审核保证。
模型引用来源不能证明每句话绝对正确；保留无资料/不可用提示，真实质量按具体问题验证。
当前每轮最多5片段、每片段8000字符、4个媒体；长文依赖知识库切分。外部视频受站点和网络可用性限制。

真实试用修订：现役模型会重复原文视频URL，不能把所有正文URL都拒绝。仅允许逐字属于本轮已引用文档的HTTPS链接，
带凭据/改写/未引用来源链接拒绝，媒体依旧由检索结果生成。这不是新增运营白名单，不需要登记链接。
