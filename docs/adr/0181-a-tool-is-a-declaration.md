# 181. 一个工具是什么，写在声明里

日期：2026-10-30
状态：已采纳（设计定型，已实施）

## 决定

`src/aiops_diagnostics/operator/operator_tools.json` 是「一个 CPMS 只读工具是什么」的
**唯一声明**：名称、描述、输入、请求模板、来源标记、响应形状、取证字段、分页标记。
网关侧的路径物化、输入、证据字段、发布白名单、Dify provider 的 OpenAPI，与节点侧的
装配和取证投影，都从它读。

节点的读取位置由系统属性 `aiops.node.tools-file` 给出（部署时随节点配置放），
否则退回 classpath 资源。读不到就是**启动失败**。

声明的边界是刻意的：

- 请求只能是 `GET` + 相对路径 + 声明里的查询串。「任意 HTTP / SQL 工具」仍不在方案内。
- `response.kind` 只有 `single`（一个对象）与 `page`（一页记录 + 派生标记）两种形状。
  需要**新的**形状时改的是两侧引擎各一处，不是每个工具各写一遍。

## 依据

同一个工具名曾经在仓库里写了五遍：网关的路径表、证据字段表、发布白名单、provider 的
OpenAPI 生成，以及节点侧的装配表。后果不是审美问题——「这个能力值不值得做成工具」这个
决定被**变更成本**主导了。ADR-0165 当年把「任意 HTTP 工具」列为被否方案时，理由是
「固定接口、白名单字段和参数足够」；那句话是对的，但它没计价同一个接口要改几处。
站点查询进不了工具面，一半原因是它，另一半原因是 ADR-0174 修掉的类型问题。

现在有一条可机械判定的证据：**节点源码里一个工具名都没有**。
`tests/operations/test_operator_tools.py::test_the_node_source_names_no_tool_at_all` 逐文件
扫描断言这一点——于是「新增工具要改 Java」不是「不该做」，而是**做不到**。

## 被否掉的替代形态

**代码生成：从声明生成 Java 源码，CI 校验生成结果。** 最强的地方是两侧共用同一份定义、
节点侧仍是编译期常量、出错在编译期而不是运行期。它输在判据本身：生成物落在
`services/execution-node/src` 下，于是「新增一个工具节点目录零改动」这条验收标准就只能
靠「改的是生成文件、不算源码」的文字游戏维持。标准和实现互相将就，那条标准就废了。

**让节点读网关下发的清单来装配。** 最强的地方是一份定义、只有一个运行时拥有它，节点
不可能漂移。它输在时机：清单随发布版本走，而「这一次能用哪个工具」是 run 级的事实；
把工具定义塞进清单等于让它随运行变化，而清单的身份就是它原始字节的 sha256。

**保留 Java 侧的字段表，只把名单收进声明。** 最强的地方是改动最小、风险最低：装配从
声明来，投影仍写在 Java 里。它输在半途——名单是一份、字段又是一份，而字段表恰恰是
「模型能回答什么」的那张表（ADR-0171 的 `direct_answer` 就是因为它的缺失才需要）。
两份真源里的第二份正是最危险的那份。

## 后果与验证

- **两侧解析必须逐项一致**，由 `tools/experiments/m2_close/m3node/tool_declaration_parity.py`
  比对：工具名、顺序、响应形状、来源、描述、取证字段。拿着一份**多加一个工具**的声明副本
  跑它，两侧都接受，而节点源码一个字节未改——这正是验收标准要的形态。
- **仓库 CI 不构建 Java**（`ci.yml` 只有 ruff / pytest / compileall）。上面那条比对因此
  是**手动**证据，不是 CI 门禁。这是本仓既有的缺口，已在 #1189 记录，本次没有变好也没有
  变坏；把它写进这里是因为一个不跑的检查如果被当成门禁，比没有检查更糟。
- **发布清单的字节与身份不变**：清单里的描述仍来自部署模板（改它会改清单 sha256，
  进而要求重发已发布版本），声明决定的是白名单、provider 与节点装配。这条取舍是刻意的：
  「一份真源」在此处的意思是**判据**只有一份，不是把部署数据也搬进代码。
- 新增工具的形态约束是真的：一个是单对象、一个是分页。第三种形状（例如嵌套树）需要先
  扩引擎，再写声明——这一点写在声明的 `_comment` 里，免得下一个人以为只是没写。
- **未完成业务验收**：没有真实 CPMS、没有真实账号、没有真实页面。

方案与分期见 [工具架构](../agents/operator-cpms/tool-architecture.md)。
