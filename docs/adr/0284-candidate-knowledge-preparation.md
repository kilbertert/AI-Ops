# 284. 候选知识准备沿用环境任务与复合知识命名空间

状态：已采纳；接续ADR0283，应用准备与激活仍为后继步骤。

## 决定

同计划的候选工作区验证后，中央按环境＋租户准备知识空间及一个空知识库。
复用既有开户、加密凭据、模型验证与知识创建接口；中央明确传目标环境，不使用控制服务的默认命名空间。
知识库创建名字、基线列表与发出标记先存原任务账本；未知结果只对账，不因换计划或重启重新创建。
新计划复用同复合主体的原准备资源，再实际核归属。知识准备成功只报告候选资源，不绑定应用或切正式路由。

## 替代方案

旧客户开通可一次建齐资源，但首开自动发布，且控制服务默认命名空间可能指向旧租户。
另建工作流/资源数据库便于扩展，却增加生命周期与恢复权威；原任务账本足以保存此有限动作。
每次重试新建空库最简单，但创建响应丢失会留下孤儿；选择先存发出意图再按实际列表核对。

## 后果

重试、取消与新计划均保留已创建资源，未知零命中需继续核对、多命中需人工确认。
空知识库只证明隔离资源可配置；内容、检索质量、应用、业务和激活尚未验收。
旧无命名空间账户不被自动改密或收养；发现映射不符明确阻塞，不改公司服务。
遵循[RFC9110§9.2.2](https://www.rfc-editor.org/rfc/rfc9110.html#section-9.2.2)的POST非天然幂等语义，
远端调用不持[SQLite写事务](https://www.sqlite.org/lang_transaction.html)。
