# 287. 消费者候选冻结正式编排并复用单库连接

状态：已采纳；接续ADR0286。记录模板来源和候选权限边界，非部署回执。

## 决定

环境管理员须有平台身份并显式选择可见正式消费者来源；原不可变Agent版本作为模板，
冻结其workflow，不借源工作区的草稿、密钥或执行目标。只接受现役三节点Agent合同及无秘密的环境变量。
页面提交所选版本；来源已更新时拒绝并要求重选。正式路由取已配置路由存储，快照/工作区取原Gateway存储。
复用同环境租户工作区和候选单库；整段替换知识选择，不把来源库UUID带入目标。
模型从平台已批准模型子模板准备，不复制profile的41运行目标。

候选使用原ckx复合凭据作为插件目录凭据，只允许控制服务返回指定单库；不能签发业务取数授权。
本片不写永久对客grant；正式业务启用仍须核对知识内容与执行目标。现役Agent直接调用插件，不另造未使用的dataset。
扩展显式候选导入至advanced-chat；首次落库API/site=false，普通导入保持。准备只回读draft，不publish或生成key。
来源快照、装配摘要和操作身份保存在原环境任务；未知结果只按ID对账，漂移保留草稿并阻塞。

## 替代方案与影响

取当前export较短但会混入未发布修改和源环境秘密；重生成业务模板会丢运营指令，故选择已发布快照。
自动挑第一个来源会掩盖多个正式模板差异；页面要求明确选择。另建候选账本会增加恢复权威，原任务足够。
候选插件当前只连控制服务完成目录装配；124实际取数、正式回调地址、路由及激活需后继成套验证。
部署先配套自有Dify补丁，再Gateway/桥/Web；旧管家候选与正式消费者回归必须通过。
