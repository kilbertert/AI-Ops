# 194. 站名形状判「是不是名字」，不判「有没有站字」

日期：2026-11-02
状态：已采纳

站点说明的既有判据 `SITE_NAME_SHAPE` 只认形状：2-8 个汉字紧跟「站/桩」。它挡住了
编造站名（`我帮你找到了虚构乙站`），也挡住了**类别名词**——`可以告诉我站点名称`
`如需查看站点详情` `请核对站点列表`。后者是提示词要求的追问写法，模型每轮会自然写出。

拒收不降级，是整轮作废（`OperatorRefused`）。用该回合冻结提示词与本轮
`cpms_site_search` 证据重放模型这一步 18 次，3 次拒收全部是 `rule=note_site_name`，
即站点问答的成功率部分取决于模型这轮怎么措辞，而不是取数是否正确。

决定：

- 先把**完整通用短语**（`GENERIC_SITE_WORDS`：`站点名称`、`站名`、`站点详情`、
  `站点列表`、`站点信息` 等）整条替换掉，再走原来的站名形状判据。收窄发生在短语层，
  形状判据本身一字未改。
- 否决「后缀紧跟某字就跳过」的字符前瞻写法：它会放行 `虚构乙站详情`（跳过「详」，
  剩下的 `虚构乙站` 不再被看见）。复审反例已进测试。
- 英文形状原本把限定词写成小写（`the|a|an|…`），而名字分支只匹配大写开头，于是
  `Your stations` 从未被排除。改为大小写不敏感的前瞻，限定词表补 `all/any/some/visible/no`。
  **不扩大**英文匹配范围：大写 `Station`/`Site` 后缀仍和原来一样不算站名。
- 编造站名仍然拒：`虚构乙站`、`为您查询天河测试站`、`Found Test Station`。判据方向
  不变，只是不再把类别算成名字。

被否的替代方案：把整条站名判据删掉会放行编造站名（复核反例仍在测试里）；改成
「只拦已知站名」同样放行编造（ADR-0192 已记录该反例）；让 `validate_site_note` 在
拒收时清空说明并继续交付，会把提示词作者的错误静默掉，且历史已把该行为改成整轮失败。
保留形状判据、收窄形状，是唯一既不放弃编造检测又不定罪通用名词的形态。

验证为真实模型回放的 18 条输出 + 3 条既有答复：修复前 18/21，修复后 21/21；
源码退回旧实现时新增 5 条测试有 4 条失败。本决策不改变取数、授权或证据，
也不改变消费者链路的逐数字判据。
