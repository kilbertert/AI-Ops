# 220. 实现聚焦功能，独立 Hack 提供反例，长期检查按价值保留

Status: Accepted

日期：2026-11-05。用户已确认采用；适用 AI-Ops 的交互式与 AFK 开发。

## 决定

执行规则集中在[验证分工](../agents/verification-workflow.md)，由 AGENTS、CLAUDE 与全部实现/验收入口引用。
实现者不默认扩张测试体系，Hacker 独立构造反例并验证用户入口；保留有独立判据的最小长期检查。
限制无依据新增，不取消必要风险验证、已有确定性 CI、Devin Review 或人工判断。
源码/文档探针仅证明其保护的约束，自动化结果不等于真实业务验收。

本决策替代 ADR 0036 中“全绿的 suite 不是证据”的绝对表述：结果是已执行条件的有限证据，
不能据此推出未执行路径正确。保留该 ADR 的两条入口、独立反例与未复现假设分层规则。
ADR 0030 的有来源上游替身与 ADR 0215 的 CI 分档继续有效。

## 被否掉的替代形态

- **所有测试停止新增和维护，只认 Hack**：能迅速减少套件工作量，但抛弃已知反例，
  每轮重新发现旧漏洞，且模型结论无法承担确定性闸门。
- **作者补完整分层测试，再交给 Hacker**：保留密集局部反馈，但重复作者假设与低价值维护
  正是本次要减少的成本。按具体错误与判据选择长期检查。
- **另建自动评分平台或强制并发数量**：可集中调度，但引入新的维护和资源成本。
  复用已有入口、回执与验证工具；模型能力及节时收益先用实际任务评价。

## 后果

明确区分实现、自查、独立验收和修复，减少为数量、措辞或实现细节维护用例的动机。
代价是仍需交付者判断反例价值、安排独立复验，并如实记录缺失环境；提示词不能机械保证遵守。
指定模型需核实受控配置映射；本决策不修改宿主路由，也不把模型可用性变成合并状态检查。
历史套件逐项判断，不因目录或名称批量删除。节时和检错收益尚待后续任务量化。
