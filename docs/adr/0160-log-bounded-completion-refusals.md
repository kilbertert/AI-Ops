# 管家完成拒绝仅记录固定内部原因

Status: Accepted

2026-10-29。原H5两次出现OPERATOR_DIAGNOSIS_FAILED，节点已有双CPMS证据且模型结束，
但最终答案没有被Gateway确认。当前统一失败码不能区分答案合同与完成回调的拒绝，缺少可复现诊断信号。

## 决定

沿用Python logging及现有aiops日志命名空间，增加固定原因枚举（JSON、结构、字段、凭据、业务写入声明）
和受限的完成拒绝代码。不记录请求路径、订单、令牌、模型正文或异常文本，不改变返回码及授权规则。

## 被否掉的替代形态

- 记录完整答案/异常：能快速排查，但会把凭据和业务内容写入常规日志。
- 只重试直到成功：可得到成功样本，却无法判断现有失败根因。
- 放宽答案校验：减少拒绝但会削弱现有交付边界，必须先用证据定位而非猜测修改。

## 后果

可定位失败类别且保持日志最小；仍不能据此重建被拒正文，必要时另做受控、明确范围的取证。
本片不是原业务失败修复，真实回归需要在合并部署后重现并继续调查。
