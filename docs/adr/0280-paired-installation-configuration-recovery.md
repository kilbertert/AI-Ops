# 280. 安装与恢复同时管理候选配置和私有环境目录

状态：已采纳；扩展ADR0273单配置事务，接入ADR0279候选投影，不开放租户激活。

## 决定

固定安装器新增候选包输入，与旧production.env输入互斥；只读取三份普通文件及精确manifest，
先核外层/成员摘要、环境归属和停用状态。新应用候选venv再检查配置与目录的路径、连接、语法及执行关闭状态。
生产配置根仍可穿越，环境目录改放自有`registry/`私有子目录；两文件各自0600，目录0700，由服务身份读取。
候选挂载完整私有目录和配置快照，验证时现役文件不变；旧单配置实例无新参数时行为保持。

安装账本增加目录摘要，首次从单配置引入须显式expected-registry=absent，不收养未登记目录。
同内容投影复用本地目录原字节；内容变化沿本地审计增加修订，草稿候选revision不是生产版本。
同环境锁下记录switching、停止自有服务、分别替换文件并切制品。跨文件不是原子提交，停止期间允许旧/新混合。
恢复逐文件只接受已记录旧/本次新/恢复摘要；外部漂移则保留pending拒绝覆盖。恢复旧业务目录内容时新修订递增，
先持久恢复快照和摘要，再替换并启动旧制品。业务状态不回写旧快照。

## 替代方案

仍让用户手工安装目录最少代码，却无法把env与目录绑定为同一候选或恢复。
把配置根改成整目录软链接可一次切换，但改变既有固定路径与私有权限合同，旧单配置实例需迁移。
引入通用配置事务引擎可管理更多文件，却超出本片两份固定文件和已有pending账本需求。
选原单配置事务加固定目录快照/摘要，不新增任意目标路径或通用远程执行。

## 后果

安装仍只管理AI-Ops、同Python/schema/零在飞，已启用目录不接受本候选流程；激活是后继受权任务。
旧pending由原同版安装器恢复，新两文件pending须新版恢复，不能交旧脚本而丢目录。
模板投影路径变化使旧计划过期，应重新预检导出；旧未安装候选包不自动改写。
`BindReadOnlyPaths`沿[systemd执行沙箱规范](https://www.freedesktop.org/software/systemd/man/latest/systemd.exec.html#BindPaths=)，
目录递增沿原schema2审计合同。正式主机权限、挂载、实际版本与恢复需现场验证；隔离检查不证明业务、网络或容量。
