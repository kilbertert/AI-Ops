# 62. 预检按渲染后的挂载判「同一份」；复跑材料入仓且只发一次

日期：2026-10-20
状态：已采纳
影响版本：`deploy/m2-live-03/checks.sh`（清单判据）、
`deploy/m2-live-03/stack_checks.py`（新增 `manifest` 子命令）、
`deploy/m2-live-03/compose.identity.yaml`（新增）、
`deploy/m2-live-03/identity.env.template`（新增）、
`tools/m2_close/m3live/live_replay.py`（新增）、`images.lock.json`（Gateway 内容摘要）

## 背景

两件事在隔离栈首轮实跑之后被独立复核指出（`REVIEW.md` 第 1、2 条）：

1. **预检假绿**。清单判据是 `basename(gateway_path) != basename(node_path)`。实测两种
   坏态都印 PASS：节点开关 `AIOPS_EXEC_MANIFEST` **缺失**、以及节点路径写成
   `/not-mounted/exec-manifest.json`（没有任何挂载覆盖它）。也就是说这条判据对
   「节点根本没在读清单」给出的是通过。
2. **复跑材料不在仓库里**。实际用到的 compose 覆盖层、构造身份注入、一次派发驱动只
   存在于临时脚本与会话记忆里；README 只写了「写清单 + up」。别人据此无法重来，
   而「恢复余额后随手重跑即可」这句话在当时没有可执行的依据。

## 决定

### 一、判据从「文件名」换成「渲染后的路径」

`checks.sh preflight` 把两侧配置里的**容器内**路径交给
`stack_checks.py manifest`，后者在 `docker compose config --format json` 的结果里
按 bind 挂载把容器路径解析成宿主路径（取最长 target 前缀，与容器解析一致），然后：

- 两侧都为空 ⇒ 未启用，通过（与启用前逐字一致）；
- 只有一侧非空 ⇒ 拒绝（单侧开启不是合法状态：开的那个会按漂移拒绝或按未启用放行）；
- 任一侧没有挂载覆盖该路径 ⇒ 拒绝；
- 解析出的宿主路径经 `realpath` 后 `(st_dev, st_ino)` 必须相同 —— **两个目录里各放一份
  同名文件不算同一份**；
- 文件必须存在、是普通文件、不是符号链接、非空、无组/他人权限。**0400 与 0600 都接受**：
  这是两个加载器（Python `execution_manifest` / Java `ExecManifest`）共同的契约，
  只认 0600 会把一个合法部署判成坏的。

判据与被测代码同源：两个加载器拒绝的正是「组或他人有任何权限」和「符号链接」，
预检照抄这一组，而不是另立一套。

### 二、复跑材料是最小的三层，不是一个框架

| 层 | 文件 | 只做一件事 |
|---|---|---|
| 覆盖层 | `compose.identity.yaml` | 把 Gateway 的入口进程换成 `identity_launcher.py`；只改 `env_file` 与 `command` |
| 键名 | `identity.env.template` | 声明三个键名；值只在宿主上的 0600 文件里 |
| 驱动 | `tools/m2_close/m3live/live_replay.py` | `baseline` / `send` / `collect` / `cleanup` |

三条由代码保证、而不是由文档要求的规则：

1. **握手令牌只从 0600 文件读**。不接受命令行参数（进 shell 历史与 `ps`）、不接受
   环境变量（会被任何子进程继承）。文件是符号链接或权限过宽即拒绝。
2. **不重试**。`send` 在同一输出目录里只允许存在一份 `sent.json`，再次发送退出 3；
   HTTP 失败也是终局 —— 写证据、非零退出。
3. **证据不外泄**。写盘前抹掉 `Bearer`/`sk-` 形状，并断言握手令牌不在正文里，命中就
   拒绝写。快照是业务正文：证据里只留摘要与键集合。

`cleanup` **不负责停栈**（那是 `checks.sh down`），它只回答「容器与端口是否归零、
生产面是否与基线逐项相同」。生产面基线缺失时它报「未比对」，而不是「未变化」。

### 三、观测缺口写进证据，而不是只在文档里

模型出口（`model_proxy.py`）只记录**拒绝与异常**，成功转发不留日志；节点也没有每轮
模型调用的日志。所以「这次模型请求了几次」在本栈上**没有观测依据**。证据里的
`model_request_count` 是 `{value: null, observed: false}` —— 错误日志的条数不是请求数
（一次请求可以打多行，一轮也可以在同一个连接上重试）。

## 被否的方案

- **只把 `basename` 换成 `realpath` 前缀比较**：能挡住「同名不同目录」，但挡不住
  「节点路径根本没有挂载」—— 后者返回的是一个不存在的路径，比较结果仍是「不相等」，
  而失败原因会被写成「两侧不是同一个文件」，掩盖真正的问题（没人挂载）。
- **让预检自己解析 `compose.yaml` 的 YAML**：那会在 Python 里复刻一份 compose 的
  挂载语义（相对路径、`~`、环境变量插值），两份实现迟早漂移。用 `compose config --format json`
  是让 compose 自己回答「这个容器路径落在哪个宿主文件上」。
- **在 `checks.sh` 里再写一份文件权限判定**：那就变成第三份判据。判据放进
  `stack_checks.py`（已有 `mounts`/`users` 两个同形子命令），`checks.sh` 只负责喂输入。
- **把「发一次」写成约定而不是检查**：实测里最省事的失败处理就是「再跑一次」。所以
  `sent.json` 的存在性是硬判据，而不是注释里的一句话。
- **让 `cleanup` 顺手 `docker compose down`**：停栈失败与清理失败是两个不同的结论，
  合在一起后「down 失败所以什么都没删」会看起来像「清理通过」。分工不变。
- **为「模型请求次数」加生产钩子**（在出口里计数、在节点里加每轮日志）：本片的目的是
  诚实，不是让缺口消失。加钩子会改 `tools/m2_live/` 与节点 Java，两者都超出本片边界；
  缺口以「未观测」的形式写在证据里。

## 后果

- 预检对「节点开关缺失 / 路径没挂载 / 同名不同物 / 符号链接 / 过宽权限 / 目录」六种
  坏态各自给出**不同的**失败原因，而不是一句笼统的「不一致」。
- 合法状态有正对照：0400 与 0600 都通过，且清单那一节写明两侧解析到同一个文件与摘要。
- Gateway 镜像内容摘要随 `tools/m2_close/m3live/live_replay.py` 进入构造上下文而更新
  （真构建得到 `778ff818…`，锁文件同步）。制品身份变化是**这次改动的一部分**，不是
  需要掩盖的副作用。
- 复跑者不需要会话记忆：模板 + 四个子命令就是全部输入。**整轮成功仍然未被验收** ——
  本片没有发任何真实请求，上游余额与供应商仍是外部门槛。
