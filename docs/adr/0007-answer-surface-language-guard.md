# 回答面输出语言校验的共享边界

Status: Proposed

系统面向用户的回答路径共 11 个，此前**只有标准诊断一个**有输出侧语言校验。同类缺陷
（提示词契约自相矛盾导致中文残留）因此第三次出现时才被当作新问题处理，而每次都在
不同面上——宣传卡片的中文小标题、诊断证据字段的中文枚举、快捷动作的缺翻译回退。
本决策把语言判定收口为单一实现，挂到各回答面的**定稿点**，并明确它证明什么、
不证明什么。

## Consequences

- **校验在输出侧，不在提示词侧。** 提示词是请求，不是保证。三次缺陷的共同形态是：
  提示词里"翻译 X"与"Y 保持原样"并存，模型**两句话都遵守**——这是契约歧义，不是
  模型失误。且它是**间歇性**的：同一提示词、同一输入，数分钟后结果可能不同（41 实拍：
  同一订单、同一 staged 输入，两次请求一次带中文一次干净）。改措辞无法闭环，必须有
  确定性判定兜底。

- **守卫的输入是契约，不是形状。** 判定收口之后剩下的失效模式是**调用方挑形状**：
  同一个 `blocks[]`，传裸 list 会落进一条形状盲的逐叶路径，既不知道 block 的 `kind`
  也不知道字段名，于是"资源名豁免"这一条正确实现在唯一需要它的生产面上走不到——一张
  好卡片被压成"知识库暂不可用"，告警却写着模型语言契约失守。因此守卫只接受两种值：
  定稿点自己的契约载荷 `AnswerSurface`（`blocks[]` 用 `from_public_blocks` 构造，无
  `blocks[]` 的面直接构造），或只以文本定稿的面传纯字符串。**其它形状是 `TypeError`，
  不是第二条判定路径**：形状错误不可能静默改变哪条规则来判这段回答。这是对本模块调用方
  的兼容性契约变更（`answer_chinese_leak` 的签名由 `Any` 收窄，`text_block_leak` 删除），
  由源码级守护封口：源码里枚举全部生产调用点，只接受上述两种输入。

- **共享件仅作判定，不作纠正。** 判定住在语言表旁边（`i18n.chinese_leak`），
  各面在自己的定稿点调用。各面的会话机制不同——诊断有合同修复回路与重试预算，
  宣传/问答没有——所以**统一的是判定，不是处置**。诊断走修复重试；没有回路的面
  命中即改发已本地化的兜底文案。为后一组新建重试编排是独立事项，不塞进本决策。

- **命中后不得改写 `retrieval_status`。** 泄漏恰恰发生在**检索成功**、模型把拿到的
  内容原样粘贴之时。把它标成 `unavailable` 等于对外声明"知识库当时不可用"——一个
  关于数据源的假陈述，会把运维视线从真实成因（模型语言契约）引开。这与既有原则
  一致：宣传路径的 `promo_empty_result` 同样拒绝把"无人检索过的库"称为"没有匹配"。
  成功与否由状态如实承载，泄漏原因由结构化告警承载。这条规则禁止的是把**成功的检索**改写成
  `unavailable`；它不豁免"`found` 却没有检索过任何分块"这类**证据主张**的纠错——一张被扣下的
  卡片与一张被送达的卡片对同一轮检索必须报同一个状态，否则卡片的兜底文案说"内容不可用"，状态
  却在声称有证据支撑一个从未发生过的检索。

- **兜底文案与告警分离。** 用户拿到的是已本地化的"暂不可用"，运维拿到的是含
  面/语言/字符数的告警。告警**不记录泄漏正文**：那是模型输出，但也是逐字源数据。

- **资源名按值豁免，不按字段放行**（豁免的完整条件见下一条：形态 **∧** 来源）。媒体与引用块的 `title` 依契约是**资源名**
  （媒体名 / 来源文档名），中文资源名是名称而非泄漏；翻译它会让回答引用的素材与
  知识库无法对应。豁免因此按**值的形态**判定（短、无句读），而不是"`title` 一律放行"，
  以免未来某个面借此开后门。正文块没有 `title` 字段，散文无法走到豁免。块引用的
  `resource_id` / `reference_id` **不**在豁免内：它们是交付给用户的载荷的一部分，中文的
  库方 id 一样会到读者眼前，而豁免是"这个 `title` 命名的是资源"这一判断，不是"这是个标识符"。

- **资源名豁免按"形态 ∧ 来源真实性"的合取判定。** 原先仅按值的形态豁免，于是
  "模型自造中文小标题"这一情形无法捕捉：`操作步骤` 与文件名一样短、一样无句读，
  形态规则接受它，中文就送到了英文读者眼前。本决策当时记录了这一点并写明闭合它
  需要**来源真实性**——把标题与本轮实际返回的分块比对（#376 已实现）。

  单独任一条都不够，两个方向各错一次：

  - **只看形态** 放行模型自造的短标题（`操作步骤`）——即上一条要闭合的情形；
  - **只看来源** 放行用句子命名的真实资源名，而本决策要求按**值的形态**判定散文。

  因此豁免的条件是**两者同时成立**：它看起来像资源名，**且**本轮确实检索到了它。
  三个方向据此分开：自造短标题→判为泄漏；真实短文件名（`新加坡无人电动巴士.mp4`）→豁免；
  句子形态的真实资源名→判为泄漏。引用块没有挂载描述符，故其 `title` 只按来源真实性一步判定。

  来源真相缺失时（无检索数据的定稿点）退回形态规则，不因此扣下合法资源名；生产调用方
  被源码级守护要求必须提供该来源，见 `tests/test_answer_caller_shapes.py`。

- **本校验证明"没漏中文"，不证明"译得对"。** 译文语义质量不可由模式判定。验收记录
  不得把前者冒充为后者。

- **原生多语言不在本决策范围。** 真正的原生多语言发生在**检索期或语料期**，前提是
  语料本身多语言。实测现状：知识库全部中文原生、无语言变体，且检索层**不支持按语言
  过滤**（数据集的 `language` 字段仅供展示、从不参与检索；分块无语言字段；
  `cross_languages` 是翻译查询词而非过滤结果）。因此原生多语言需业务方先提供双语
  原稿，翻译只能作派生物、不得替换权威源。
