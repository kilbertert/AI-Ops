# 241. 订单日志交付设备窗口候选，缺失原始报文保持缺口

Status: Accepted

日期：2026-11-10。用户批准三个反馈的方案实施；本轮只读核验发现当前无原始通讯历史可复原。

## 决定

工具只接受order_no，从已交付且当前授权的订单详情派生父设备、枪和时间窗。
通讯、桩事件、枪事件、桩调用、枪调用分别报告记录、空窗或不可用；
每源最多12条，总量60条、窗口24小时。入库时刻与事件/调用名仅为
`device_window_candidate`，不能据此认定本单交易或设备执行成功。

源事实来自tsdata f44ea003指定写入/查询源码及父会话的只读核验：无comm表，
MySQL日志表无记录，目标窗口事件为空，枪遥测存在。未知方向、code、decoded与正文
不查询、不透传；遥测不补造成原始报文。Gateway接线与缓存回读复核保持现有授权边界。

## 被否掉的替代形态

- 从枪遥测或历史回答复原原始日志：缺独立来源，会把推断包装成已取得的报文。
- 只保留父设备fi：已证实存在枪fi，父设备调用不能覆盖枪级调用，故纳入第五源并收紧单源行数。
- 透传decoded后交由模型判断关联：可能暴露同设备其他订单正文，且没有已确认交易关联合同。

## 后果

现有缺失历史仍不可用，空窗不证明正常；后续启用原始通讯持久化和正文交付须另核源合同。
