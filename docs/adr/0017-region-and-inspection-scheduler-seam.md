# 两条未实现的 PRD 条款的收口：`region` 不做、巡检接缝只写合同

日期：2026-10-12
状态：已采纳
影响版本：PRD #693（收敛其 User Stories 23 与 24）

## 背景

PRD #693 里有两条**显式决定**从未被任何子票承载，六个月后仍在原地。这不是"还没做"，
是**决定与现实之间的漂移**：PRD 写着一件本期该做的事，而仓库里既没有它、也没有一条
记录说"不做了"。本 ADR 把它们各自收敛成一句可复核的话。

两条都是**便宜**的（原 PRD 措辞就是"现在建字段"与"只留接缝"），所以真正要回答的
不是"值不值得做"，而是"**它今天做的到底是什么**"。

### story 23 · `region`：「现在建字段、本期只部署一个区」

原文（PRD Problem/User Stories 23）：

> 作为运维，我想 `region` 字段现在建、但本期只部署一个区，这样双区是"多客户 + 跨境合规"
> 的事，不是现在。

**它要防的是什么**：把区写死进代码/配置，等真要双区时发现处处假设了单区。

**今天的现实**（都实测过，不是推断）：

1. **公司自己的租户权威上已经有这个字段** —— UPMS `sys_organ.ops_country`
   （在 41 上 `SHOW COLUMNS` 读出）。PRD 已经定过「租户权威 = UPMS `sys_organ`，
   经公司接口取，**不读表**」。因此「建一个 region 字段」在**权威层是多余的**：
   第二份来源正是 PRD 反复要避免的形状（「不重演给一个已存在的权威再造第二份来源」）。
2. **但它是空的**：`SELECT ops_country, COUNT(*) FROM sys_organ GROUP BY ops_country`
   → `(None, 352)`。**352 行全部为 NULL。**
3. 我们自己的清单 `ops/environments/env-41.toml` 里没有任何 `region`。
4. 探索稿 `docs/TrendPower_AI_Operation_V1.0_Architecture.md` 把 Region 定义成
   **CN / SG 双区独立部署**：两套 API 网关、两套 Dify、「两个 Region 不要共享业务数据库」。
   那是一次**跨主机的部署形态**，不是我们仓里某个文件的字段。

## 决定

**一、不在 AI-Ops 侧另建 `region` 字段。**

理由不是"不需要 region"——双区确实需要。理由是**今天建它没有可写进去的值**：
权威是公司的、且全为 NULL；本机只有一个区；写一个常量或全 NULL 的列，
**不是"留了一个接缝"，是留了一个空壳**——它看起来像已支持，实际每一个读它的地方
都得再写一遍单区兜底。

**二、区这一维的权威已经存在，只是没被填充。**

真要开双区时，正确顺序是**先让公司填 `sys_organ.ops_country`**（那是租户属性，
公司与客户之间的约定），再由 AI-Ops 经公司接口**读**它。届时 AI-Ops 侧要加的是
**读取**，不是字段。

**三、触发条件（可复核，避免这条决定无限期挂着）。**

同时满足两条才启动：① 第二个区**真的要有自己的部署实例**（不是同实例多租户）；
② `sys_organ.ops_country` 有非 NULL 值。在那之前，本仓不引入 `region`。
如果到那时发现需要的是"区级部署标识"而不是"租户属性"，那是**部署形态**的问题，
落在运维清单（`ops/environments/`）与主机侧，仍然不是一张业务表上的列。

## 关于 story 24 · 主动巡检（Scheduler）

同一条判决，结论是「**不建调度器；把接缝的合同写下来**」——见下一节。

原文：

> 作为运维，我想主动巡检（Scheduler）本期**只留接缝**（同一个运维配方可被非用户触发起跑），
> 不建调度器与告警，这样不自造一个没人接的巡检器。

**现实**：`start_operations_analysis(context, *, site_ids, window_start, window_end, language)`
是公开方法，今天只有两个调用点，**两个都是 HTTP**（`POST /v1/standard/analyses` 与
点击 `operations_review`）。没有调度器、没有告警、没有非用户触发路径。

**为什么不再造一个"接缝抽象"**：能被非用户触发的入口**今天就已经是那个方法本身**。
再包一层（一个 `SchedulerTrigger` 协议、一个 provider 注册表）会得到
**一个没有第二个实现的接口** —— 而它要服务的消费者（调度器）不存在，PRD 自己也说
"不自造一个没人接的巡检器"。生成一个接口不是为了以后方便，是把成本提前付给了
一个还没出现、且形状未知的需求。

**接缝的合同**（这才是"只留接缝"能落地的部分，写给未来的调度器）：

- **入口**：直接调 `GatewayRuntime.start_operations_analysis(context, ...)`，
  不要另开一条 HTTP 路由。窗口由**发起方**给（服务端 24h 常量是**点击动作**的口径，
  不是这张面的口径）。
- **`context` 必须是真实解析出来的那个**：调度器要为谁巡检，就要构造**那一个主体**的
  `ScopeContext`（`caller`/`subject`/`effective_tenant_id`/`data_scope`），
  **不得**用平台身份代替 —— 否则巡检结果会比被巡检的人能看到的宽，
  而那正是本仓 #628 / #721 两次踩过的形状（把"未收窄"读成"全部"）。
- **归因**：作业行已经带 `scope_fingerprint`；系统发起的作业必须能由它反查到主体，
  因此"是谁发起的"不能丢。
- **本期不做**：调度器、告警、去重、并发上限、失败重试策略。它们各自的形状取决于
  真实运维节奏，现在定是猜。

## 后果

- **story 23 关闭**，触发条件写在上方，可复核。冻结的代价：真要开双区时，第一件事是
  推动公司填 `ops_country`，那一步有交付周期，应提前于部署排期，**不是**要我们现在埋字段。
- **story 24 关闭**（不建调度器），接缝合同写在上方。若将来证明"合同"不足以约束实现
  （例如调度器写出了与点击动作不一致的窗口语义），那时再引入代码级接缝**有据可依**，
  而不是现在猜。
- 两条都被本文档**显式**记录为"决定"而不是"欠账"，因此 PRD 与现实之间不再有一处
  无人认领的漂移。

## 被否掉的替代形态

### 关于 `region`

- **（A）在 AI-Ops 侧加一个 `region` 列 / 字段（PRD 的字面读法）。** 被否：
  今天**没有可填的值** —— 权威是公司的 `sys_organ.ops_country` 且 352 行全为 NULL，
  本机只有一个区。加出来的是一个**全 NULL 或写死常量的列**：它看起来像"已支持双区"，
  实际每个读它的地方仍要写单区兜底。留接缝与留空壳的区别是**有没有第二个值**。
- **（B）现在就经公司接口读 `ops_country`、在运行时携带它。** 被否：读了也全是 NULL，
  等于把"未填充"这件事编码进一条链路，而链路两端（我们 + 客户）都还没有值。
  等它有值时再加读取，是一次小改动，不是现在能提前付的成本。
- **（C）把 `region` 放进 `ops/environments/env-41.toml`（部署侧）。** 被否：
  单区时它是一个只有一个取值的常量配置 —— 而**一个永远只有一个值的配置项，
  是伪装成配置的常量**，不会带来任何可切换性，只会让"我们有区概念"这句话看起来成立。
  真到双区，那时的形状是**两台主机各自的环境清单**，不是一个清单里的一个字段。
- **（D）什么都不写，让它继续悬着。** 被否：这正是本 ADR 要终止的状态 ——
  PRD 写着"现在建"，仓库里没有它，也没有记录说不做。**无人认领的漂移**比
  "决定不做"更贵，因为它会在每一次盘点时被重新拿出来讨论一遍。

### 关于主动巡检接缝

- **（E）现在定义 `SchedulerTrigger` 协议 / 提供方注册表（"接缝"的字面读法）。** 被否：
  它会得到**一个没有第二个实现的接口**，而它要服务的消费者（调度器）PRD 自己说不建。
  为一个形状未知的未来需求先造抽象，是把成本提前付给猜测。
- **（F）现在就建调度器（cron / APScheduler + 告警）。** 被否：PRD 明确划在本期之外，
  且它牵扯的并发上限、去重、失败重试策略全都取决于**真实运维节奏**——现在定是猜。
  猜错的调度器比没有调度器更糟：它会开始写作业行，而那些行会被当成有人要的。
- **（G）什么都不做，把"接缝"理解成"已经有那个方法就够了"。** 被否——**部分否**。
  方法本身确实是接缝，但"只留接缝"若只当成"方法存在"，就会漏掉**唯一的真风险**：
  未来的调度器为谁构造 `ScopeContext`。用平台身份代替被巡检主体，会让结果宽于那个主体
  能看到的——正是本仓 #628 与 #721 两次踩过的同一形状。因此接缝要**写下合同**
  （入口方法、`context` 必须真实、归因不可丢），而合同是文字，不是代码。
