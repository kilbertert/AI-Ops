# 273. 显式配置摘要变更沿用安装恢复事务

状态：已采纳；扩展[ADR0272](0272-managed-gateway-install.md)中“配置不变”的首版限制，其他身份、schema与切流量边界保留。

## 决定

业务连接不能靠手改现役production.env接入。安装命令新增`--expected-config-sha256`，
配置变化时必须匹配安装账本和当前文件；未显式提供或版本过期在停服务前拒绝。
新配置核固定摘要后以0600原子保存到本次制品目录，候选独立状态/网络只读取这一份快照，现役配置不动。
候选通过systemd `BindReadOnlyPaths`在独立挂载命名空间把快照映射到正式配置路径，
保持环境目录的config_ref绑定；宿主原路径内容不变，不通过改写登记表绕过绑定。

候选通过后，零在飞/同schema检查仍照常执行。保存旧配置快照，先持久记录switching，
再原子替换现役配置及制品指针。失败或中断恢复时，仅接受旧/本次新摘要，先恢复旧配置再启动旧制品；
发现第三方改写则保留pending并拒绝覆盖。配置与制品是可恢复的两步，不宣称跨文件原子事务。
停服务前和正式替换前再次核对旧摘要；所有受管写入遵守同环境flock，非协作写入仍不能提供跨进程原子CAS保证。
配置中的外部文件引用须为已批准的固定版本；本片只冻结env正文，不声明递归快照所有依赖。

## 替代方案

- 手改配置再重启最少代码，但绕过摘要/候选验证，且恢复制品时仍留下新配置。
- 为每次配置变化创建另一实例能保留完整旧栈，但增加常驻资源及流量切换步骤，不是日常配置变更的最小路径。
- 通用配置服务可管理更多类型，却重复现有目录与安装账本；此处只补所需CAS与快照。

## 后果

复用原systemd、fsync/原子替换和pending恢复，不改服务unit、HTTP合同、业务数据或公司系统。
旧安装调用不传新参数时保持配置不变规则；安装器与应用仍要求同修订。
只有新安装器能执行新的配置事务，其pending须用同版安装器恢复，不能用旧脚本处理。
