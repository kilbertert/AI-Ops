# 103. 结果分类按区间判定，不按枚举；统计先筛事件再聚合

日期：2026-10-23
状态：已采纳
影响版本：`src/aiops_diagnostics/request_observation.py`、
`docs/agents/consumer-order-chat/observability.md`、
`docs/agents/consumer-order-chat/single-tenant-enable-change-ticket.md`

## 背景：一版枚举漏掉了 401，让凭据问题变成"服务故障"

ADR 0102 把请求结果分成 `completed` / `refused` / `failed`，并把"拒绝"写成一个**枚举**：

```python
_REFUSAL_STATUSES = frozenset({400, 403, 404, 409, 422})
```

漏了 **401**。而 401 在这条路径上生产可达：首次解析 `aiops:diagnoses:write` 成功，
`authenticated_chat_order_reader` 里的第二次解析 `aiops:orders:read` 返回凭据无效。
于是"某个用户的登录过期了"被记进 **5xx 分子** —— 那正是运维用来判断"网关坏了"的那个数。
独立复核在真实 API 路径上复现了它。

同一轮复核还指出统计命令的口径问题：手册直接 `grep -o 'outcome=...'`，
而网关 journal 里知识审计也写 `outcome=`、Dify 试运行也写 `duration_ms=`。
合成混合日志实测：本片 1 条结果被报成 2 条，10 ms 被报成 10/9000 ms。

## 决定

### 1. 分类用区间，不用枚举

```
任何 4xx → refused（我们说不）
任何 5xx / 逃逸异常 → failed（出错了）
2xx → completed
其余（如 3xx）→ failed（这条路径不该产生，让它显形）
```

枚举的错误模式是**漏项**，而且漏了不会有人知道 —— 它默认落进 `failed` 而不是报错。
区间没有"需要记得补一个"的步骤。测试因此钉的是**边界**（401/429 是拒绝、5xx 不是），
而不是某个集合的成员：钉成员等于把"清单是否完整"这件事交给写测试的人再猜一次。

### 2. 统计先筛事件，再聚合

所有汇总命令的第一步是筛到本片自己的事件（`assistant_question_result`）并固定观察窗口，
之后才允许碰字段名。原因不是"命令要好写"，而是**同名字段在同一个 journal 里本来就有多份
来源**：一旦先按字段名聚合，混进来的是别人的业务日志，而输出看起来完全正常。

配套三条：

- 目标租户过滤**只用于汇总**；「未登记租户」告警必须**全租户**查 —— 加目标租户过滤会把
  这条告警整条吞掉，那个"有别的租户在用就停"的停止条件于是永远不会触发；
- **读取失败 / 零样本 / 有样本**三种状态分开写：读不到日志不是"没有行"；
- 少于 20 条样本只报计数与极值，不报 p95 与百分比。

### 3. 归因需要真实关联键

`agent_run_metrics` 与 `gateway/runs/` 都**没有 `qa_id`**。所以"同租户同秒出现了
`routing` 行"**不能**证明是这一条状态查询调用了模型 —— 共享网关上的普通问答会在同一秒
写同样的行。按那个口径设停止条件，会把别人的正常问答记成本片事故并**误停用**。

只有某个 `qa_id` 在两侧都能对上，才允许说"落回了模型"；对不上就写「待核实」。
**不新增全链路追踪** —— 那是另一片的范围，而这里只需要不误判。

## 被否掉的路线

| 路线 | 为什么不行 |
|---|---|
| 保留枚举，补上 401 | 补一个还有下一个（407/408/413/429…）；错因是"靠人记得补"，不是"少了一个" |
| 把 401 单独归成第四类 outcome | 变更单的分母是"拒绝 vs 失败"两类；多一类会让每个停止条件都要重新定义一次 |
| 统计时用 `--grep` 交给 journalctl 过滤 | journalctl 的 `-g` 匹配整行任意位置，同样会命中别人的行；显式筛事件更可控、也可在导出的日志上复跑 |
| 给 `agent_run_metrics` 加 `qa_id` 列 | 那是改指标存储与保留期语义，超出"不扩大功能"的边界；先做到不误判 |

## 后果

- 401（以及任何 4xx）不再进入 5xx 分母；`test_every_4xx_is_a_refusal_and_every_5xx_is_a_failure`
  与重认证 401 用例钉住它，把判据改回枚举缺口会让 2 条测试转红；
- 统计命令在同一份混合日志上得到 1 条结果行、`outcome=completed` 1 条、耗时 `10`；
- 变更单的模型调用停止条件改写成"有关联键才归因，否则待核实"，并写明仍判不了的三项。
