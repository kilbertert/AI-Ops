# 268. 发布身份使用活动登录绑定

Status: Accepted（执行已确认P1会话收敛任务）

旧发布身份检查仅验签与映射，退出只撤销令牌交换缓存，造成同一会话在管理与发布入口的有效性不一致。
复用LoginService现有内存会话绑定：每次正常登录都登记会话哈希、到期、公司用户/租户，只有配置令牌交换时保留公司令牌。
发布检查和operator-token共享验证入口，正常登录之外的签名会话、跨实例、退出、到期、disabled或映射错配均拒绝。
不增数据库或第二个会话目录。登录代理重启会丢失活动绑定，需要重新登录；首次部署前明确这个影响。
原Dify退出按钮仍用`/console/api/logout`，现有同源代理将其送入登录服务：先校验完整会话/CSRF，撤销本地绑定，再调用固定Dify原生退出；上游失败返回未确认且不复活本地绑定。
公司权限及成员快照仍沿原合同，不把活动会话等同所有公司撤权实时刷新。

替代方案：维护独立发布撤销表会重复状态；仅验JWT签名不能证明当前环境曾完成登录；持久化公司令牌超出本片需要且增加秘密存储面。
[RFC8725 §3.8–3.12](https://www.rfc-editor.org/rfc/rfc8725.html#section-3.8)映射为环境绑定与互斥入口验证，
既有JWT结构不变。本决定替代ADR0024中无活动绑定的会话判据，保留其发布授权和审计分工。
