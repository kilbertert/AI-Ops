# 249. 运行日志投影扩展至问题、订单号与执行明细

Status: Accepted

ADR-0242 批准的日志白名单只含运行元数据，明确排除了问题全文、订单号与失败原文。
上线后用户反馈详情页过简，无法支撑排障；用户明确批准拓宽为「执行元数据 + 问题全文
+ 绑定订单号」这一层，业务结果内容仍不投影。本 ADR 修订 0242 的输出白名单，授权与
时效约束不变。

## 扩入的字段

同一 `agent_runs` 记录与同库 `assistant_questions` 上已有的数据，不新建账本：

- `question`：问题全文。经同一只读连接按 `qa_id + scope_fingerprint` 批量读取，
  不走 `get_assistant_question` —— 它顺带做过期收敛，是一次写，会破坏只读判据。
- `order_no`：运行绑定的订单号（未绑定为 null）。
- `reason`：终态原因。账本该列只存机器码（拒绝/失败/撤销码），投影限长 128 字符，
  覆盖最长合法组合 `operator_node_failed: tool_refused:<80>`（115 字符）；
  「无失败原文」约束解释为无自由文本，原因码不在此列。
- 执行定位：`expected_node_id`、`actual_node_id`（不一致由前端标注）、
  `environment`、`language`、`agent_version_observed`、
  `agent_version_gap`、`claimed_at`、`completed_at`、`expires_at`。
- 结果关联：`result_sha256`（对照用指纹，不还原结果）、`trial`、
  `history_run_count`、`evidence_tools`。
- trace 事件新增 `detail` 字段：拒绝/复核/终态事件携带机器码（`record_trace`
  白名单同步扩入，存储层截断 64 字符兜底）。

两个投影口径经独立 Hack 修正后另行记录：`trial` 的权威判据是
`chat_binding` 的 `operator-trial:` 前缀（快照 `trial` 键只在完整快照写，
失败与部分快照没有）——绑定串本身不投影，它是内部标识不是排障信号；
`evidence_tools` 只投影仍在工具声明集里的键名——死 run 取证路径（节点回调
终局吸收）的 evidence 键来自节点上报，不是本进程校验过的常量，逐字投影会让
已认证节点往管家日志塞任意文本。

附带的已知口径：`evidence_tools` 是「终局快照证据图里声明集内的键名」，
不是「本进程实际调用过的工具」——死 run 取证吸收的节点上报同样会进键名，
这是取证语义的如实呈现（收下不等于核实），不单独标注。

## 备选方案

- **只在详情投影新字段、列表保持原样**：被否——列表是排障的第一眼，没有
  问题/订单号列，定位到目标运行只能靠逐条点开。
- **投影自由文本失败原文**：被否——0242 的核心边界，失败原文可含上游正文
  与模型措辞，拓宽到机器码（reason/detail）已能回答「为什么停」。
- **投影 chat_binding 原值**：被否——它是内部 app/agent 标识不是排障信号；
  试用判据只需其 `operator-trial:` 前缀，服务端派生 `trial` 即可。

## 仍不投影

答案与证据 data、工具参数、凭据、`scope_fingerprint`、内部 app/agent 标识、
快照原文、自由文本失败原文。详情不调用 `authorize_readback`；业务结果过期后，
问题与订单号仍在日志中可见 —— 这是本次批准的明确取舍：它们是排障所需的**输入**
标识，不是有交付时效的**结果**。

## 后果

列表新增问题与订单号列；详情分块展示终态原因、执行节点、时间线（领取/完成/过期）、
版本核对、结果指纹、证据工具与逐事件拒绝码。旧前端对新字段无害（忽略未知键），
新前端对旧后端逐字段兜底「未记录/未采集」，Gateway 与 web 补丁可分别发布。
`detail` 由同进程 `_trace` 写入、`record_trace` 白名单同步放行，无跨版本读写；
旧账本事件没有该键时详情不显示原因行。
