# WF01发布不要求另一场景的节点目标

日期：2026-10-25
状态：已采纳

## 背景与决定

生产已有同租户本人订单节点路线。新增独立WF01应用时，发布入口却按租户读取旧节点行，
将新应用没有节点目标误判成`NODE_TARGET_MISSING`。两个场景的正式键不同，旧路线是恢复依据。

已声明consumer_service发布目标时，不执行旧节点路线的缺目标判定；仍保留同应用已有旧场景
时的`CONSUMER_ROUTE_MIGRATION_REQUIRED`，以及同应用两类目标冲突判定。
旧节点自己的发布仍必须具有节点目标。只修复发布守卫，不改变运行优先级、鉴权或旧行。
复用ADR-0138的发布内容快照与既有场景键，不新增跨系统协议。

## 备选方案与后果

- 删除旧节点行再发布：丢失恢复依据，且可能使旧请求错误回落，拒绝。
- 给新WF01伪配节点目标：同一应用两种引擎冲突，拒绝。
- 全部取消缺目标守卫：会放过旧节点自身的半配置，拒绝。

回归先真实建节点版本，再经发布API发布WF01并提问取得审核答案，前后旧路由逐字段一致。
旧节点缺目标及同应用跨场景两条负例仍拒绝；恢复旧错误判定的变异被检出。
