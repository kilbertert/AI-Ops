# Dify执行地址与回调凭据使用各自契约

日期：2026-10-25
状态：已采纳

## 背景与决定

真实WF01验收暴露两处部署缺口：管理绑定未在启动时校验远端HTTPS，客户端构造时才失败；
随后Dify知识HTTP节点经过App代理，原一次性凭据被替换成服务令牌，取数返回GRANT_UNKNOWN。
出站凭据摘要与签发行相符，失败发生在代理层，不能降低网关取数守卫。

配置有Dify执行地址时统一调用既有canonical_gateway_url，保持回环HTTP测试支持。
知识回调用精确POST location保留Authorization，并清空用户会话、入口及来源密钥。
复用Nginx官方ngx_http_proxy_module的请求头覆盖与无URI proxy_pass语义；不新增授权规则。

## 备选方案与后果

- 放宽执行客户端允许远端HTTP：削弱既有传输约束，拒绝。
- 让回调接受App服务令牌：丢失一次请求的授权范围，拒绝。
- 整片internal路径透传：扩大不必要的入口，拒绝。

真实Nginx验证精确POST凭据透传、身份头清空、方法与子路径拒绝；启动测试覆盖普通和管理绑定配置。
生产验证使用已撤销凭据，只证明运输层未换钥，不触发取数；业务成功仍须原页面独立验收。
