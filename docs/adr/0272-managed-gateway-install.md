# 272. 最小接入模块独立安装与有界恢复

状态：已采纳，承接P3；安装成功不等于目录激活或业务验收。

## 决定

复用Gateway离线制品和归档校验，只管理`aiops-access-<environment>`单位及同名自有目录。
既有服务身份、受管目标和端口由部署计划确定，不自动改公司服务、旧Gateway、账号或公网入口。
目录只接受首次全新创建或带安装账本的本工具实例；相同制品/配置重跑先读回运行身份，不重启。

首版升级只支持配置和Python不变、同schema且零在飞任务。候选以独立状态根启动，
停止当前自有单位后二次检查并备份状态，切制品后核主进程持有的监听socket及health版本。
失败恢复旧制品并复验；不自动恢复SQLite快照覆盖新数据。配置漂移、schema不兼容或恢复失败保留现场。
原子写入并fsync的pending区分准备与切换：中断后必须recover，不能继续另一个安装任务。
冷安装失败先确认本次单位停止，再移走自有目录保留恢复资料，允许从干净位置重试。

## 替代方案

- 直接参数化95安装器能复用切换代码，但其合同是停止旧实例并收养历史路径，不能满足新环境独立安装。
- 只启动临时预演更少代码，但没有重启持久性、幂等与中断恢复，不能成为P3安装基础。
- 同时支持任意schema/配置迁移能减少后续手工步骤，但需要额外兼容性协议与配置版本治理，首片明确拒绝。

## 后果

用[systemd service](https://www.freedesktop.org/software/systemd/man/latest/systemd.service.html)管理非登录身份、
资源与重启，用原子文件替换及目录fsync记录切换边界；flock保证同环境安装互斥。
本地检查用真实文件与SQLite、主机命令替身；目标systemd必须再实测，不能把替身当现场验收。
无法确认停止时不删除现场；停机窗口仍可能拒绝用户请求，因此正式切换须由后续预检/任务协调。

**后续补充（2026-11-25，受管前向 schema 升级）**：当 `gateway_schema.VERSION` 前向递增（如 ADR-0337 的 `2 → 3`）时，
受管升级允许对已知可迁移旧库执行「候选目录 `.backup()` 演练 → 停服落地 root 持有校验备份并写入 `pending.json` → 单事务前向迁移」；
同 schema 升级仍不覆盖状态库。若前向迁移后新服务启动/健康失败，`recover` 在留存失败库副本后，仅在校验 `pre-schema-gateway.db` 摘要一致且版本匹配时恢复该停服备份，
随后仍以旧制品严格复核数据库并启动旧服务；降级与未知版本漂移仍 fail-closed 拒绝。
