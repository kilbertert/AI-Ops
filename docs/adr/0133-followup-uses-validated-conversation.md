# 133. 未解决反馈沿用已验证的会话

Status: Accepted

## 决定

原App的明确未解决反馈（如“还是不行”）需要原问题才能检索；仅传这句话会丢失业务主题。
使用同主体、同会话的上一条成功QA，重用现有最终放行校验（绑定/内容摘要/TTL/正文一致）。
本轮检索上下文保存主题及连续未解决次数，不建立另一套客户端计数或新的会话存储。
读取前后都验证所用前轮仍可交付；拒绝过期、取消、失败或改绑的前文。

第一条明确未解决反馈检索原主题并询问当前步骤与错误提示，避免复述同一操作。
第二条及之后在原API返回受控人工渠道，不再启动模型或知识检索；不声称已经转接或建单。
新主题、新会话重新计数。模型不能覆盖这条边界。

## 取舍

不使用模型推断的失败次数，防止把一般咨询误当失败升级；首片只识别明确的中英文未解决反馈。
隐含反馈仍由Chatflow处理，不能声称已穷尽自然语言表达。沿用Dify会话协议、JSON上下文与
原API clarification形状，没有新的外部协议；人工渠道仍仅来自已审核配置。
