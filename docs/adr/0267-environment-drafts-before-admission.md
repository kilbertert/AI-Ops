# 267. 环境配置准备先于业务准入

Status: Accepted（执行已确认的手工目录规划，P1基础片）

现有目录写入立即改变业务准入；新环境尚未安装时，不能把管理员保存表单等同启用。
目录JSON继续是生效关系与管理授权的唯一来源，草稿放同私有目录的SQLite账本，复用同一目录锁和数据库事务原语。
保存携带目录revision与草稿revision，锁内重新核权；草稿记录依据版本与内容摘要，运行服务只读取生效JSON。
没有部署/预检回执的草稿不提供激活入口；现有名称/准入启停接口仍按原合同立即生效，页面迁移时明确区分。

管理准备引用允许控制实例管理空目录，但不启用目标业务准入；若同时配置运行目录，两者必须同一路径。
受管CLI可在空目录授予正常控制环境主体`environments:["*"]`，这是显式全局目录权限，不从公司平台角色自动推定。
已有按环境授权保持原范围；浏览器不能修改管理员，也不能提交配置文件路径或秘密正文。
部署/凭据仅保存逻辑引用，未知引用的实际验证留给开通预检；草稿保存不发网络请求。

替代方案：直接保存生效目录会让地址变更立即影响在飞业务；把管理引用设为另一权威目录会再次产生漂移。
SQLite短写事务与目录版本检查沿用[SQLite事务](https://www.sqlite.org/lang_transaction.html)及本仓CAS合同，
不声明JSON和远端部署具有跨系统原子性。本片不改旧publish/check的撤销窗口，也不将其当作新草稿身份入口。
