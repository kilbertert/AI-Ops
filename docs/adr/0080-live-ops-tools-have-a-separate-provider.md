# 真实运维工具使用独立提供方

状态：已采纳

`aiops-ops` 执行 `charging_info` 和 `order_list`；旧 `aiops` 继续仅返回说明。
两者使用独立凭据，新能力不是旧七工具中两项的改名，不按数量推导旧工具退役。
本决定仅扩展新路径，ADR-0019 对旧说明端点的无业务数据属性继续成立。

新建provider后通过同payload的官方update清理同名旧凭据缓存；这一步仅作用于本次新建对象，
不改变已有provider重复登记的零写契约。Dify 1.17.1缓存按workspace/名字存24小时，
删除再创建不会失效；已实测旧掩码保持、update后切到新掩码。直接清Redis或重启平台扩大范围，故不采用。

## 备选方案

- 原地替换旧 provider 的同名说明工具：会让已有调用方和共用凭据获得新的业务读取能力，
  也会混淆旧七工具与新两工具的关系，因此采用独立 provider 与凭据。
