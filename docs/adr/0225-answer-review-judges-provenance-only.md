# 225. 答复复核的 verdict 只判出处：充分性判定移出模型判据

日期：2026-11-05。

Status: Accepted（PRD #1380 第三步 #1382 合同清单 C5，用户确认方案后实施）。

`operator_answer_review` 的 verdict 判据原写「该判定只核对其他业务事实」，
其中「缺证不得判通过」把**论证充分性**交给了模型逐次判定——同一段答复，
这轮说证据够、下轮说不够，合法答复被合同拒的样本就出在这里（判据误拒是
历史成功率 26% 事故链的第一环）。充分性是不可逐次核验的判定，放给逐次
语义的模型就是无解合同。

决定：verdict 判定对象收窄为**凭空断言**——答复断言的事实、金额、状态、
计算关系必须能对应到本轮证据或历史记录。字段含义说错、把空记录说成无
资格、把账务记录说成到账、局部算术相符说成整单无多收、声称执行过未做
的操作，都是凭空断言即 reject；明说缺证、只给可能性、建议人工核查或
无法确认是 allow。不复核「论证够不够」——那是 INSTRUCTIONS/SOP 对生成
侧的要求，不是复核层能逐字核验的对象。

剥掉充分性判定后复核层剩下它真正能做的事：出处核对。逐字可核验的部分
（币种/站名摘录的成员判定）本就由 `known_facts` 程序核对兜底，模型只
摘录不裁决——这一半不动。

`SYSTEM` 文本改写即合同改写，`REVIEW_VERSION` 随 SHA256 自动轮换；
判据仍是逐次语义（同题可异果是模型判定固有属性），但判定对象从
「够不够好」变成「有没有凭空引用」——后者是可满足判据。

## 备选方案

- 保留「缺证不得判通过」再补一条「明说缺证除外」：例外叠例外，判据
  仍要模型权衡充分性，只是更难满足，否决。
- verdict 也改程序判定（正则扫断言词）：断言与证据的对应关系不是字面
  模式，正则只会把「解释上次结论」这类合法引用一起误杀，否决。
- 连凭空断言也不复核、只留币种/站名硬检查：写操作/日志/到账这类凭空
  声称没有字段可摘录比对，撤掉 verdict 等于放开最大风险面，否决。
