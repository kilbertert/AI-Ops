# 134. WF01实时订单查询是单轮授权

Status: Accepted

## 决定

复用已有CPMS充电状态接口和本人订单授权；consumer_service绑定显式配置live_order_status后，
只有明确本人订单状态问题才建立实时轮次。网关按本人SQL选最新单或验证指定单，验证orders:read，
将单号冻进本轮run和grant。Dify的HTTP节点只取这一单，客户端/模型不能重定向。
知识回调兼容既有空单号知识用途；实时轮次不检索FAQ，只交同轮CPMS快照。

外部读取前后、worker落正文前、历史正文回读都用既有授权器再判归属，并检查取消/TTL/绑定。
模型返回realtime类别后，网关渲染原状态快照，不接受模型生成订单事实。
实时轮次不接续Dify历史，下一轮也不继承其实时上下文；Gateway会话与逐QA回读保留。
避免旧实时数据进入后续模型输入，代价是跨实时轮次不保留上游模型记忆。

## 替代方案

不让Chatflow失败回落节点或直读，不增加第二次模型循环；不从订单状态推测支付/退款。
不使用整租户工具凭据，沿用单轮grant。单纯保留Dify记忆会让后续非订单请求暴露已撤权的旧数据。
协议沿用CPMS、Dify HTTP节点及原App接口；权限遵循现有orders:read与本人范围，无新增写能力。
