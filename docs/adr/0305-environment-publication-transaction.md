# 305. 正式开通沿原发布器与安装账本执行可对账事务

Status: Accepted（2026-11-22，用户批准多环境完整主线，D41/D42依赖后接完整P4）。

## 决定

环境任务保存已核验证、内容与目标前驱，中央只负责共享应用发布和精确运行凭据，目标消费冻结内容
写原AgentStore不可变版本与route CAS，最后由原root安装器事务推进配置、目录与installed账本。
不在中央假装切目标路由，不向目标复制Console/共享KB管理密钥。已选能力证据不足不执行正式动作。

网络/身份/容量由固定实际端点与运行事实产生，业务语义确认保留可核来源；页面不能填写passed替代。
原候选与正式内容间的接线转换记录精确差异，准入前验证实际正式读取链。凭据只在私有工件中传递。
跨系统步骤先保存意图；未知发布/安装仅按原对象与摘要对账，不能反复POST创建或无条件回滚数据库。
原任务承担逐端部分状态，恢复原指针也推进新revision并实时核撤权，保留已发布内容和业务运行证据。

## 备选方案

把enabled置true最少代码但绕过资源有效性及installed摘要；目标复制管理员key便于复用本地SelfService，
却扩大权限；新建通用工作流/发布数据库会重复原真值，均不采用。复用现有内部本机HMAC与受管安装入口，
兼容原本地发布调用；普通用户入口继续正常身份→LLM/SOP→受控工具，不加关键字路由。

## 标准与后果

原Dify发布/导出协议、RFC6750 Bearer与TLS、原CAS及目录单调修订是具体合同；不声称跨平台原子提交。
更新目标运行配置可能重启自有Gateway，需要明确零在飞维护窗口；开发完成不授权现场grant、发布、准入或重启。
版本、部分生效和恢复点必须页面可见，失败后由同一任务对账，不删除未知资源伪造回滚。
