# 整体退役 Python Thin Harness，保留独立运维入口

Status: Accepted

2026-10-29。本轮用户明确：旧执行器可以整体退役，C端检测和管家/Dify 试用应走各自业务路线；
诊断/设备 CLI 无业务用途。用户另行确认保留独立运维入口。此决定替代 [0157](0157-remove-unused-diagnostic-config-aliases.md)。

## 决定

删除旧模型循环、工作区、恢复、诊断取证、标准诊断/设备 HTTP 面和 CLI/便携交付。
C端检测接入自身工作流的本人状态分支，管家使用公司授权 Java 节点；草稿试用按已登记应用执行。
没有业务绑定时明确拒绝，不回落旧 Python 或通用问答。`aiops-admin` 保留开户、发布和知识管理。
共享权限/存储/健康能力保留；单次模型请求复用既有有界 HTTP，不保留 Codex 依赖。
先完成模块清理，目录迁移后置。

## 被否掉的替代形态

- 因源码仍有调用而保留整条旧链：可少改调用方，但违背用户确定的架构路线；旧调用应被删除或改接业务入口。
- 把旧代码移进 legacy 并保留回退：方便暂时兼容，但旧依赖和权限面仍存在，不能算退役。
- 连同管理 CLI 删除：入口更少，但用户确认开户/知识/发布运维仍需要它，故改为独立入口。
- 本轮同时迁移全部目录：可以立即改善导航，但会把大量路径变动混入行为退役，按用户顺序延后。

## 后果

旧接口返回 404，旧命令和 Python 导入消失；调用方须使用当前业务入口。C端检测不再提供旧多源因果报告。
既有数据库与证据不删除；新库不创建设备专属表，分析/试用沿用原任务存储。
生产切换、依赖更新、旧适配器停止需要对应制品和验收，本次未执行。
