# 300. 已安装候选登记独立续接，失联只读对账

状态：已采纳。接续[原P4规划](../architecture/2026-11-16-manual-environment-onboarding.md)与
[安装任务](0296-persistent-candidate-installation.md)，不改变安装成功不等于开通的含义。

## 决定

登记任务消费成功安装的工件身份，另取输入摘要相同的新鲜计划授权本轮操作；原安装窗口过期不要求重装。
页面不能传资源编号、部署路径或秘密。复用environment_tasks、installation_claim与原环境互斥，
远端仍以固定安装器持同一环境锁，调用原工作区和双端三行同事务登记。
任务到期前才允许首次写；先存意图，之后只读核对既有登记，缺失或部分冲突不自动补写。
未派发且观察确认不存在可安全终止并释放互斥；已派发且结果未知仍待核对。
已派发后的管理撤权或草稿变化只阻止新写，不阻断执行端对原冻结目标的只读恢复；
读取管理结果仍须当前权限，不能通过恢复把旧权限交还用户。

沿用[SQLite事务](https://www.sqlite.org/lang_transaction.html)与
[RFC 9110 §9.2.2](https://www.rfc-editor.org/rfc/rfc9110.html#section-9.2.2)：
POST本身不保证幂等；唯一任务绑定冻结输入，外部调用不持数据库写锁。
登记在原短写事务完成，观察以mode=ro和读事务核同一快照，不通过创建器修复权限或迁移schema。

## 替代方案

安装后自动登记省一步，但会扩大已批准安装任务的副作用，且旧成功回执会含混；保留显式续接。
失联后重跑幂等登记能少写观察代码，但会把“此前未写”变成“恢复时补写”，越过取消或到期边界。
要求所有步骤同15分钟计划简单，却让已成功安装因正常审批等待而重复重启；仅同摘要续期授权更合适。
另起队列或部署服务不能改善原安装事务，反而多一套锁和恢复来源，故复用原领取入口。

## 后果

应用与安装器须配套支持只读登记观察（1.35.0起），旧安装记录仍可读，新任务在旧版目标明确拒绝。
需先部署控制Gateway与执行端，再更新桥/Web；旧执行端遇新动作在stage拒绝且不产生远端写。
登记不重启、不生成正式密钥、不启用租户；回退代码保留候选记录，不用恢复数据库覆盖后续证据。
业务、网络、容量、身份验证及正式激活保持原完成条件。
