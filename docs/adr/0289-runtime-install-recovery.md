# 289. 运行工件沿安装事务切换，登记与激活另行验收

状态：已采纳；接续ADR0288和ADR0280。读者为部署工程师，解释运行工件的恢复边界。

## 决定

原固定安装器接收同plan/digest的D30运行包和三文件停用候选，核外层/成员摘要及复合归属。
原基础候选仍拒绝运行接线；运行包只增加两个固定配置引用，不开放任意安装路径。
运行文件保存在本次release下的私有快照，配置根runtime指针指向该快照；安装账本记录摘要和所属release。
隔离候选挂载完整候选配置根，其runtime指向新快照；不向现役指针或状态写运行文件。
候选通过后在停服窗口切配置、目录、运行指针和制品；pending记录允许旧/新混合，恢复只接受已记版本。
恢复运行指针和旧配置，不还原旧数据库快照，目录恢复继续产生新revision。
安装器不登记应用、不发密钥、不发布路由或启用租户；已安装资源的试运行和激活由后继受权流程完成。

## 替代方案

直接把成员逐份复制到现役目录可以少一个指针，但中断后不清楚哪些成员已换，也易把旧数据库备份
误当登记回退；选择不可变字节快照和一个受管指针，复用已有pending恢复。
把所有运行资源放入数据库可获得单事务，但当前发布器和节点已读取固定私有文件，不引入新持久化格式。
直接挂载runtime子路径最省代码，但现役路径可能为指向旧快照的符号链接；完整候选配置根让新快照的
解析路径明确，也不需要在宿主提前建立候选挂载目录。

## 后果

配置/工件漂移被拒绝，同内容重复不重启；旧单配置和三文件输入保持兼容。
成套切换仍不是跨文件原子；中断须同版安装器recover，旧快照保留作恢复点。
只证明私有运行配置已安装，不证明应用登记、消费者回调、知识内容、真实模型和三项业务可用。
