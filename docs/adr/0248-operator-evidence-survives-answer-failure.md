# 248. 管家答复失败保留可授权证据，诊断完成与结果交付分开

Status: Accepted（2026-11-12用户明确选择“保留诊断，失败时交付证据”）。

截图4笔失败均为OPERATOR_MODEL_OUTPUT_UNSTABLE；3笔有阶段记录且业务取证成功，
回答复核两次拒绝后整轮失败。既有模型复核还实测放行“订单结束即无异常”，
因此调宽判据或增加盲重试不能提供可靠交付。

正常模型诊断保留。对复核拒绝/不确定/不可用及已取证后的模型失败，程序只呈现本轮
已授权原记录，并明确诊断未完成；无证据或权限/发布/取消失效不能转换成功。
此决定有限更新ADR0218/0219/0225的“拒绝不交付”：不交付的是未经核实的模型正文，
不应连同已取得的来源证据一并丢弃。原来源值不进行二次计算；受控核验工具的输出注明来源。

复用既有QA结果blocks与运行账本，无新状态机或存储；completed仍指结果可交付。
新增delivery_mode及固定复核原因元数据，让日志区别证据交付与正常答复。历史不补写，
无原记录不推断拒绝原因。no-store沿用RFC9111，来源JSON按RFC8259转义并有界展示；
权限仍按原运行身份和当前范围授权，输出方式不产生数据访问权。

## 备选方案

无条件放行回答会泄露错误断言；无限/同输入重试增加延迟而不能保证纠正；
全改成程序事实会取消管家分析能力，用户本轮未选择。保留模型诊断意味着任意语义
准确性仍不能用单次复核证明，真实反例与产品验收继续独立记录。

验收见[证据交付合同](../agents/operator-cpms/evidence-delivery.md)。

真实Java整链注入仅message的HTTP500发现：SDK对缺少type字段的访问会再次抛异常，
错误分类器因而中断原错误回调，运行等待到120秒。对可选code/type读取捕获
OpenAIInvalidDataException并回退普通model_failed；不猜额度、不吞原失败。
节点JAR与Gateway/前端配套交付，真实Java反例必须从失败转为及时终止及证据回读。
