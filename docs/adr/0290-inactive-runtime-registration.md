# 290. 目标运行登记沿原账本事务，正式启用另验

状态：已采纳；接续ADR0289。读者为开通和运行工程师，说明目标资源登记与准入的区别。

## 决定

固定安装器增加register-runtime，仅在同修订现役实例、零在飞、无pending且工件/配置一致时执行。
以原服务身份调用aiops-admin，读取固定安装目录的停用运行快照，不允许调用者选择其他数据库或资源。
沿原dify_workspaces和operator_apps登记已创建工作区与管家/客服应用；一份短SQLite事务写三行。
原register可复用传入事务连接，默认自行持租约的旧开通调用保持，不在事务内再开第二个写连接。
工作区状态为created；不标ready，不创建Agent版本/路由/密钥或开启业务准入。
已有完全相同三行只回读；任何部分记录、归属/能力/版本冲突拒绝，不修复或覆盖未知资源。
登记事务前后核输入，安装器和登记共享环境锁。失败回滚本批，已有状态和证据保持。

## 替代方案

直接调用三个既有公开写方法最少改动，但每个方法独立提交，第二端失败会留下工作区和第一端。
把登记塞进安装恢复能减少一次命令，却把文件指针恢复和运行数据库回退混为一体；选择先安装后登记。
复制中央数据库能复用资源映射，但把41身份和运行路由带到目标；只从目标已核验工件登记指定复合主体。
新建注册表容易标记候选，但现有应用目录和正式路由已分离，created工作区足以表达准备状态，不增加schema。

## 后果

目标节点清单可从原应用登记读取，现有能力上报入口和发布器无需另一份可编辑映射。
普通业务仍被停用目录拒绝。登记不证明共享资源当前状态、回调、知识内容、正常身份或三业务已验。
本片不提供自动删除登记：资源必须保留对账，恢复或更换已登记工件需另核现役登记及发布状态。
