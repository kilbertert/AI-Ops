# 177. 站点查询一份实现，三个入口

日期：2026-10-30
状态：已采纳（设计定型，尚未实施；**C 端可见范围未决，实现不得先于该决定**）

## 决定

站点查询的能力（范围推导、逐行归属核对、分页上限、`total` 口径、呈现语义）只保留
**一份实现**，被三个入口共用：

| 入口 | 形态 | 状态 |
| --- | --- | --- |
| 管家对话回合 | `kind=site_search`，四字段协议 | 已上线（ADR-0165 / 0172） |
| 节点工具 | `cpms_site_search(name, address)` | 待 P1–P3 |
| 用户端只读 API | `GET /v1/sites` | 待实现，纳入公网 OpenAPI |

`GET /v1/sites` 采用查询参数 `name`、`address`（形态同 `cpms_site_search` 的参数，
判据同 ADR-0176），分页上限由服务端固定，**不接受调用方指定 `size`/`current` 上限**。
响应必须带上 `total` 的口径标记——员工账号的 `total` 是租户口径（ADR-0172 已记录这个
事实错误风险），三个入口都要带同样的语义，换入口不会让这个坑消失。

增补到 `src/aiops_diagnostics/gateway/public_openapi.py` 的 `OPERATIONS` 需要**显式加一行**
（ADR-0156：公网规范只公开显式登记的操作），这是本决定唯一需要碰的发布面。

## 依据

三处共用不强，但「逐行核对 `tenantId` 与站点集合」是安全判据
（`operator_cpms.py:956-966`），复制三份就必然漂移，而漂移的方向永远是放宽。
同一个理由已经在别处被验证过：`operator_cpms.py:942-955` 的响应信封校验只写了一次，
`query_sites` 与订单诊断共用 `cpms_get` 的信封校验。

用户端两个形态都要，理由不同：前端拉列表需要可缓存、可分页的 REST；用户用自然语言问
需要对话。它们不是同一个东西的两种外观，不能只做一个。

## 被否掉的替代形态

**只做对话，前端读 QA 快照。** 最强的地方是零新增对外契约：结构化站点就在
`snapshot.sites` 里（`operator_cpms.py:548-551`），一个端点都不用加。它输在 QA 是运行时
对象——有 TTL、有取消态、有「撤权后不交付」的规则，用它当列表数据源意味着前端要起一个
会话、发一句话、轮询一个异步任务，才能拿到一张站点表。

**只做 REST，对话里不再支持站点。** 最强的地方是形态最干净：一个端点、一份契约、
一套权限，不用再维护四字段对话协议里的 `site_search` 这一支。它输在两件事：用户端
已经明确要自然语言问；而且对话那一支已经上线并在 41 上验收过，撤掉是净损失。

**三个入口各自实现。** 最强的地方是各入口可以按自己的口径裁剪，例如 C 端只返回站名
不返回地址。它输在判据复制——`total` 口径这个坑已经在 ADR-0172 里踩过一次，
复制之后它在某一条路上一定会重新出现，而且不会有测试变红。

**`GET /v1/sites` 要求公司 Bearer（复用管家鉴权）。** 最强的地方是范围判据现成：
`operator_scope` 已经处理了 `all`/`organ` 与员工站点集合。它输在 C 端用户的凭据是
`third-session`，没有公司令牌；要求公司令牌等于要求 C 端用户是公司员工。

## 后果与验证

- **C 端可见范围是一个未决问题，不能顺手实现。** C 端调用者的 `DataScope` 是 `self`，
  `resolve_query_scope` 对 `self` 返回 `site_ids=None`（`identity/query_scope.py:273-281`），
  而在 `query_sites` 里 `None` 表示**不过滤**（`operator_cpms.py:1021` 只在 `site_ids != ()`
  时进入查询循环）。直接复用等于把整租户站点名单交给任何 C 端用户。三个候选各有不同含义：

  | 候选 | 含义 | 代价 |
  | --- | --- | --- |
  | 公开目录 | 租户的站点名单本身是公开信息，C 端可见全部 | 需要确认租户侧是否所有站点都可公开 |
  | 与本人订单有关联 | 只返回该用户充过电的站点 | 用户问「附近有什么」时几乎必然空结果 |
  | 不向 C 端开放 | `GET /v1/sites` 只服务 `operator` 入口 | 用户端「两者都要」里的 REST 一半落空 |

  这条决定必须先落成记录，`GET /v1/sites` 才能开始实现。
- 三个入口的呈现语义要对齐：列举与搜索的「没有结果」含义不同（ADR-0172 已定），
  这个区分在 REST 里不能退化成同一个空数组——至少要有可区分的标记。
- 「距离排序、实时价格、空闲枪口」仍不在范围内（ADR-0165 的边界）。
- 验收：三个入口对同一账号、同一关键词，返回的站点集合与 `total` 口径必须逐项相同；
  另有一条针对 `total` 口径的变异测试——把 `scope_limited` 恒置为 `false` 时必须有断言变红。

方案与分期见 [工具架构](../agents/operator-cpms/tool-architecture.md)。
