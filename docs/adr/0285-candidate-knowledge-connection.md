# 285. 候选知识连接使用复合资源凭据与现有共享接口

状态：已采纳；接续ADR0284，应用准备和正式激活仍独立验收。

## 决定

已核候选知识资源通过后，中央为该工作区准备Dify外部知识API连接。
复用现有共享知识适配入口，但凭据明确绑定环境、租户、工作区和单个知识库；根密钥不离开中央。
原环境任务账本保存连接准入与创建意图。最新对应任务取消、撤权或目录漂移时拒绝；证据过期不自动删除资源。
知识库实际归属每次按复合空间核对，不使用控制环境默认库或原共享凭据的全部来源。
已发出连接创建但结果未知时只对账，零命中等待、多命中阻塞；新计划复用同资源，不绑定应用或发布。

## 替代方案

复用原全局知识密钥最少接线，但它不能表达跨环境的单库授权，也可能查到控制环境的同号租户。
把所有知识API凭据部署到每个业务服务器便于沿旧接口运行，却增加目标依赖与配置，且当前目标未配此能力。
新增知识代理服务便于独立扩展，但已有适配层足以验证有限资源范围，选用现有入口的受限身份。

## 后果

原生产/调试凭据行为保持；候选凭据不授权公司取数、应用发布或环境准入。
任务及工作区映射共同控制凭据生命周期；修改目录后需重新准备验证，不能把缓存回执当永久许可。
连接成功只证明单库接口接线；内容、应用、业务与完整双环境验收尚未完成。
依据[RFC9110§9.2.2](https://www.rfc-editor.org/rfc/rfc9110.html#section-9.2.2)保持POST未知结果对账；
Bearer交换遵循既有Dify External Knowledge API，凭据不写浏览器、任务正文或日志。
