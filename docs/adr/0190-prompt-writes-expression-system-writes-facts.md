# 190. 页面提示词控制表达，运行冻结版本与本轮事实

日期：2026-10-30
状态：已采纳

## 背景

产品要求客户端在「选择答复类型与知识引用」SYSTEM、管家在编排页提示词中调整表达，
通过页面试用、发布和恢复。旧路径固定渲染正文；候选多轮修复又出现文件绑定被空管理表
误判撤回、只检查worker漏掉取数回调、事实片段协议与实现不一致等问题。

## 决策

- 业务提示词仍在原编辑区；客户端第二个SYSTEM是系统协议块，迁移只替换有标记的协议块，
  保留业务文字并按名更新契约变量。新版发布校验协议完整性，旧发布版本保持原行为。
- 客户端callback_version=5使用完整事实段：模型在独立行引用status_line或billing_line，
  系统用本轮快照与现有多语言模板填充，包含订单、来源、时间及业务限制。协议要求本轮
  status=live时kind=realtime，不能把live_snapshot当知识引用。版本4以前沿用原正文协议。
- 自由表达负责语气、解释与追问；校验数字、链接及明确执行承诺，但不声称词表能证明所有
  自然语言推理正确。完整事实段不能拼接进模型自己的句子，未知币种保持未知。
- 保存已校验reply模板，回读时重新填同轮事实并与缓存比较；禁止后续改版重新生成历史答案。
- 客户端worker、回调、回读使用同一绑定规则。管理绑定按不可变Agent版本恢复原workflow_id；
  普通发布可以推进版本，当前应用、凭据、知识库和能力仍需覆盖原授权。文件绑定不要求空
  管理表里存在行；真实撤回不能回落文件。
- 管家复用run.execution_manifest，新增publication_app_id记录Dify应用身份，避免与执行平台
  app_id混淆。运行清单自身的SHA始终校验；当前发布需允许同模型/端点和已授工具。纯提示词
  更新不撤销旧运行，撤回/缩小工具/换应用拒绝。历史无新增身份的记录保持严格revision检查。
- 管家JSON允许reply承载按提示词组织的完整正文；结构化诊断依据保留，来源由系统追加。
- 普通澄清可由新版提示词表达，紧急安全、权限拒绝和系统故障保持可靠系统输出。

## 标准映射与取舍

沿用Dify 1.17.1的system消息、草稿/发布版本和JSON输出；不引入另一套发布系统。
JSON仍是内部协议，用户正文由Gateway交付blocks。Dify官方LLM和Version Control文档已核对。
运行数据库只做新增列的幂等迁移，不回填/重算历史数据。取数授权、有效期、取消和撤权不放宽。

代价：新版事实部分保持确定性，提示词可改变其周围表达，不能改变事实本身。模型仍有生成失败
与时延；实际语气需人工观感及模型样本验证，单测不证明诊断准确率。

## 被否的替代方案

- 继续扩大数字/状态关键词词表：不能证明自然语言含义，且误拒正常表达。
- 把提示词移到命令行文案包：没有满足产品指定的页面入口。
- 用当前版本重算旧答复：破坏冻结证据和恢复语义。

## 验证

仓库用例覆盖文件绑定/空管理表、取数前后发布、回读、撤回、能力缩小、事实段正负例及多语言。
本次隔离真实Dify/Gateway 73项通过（外部模型/业务数据合成）；真实模型客户端10次样本通过。
正式页面/原H5与部署验收仍单独记录，不以这些结果替代。候选早期失败证据保留在私有复核目录。
