# Jev 阈值按真实流量复标（#390 / #392 follow-up）

> **结论：保留 `risk >= 0.5` 且 `confidence < 0.8`，但必须改变对它的期望。**
> 真实流量揭示了一个在 n=10 样本里看不见的事实：**Jev 对"涉钱"的问题同样非常自信**，
> 因此这条规则在真实流量上**几乎不触发** —— 与现状分类器一样。

**样本**：41 生产库中 **86 条去重真实提问**（2026-09-12 → 09-23）。n=10 → n=86。
**零失败**：86/86 均得到判定。延迟中位 **0.66s**（0.57–0.83），与 #390 一致。

复跑脚本 `tools/jev_recalibrate.py`；语料 `docs/jev-recalibration-corpus.json`；
原始结果 `docs/jev-recalibration.json`。语料为真实用户提问，**不含用户身份**，订单号上游已脱敏。

## 一、最重要的事实：规则在真实流量上仍然不触发

按已部署的阈值（`risk>=0.5` 且 `conf<0.8`）：

```
would_ask = 0 / 86
```

**不是阈值定错了，是数据形态如此。** 高风险那 5 条的真实取值：

| risk | confidence | 是否追问 | 问句 |
|---|---|---|---|
| 0.85 | **1.00** | 否 | 帮我看看我的订单扣费对不对，感觉多扣了钱 |
| 0.74 | **1.00** | 否 | Please check charging anomalies for order (REDACTED) |
| 0.62 | **0.97** | 否 | 我上个月的充电扣费感觉多扣了，帮我看看对不对 |
| 0.60 | **1.00** | 否 | 帮我检测（REDACTED）这个订单的充电异常 |
| 0.55 | **0.97** | 否 | refund |

**Jev 认出这些是涉钱问题（risk 0.55–0.85，与其余 81 条的 0.02–0.10 分得很开），
但同时对"这是涉钱问题"这件事极度自信（confidence 0.97–1.00）。**

而规则要求**两件事同时成立**：高风险 **且** 拿不准。真实流量里这个组合一次都没出现。

这与 #390 在现状分类器上发现的是**同一个形态**：那时是"`risk=high` 但 `conf=high`"，
现在是"`risk` 高但 `confidence` 更高"。**换成 Jev 并没有让这条规则开始工作。**

## 二、我必须更正上一份验收记录里的一句话

#400 的验收记录写了：

而**真实用户表达同一诉求时用的是另一种句式**：

**"3/3 稳定"是真的，但它证明的是"我的示例问句会触发"，不是"真实流量会触发"。**
用自造问句验证出来的结论，被我当成了生产行为写进验收记录 —— 这正是 #390 用 10 条

## 三、数据形态

**risk 分布**（双峰，阈值落点很稳）：

```
min 0.02 | p25 0.03 | median 0.05 | p75 0.10 | max 0.85
  81 条 <= 0.34      5 条 >= 0.55      间隙 0.34..0.55（落点区间）
```

**0.34 与 0.55 之间没有任何取值**（实际档位：…0.26、0.30、0.33、0.34 ｜ 0.55、0.60…），
所以 `risk_at_least` 取**大于 0.34 且不大于 0.55** 的任何值，高低风险划分相同。**0.5 落在这个
间隙内**，安全。

⚠️ **更正**：初稿写的是"0.3–0.7 之间没有任何取值" —— **错了**，语料里有 0.30/0.33/0.34。
按实际数据，取 0.3 与取 0.5 **不同**（`conf<0.9` 那一列：1 vs 0）。

**confidence 分布**（这决定了阈值有多脆）：

```
min 0.33 | p25 0.77 | median 0.995 | p75 1.00 | max 1.00
```

中位数 0.995，**85/86 在 0.95 以上** —— 绝大多数判定是满分自信，这个量在本语料上几乎没有区分度（p25 已是 0.77）。

## 四、一个需要你决策的风险：阈值离观测值太近

`confidence_at_least = 0.8`。真实流量里最近的观测值是 **0.81**
（`Tell me about the Singapore autonomous electric bus project`），**距离仅 0.01**。

#390 已实测 Jev 的 confidence 在两次运行间会漂移（0.71 → 0.67）。**0.01 的余量小于观测到的漂移量**
—— 这条问句可能今天不追问、明天就追问。

但这次**不要急着调**，因为：

- 目前 `would_ask = 0`，这条边界**不影响任何真实问题**（它 risk=0.04，远低于 0.5）；
- 唯一落在脆弱带附近的问句是德语 `Wurde ich für diese Ladesitzung überladen?`
  （risk=0.34，confidence=0.84）。**它按业务语义是高风险（德语「我这次充电被多收钱了吗」），
  但被 `risk >= 0.5` 分成"低风险"** —— 挡住它的是**风险阈值**，不是 confidence 阈值。

  ⚠️ **这里正是本报告要区分的一件事**：`risk=0.34` 在**业务上**是涉钱问题，
  在**程序分桶上**是 low。措辞混用会让读者以为分桶等于语义。**分桶只是阈值的结果，
  不是对问题的判断。** 上一条注释同理（risk=0.04 的纯咨询问题，两边都不是高风险）。

也就是说：**接近 0.8 的观测值恰好都不是高风险**，所以脆弱性目前不产生可见影响。一旦
真实流量里出现"risk 高且 confidence 在 0.75–0.85"的问句，就会立刻显现。**这是要盯的。**

## 五、建议（不改配置）

**保留 `risk>=0.5` / `confidence<0.8`。** 理由：

1. **阈值本身没问题** —— 风险双峰、间隙 0.21，0.5 落点稳且不敏感；
2. **但阈值确实能改变结果，成本比我初稿说的小得多。**（初稿写"要触发得提到 0.97 以上，
   那会让**几乎所有问题**都被追问" —— **后半句错了**：追问始终被 `risk >= 0.5` 闸住，
   **最多只有那 5 条高风险问句**，不可能"几乎所有"。实测，固定 `risk>=0.5`：）

   | confidence_at_least | 追问条数 |
   |---|---|
   | 0.8（当前） / 0.9 / 0.97 | 0 |
   | **0.98** | **2** |
   | 0.99 | 2 |
   | 1.01（等于忽略该项） | 5 |

   **取 0.98 恰好追问两条，且正是那两条真实扣费投诉**
   （`我上个月的充电扣费感觉多扣了,帮我看看对不对`、`refund`）。
   这不是"几乎全部"，而是"精确命中涉钱问题"。

   代价：0.98 落在观测值（0.97–1.00）**正中间**，按第四节的脆弱性标准不安全 ——
   一条问句漂移就会改变行为。**所以调阈值是可行的止血，但不稳；
   改规则语义（方案 A）才是稳的，且效果同样是盯住那 5 条高风险。**

**真正该做的是改规则语义**（属于产品决策，不在本片范围）：

| 方案 | 含义 |
|---|---|
| **A. 高风险一律追问** | `risk >= 0.5` 即追问，不看 confidence。最贴近"涉钱就别猜"的原意，代价是多一次交互 |
| **B. 高风险 + 有订单号才追问** | 只有真能执行的高风险动作才拦；纯咨询不拦 |
| **C. 维持现状** | 承认这条规则基本不触发，等同于只记录不拦截 |

**我倾向 A** —— 因为 Jev 已经能可靠分出"涉钱"（0.02–0.10 vs 0.55–0.85），
而 current 的 `confidence` 条件实际上让这个可靠的信号失效了。**但这是产品语义变更，
需要你定，不应由我在复标里悄悄改掉。**
