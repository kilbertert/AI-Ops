# H5 聊天页实际调用的网关路径 —— 唯一声明处。
#
# 每条都是 H5 产物里真实出现过的调用（读法与出处见 ops/h5-assistant-routes.md），
# nginx 只转这一组。`tests/test_h5_assistant_routes.py` 断言：
#   1) 这里每一条都被 nginx 的正则命中；
#   2) 网关 /v1/ 下**其余**路由一条都不命中。
# 新增一行而不同步 nginx 片段、或把正则该死的路径放进来，CI 都会红。
#
# 形状：<方法> <路径模板>；{qa_id}/{job_id}/{diagnosis_id} 是 32 位十六进制。

GET  /v1/faq/recommendations
GET  /v1/faq/catalog
POST /v1/faq/answer
GET  /v1/shortcuts
GET  /v1/media/{signed_id}
POST /v1/assistant/questions
GET  /v1/assistant/questions/{qa_id}
POST /v1/assistant/questions/{qa_id}/cancel
POST /v1/health-report-jobs
GET  /v1/health-report-jobs/{job_id}
# 以下三条的上游路由已退役（被 /v1/standard/analyses 取代），声明保留是因为
# 已部署的 H5 产物仍可能发出这些调用——转发后由网关给诚实的 404/405，比静默
# 落到默认处理更可诊断。2026-11-13 日志观测：ulink.h5 上 658 次 GET 均为
# 10-25~28 的本机验证流量，退役后仅 1 次外部 curl 探测。从声明集中移除是
# 一次独立的暴露面变更，按共识先观测流量再决定，不在文档订正中顺手删。
POST /v1/standard/diagnoses
GET  /v1/standard/diagnoses/{diagnosis_id}
POST /v1/standard/diagnoses/{diagnosis_id}/cancel
