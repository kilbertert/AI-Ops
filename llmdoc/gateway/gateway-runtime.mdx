# Gateway 运行时：启动、配置与边界

## 启动顺序（serve()）

`src/aiops_diagnostics/gateway_server.py` (serve)：isolation_guard → `Settings.from_env()` → `validate()` → `require_deployment_identity` → `configure_gateway_logging` → `create_gateway_app` → uvicorn（`log_config=None`、`proxy_headers=False`、`server_header=False`）。

- 隔离检查排第一且仅当 `M2LIVE_ISOLATION_ROOT` 设置时生效；拒绝即退出码 2。ADR-0039：隔离必须是产品启动路径内的闸——一个继承生产 `AIOPS_GATEWAY_DATABASE_FILE` 的试用实例会写穿生产 gateway.db，"业务只读"不等于"无副作用"。
- `create_gateway_app` 内（`gateway/gateway_api.py`）：校验 → 建 store → `gateway_schema.startup` + `KeyOperations.clean_legacy()`（旧格式误存 token 按数据探测原位剥除——老程序回滚会再写，schema 版本代替不了探测）→ **`recover_interrupted_jobs()` 必须在 serving 之前**（不能放 `__init__`：短寿命 CLI 也开同一个库，会把活任务杀掉）→ resolver/authorizer 装配（集中于 `gateway/dependencies.py` 的 `build_dependencies`），各处注入失败一律 empty/fail-closed，绝不让"可选增强"变成放行。非 HTTP 装配面 `GatewayRuntime.__init__` 同样先过 schema 闸。
- `GatewayRuntime` 本体只剩线程池、取消登记与共享 store 容器：聊天 QA 执行（Dify/节点两路线）在 `gateway/chat_job_runner.py`，试运行并发闸与范围构造在 `gateway/trial_job_runner.py`，健康/ops-analysis 执行器在 `health/`、`operator/` 包——找执行逻辑不要在 runtime 里翻。

## 配置合同

- `gateway/gateway_config.py` (SETTING_SOURCES)：每个字段声明 env 名、是否可读文件、类型、默认——**"一个设置从哪里读"的唯一权威表**。`missing`-only-fallback：文件值仅在进程 env 缺省时补位；`KEY=`（空串）就是一个值；`file=False` 的字段永不读 production.env。显式点名却不存在的配置文件 = 启动失败。
- `validate()` 最先是 schema 闸：对已存在的 `database_file`/`chat_route_bindings_file` 各跑 `gateway_schema.startup()`——**同版本漂移也拒绝启动**，bindings 独立成文件时受同一份结构合同管；随后委托 `gateway/gateway_config_groups.py` 的五组类型化冻结子配置分段校验（`http`/`knowledge`/`onboarding`/`caller_auth`/`dify`）。半配置对拒绝语义保留在组校验器内：成对出现的 URL+key、互斥通道（`company_jwt_key` XOR `check_token_url`）、source_key 要求至少一条校验通道且 ≥16 字符、bindings/manifest 在启动期全量校验。理由不变：半配置在运维上的表现是"永远 401"，与未配置无法区分，所以挡在启动期。
- 分组是只读视图不是重写（ADR-0333）：平坦字段与 env 键名 100% 兼容，`http`/`caller_auth`/`dify`/`knowledge`/`onboarding` 只是属性投影；`load_data_sources()` 把 `common.config.Settings` 折进同一棵配置树。改配置仍改平坦字段，不要发明第二套键。
- `deployment_environment.py`：`AIOPS_GATEWAY_ENVIRONMENT` 是部署身份，serve 时必填；只做合法性校验**不做归一化**（`prod.41`/`prod`/`41` 是三个不同身份）；workspace 查寻由部署身份派生环境，绝不从请求取（请求带 env = 400，跨环境查寻才是真正的越权路径）。ADR-0059。
- `.env.example` 是 SETTING_SOURCES 合同面向运维的复述，逐键对应有测试钉住（镜像测试只收 `AIOPS_GATEWAY_*` 前缀键；`AIOPS_MYSQL_MALL_DATABASE` 这类非前缀键只有文件内断言——置空 = 该环境无商城侧证据）。

## 运行边界与观测

- 日志（`gateway/gateway_logging.py`）：uvicorn 的 dictConfig 只给 `uvicorn*` logger 挂 handler，root 无 handler——`aiops.*` 的 INFO 曾全部丢失。修复 = 装 root handler 并配 `log_config=None`，两者是配对，单独改一边都会复发。
- `public_openapi.py`：公开规范由显式 `OPERATIONS` 白名单生成，新内部路由不会自动出现；方法是边界的一部分（GET /shortcuts 是用户面，POST 是管理面）。第二份显式边界清单 `OPERATOR_ONLY_PATHS` 给管家专属路径在生成规范里标注 `OperatorBearer` 安全方案与枚举约束，两份名单都有测试钉住。
- **路由全表**（ADR-0344）：`gateway_api.py` 里一个 `@app.*` 都没有——原住其中的路由全部按业务域搬进 `gateway/routers/` 十三个模块（agents/assistant/assistant_actions/conversations/dify_console/files/health_analysis/health_faq/internal_callbacks/knowledge/media/orders_sites/shortcuts），各自导出 `register(app, context, deps, api_module)`，由 `create_gateway_app` 尾部三段式骨架挂载：`dify.self_service_api` → `/v1/dify/management/*`（`onboarding.management` 与 `dify.operator_run_logs_api` 仍嵌在其内）→ 域模块单循环 → `onboarding.trial`（`/v1/internal/environment-trial`）+ `install_public_docs` 公开文档对（`@app.get` 住在 `public_openapi.py` 内）。grep `@app.` 在 gateway_api.py 零命中，**三段挂载骨架才是权威索引**；`errors.py`（StandardAPIError 共享异常）、`schemas.py`（请求体唯一声明）、`dependencies.py` 是域模块共用的抽取层——ADR-0349 增补 `conversation_helpers.py`（轮次认领/订单守卫）、`response_views.py`（响应序列化）与 `caller_auth_wiring.py`（身份链接线，语义归 [identity-scope](../identity/identity-scope.mdx)）；路由路径在拆分中全部未变。
- `request_observation.py`：每个候选请求恰好一行 INFO、不落库（第二个分母会漂移）；身份解析之前绝不记录；上报永远不能让响应失败。`metrics_store.py` 的 `agent_run_metrics` 按构造脱敏；`ROUTE_TYPES` 里的 `"promo"` 是历史只读词汇——`record()` 拒未声明类型，该成员只为读存量行保留（宣传路由随 #1125 退役），别当死配置删。
- `localized_copy_language`（实现住 `gateway/dependencies.py`）挂在恰好七个确定性文案出口（`/v1/faq/recommendations`、`/v1/faq/catalog`、`/v1/faq/answer`、`/v1/assistant/starters`、`/v1/shortcuts`、`/v1/banner`、`/v1/assistant/agents`）：每请求一行 INFO 记 path + 逐字 `Accept-Language`（截 160 字符只为限长，运输层禁 CRLF 伪造不了额外行）+ resolved tag。刻意不并入 `request_language`——chat/trial/analysis 的语言已持久化，文案端点不留痕时客户端发错头无从定位。
- `admin_cli.py` 只是薄装配壳（ADR-0339）：Typer 根 + `admin/{onboarding,dify,knowledge,maintenance}` 四个子包的 `register()`——**命令名全部未变，变的只是文件布局**：schema/reconcile/consumer-copy 族在 `admin/maintenance.py`，pull-dify/ensure-workspace/ensure-ready 族在 `admin/dify.py`，onboard-tenant/credential 轮换/knowledge 族在 `admin/knowledge.py`，`environment-*` 开通命令族在 `admin/onboarding.py`（语义归 [environment-onboarding](environment-onboarding.mdx)）。特权合同不变：`schema check|migrate --db`（check 只读报告、migrate 先 ensure 再 check）拒绝统一输出 `{"error":"SCHEMA_REFUSED","type":<类名>}`，不外泄可能携带用户 SQL 的原始错误；迁移类命令构造合成 ASSERTED ScopeContext，不走请求身份。
- `tdengine_proxy.py`：独立部署的只读遥测代理——监听和上游都限回环（`is_loopback_host` 唯一回环规则）、仅 `iot` 库、仅 POST `/rest/sql/iot`、SQL 白名单（`SHOW STABLES`、精确 `GUN_QUERY` 或精确 `COMM_QUERY`——后者读 `charging-pile_comm` 帧、码表受 `COMM_ALLOWED_CODES_SQL` 收口）、≤168h、≤2000 行、无日志。`GUN_COLUMNS` 与 `COMM_*` 列/码常量同 `data/sources.py` 共享一份字节——两个独立部署，漂移会被在线代理拒绝，所以共享不复制。

`include_composition=True`；旧callback默认False，均复用既有主体端点与调用方前后授权。
