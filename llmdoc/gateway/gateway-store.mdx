# Gateway 存储纪律

所有应用账本集中在 Gateway 的 SQLite 里；连接事务由 `gateway/gateway_db.py` 的具名 profile 统一。**调用方不得自己 `sqlite3.connect` 这个文件**——绕过 profile 就绕过了锁序与忙等纪律。

## 连接 profile

- `LEASE`：`BEGIN IMMEDIATE` 在进入块时拿写锁——一切读-改-写、多语句、DDL 都走它。
- `SINGLE_STATEMENT`：autocommit，仅当块可证明只写一条语句且没有读-改-写时使用。
- 未知 profile 直接抛错（无静默回退）；共享参数 `timeout=5`、`foreign_keys=ON`、`busy_timeout=5000`。
- `initialize()`：先在事务外切 WAL——`journal_mode=WAL` 遇 SQLITE_BUSY 会绕过 busy_timeout 立即返回，故在共享 5s 期限内**只重试这一步**并校验返回值确为 `wal`——再一次 LEASE 完成全部建表。`connection(readonly=True)` 以 `?mode=ro` URI 开只读连接（readonly+write 抛 ValueError），`check`/`rehearse`/`clean_legacy` 探测走它。ADR-0243：`executescript` 会隐式 COMMIT（这是它取代逐条 execute 时的陷阱）；`MappingStore/mappings.db` 仍是唯一例外。

## 迁移与恢复

- `gateway_schema.py`（ADR-0244）是 28 张表的唯一结构权威：`TABLES`/`INDEXES`/`LEGACY_COLUMNS` 一份声明同时驱动 CREATE、白名单 `ADD COLUMN` 与结构校验，`PRAGMA user_version` 记版——`_version()` 接受 `0 <= v <= VERSION`：0 = 版本化之前的历史库，`1..VERSION-1` = 已知历史发布（缺的列须由 `LEGACY_COLUMNS` 白名单放行才过 legacy 校验）；只有更新版本写出的库/非法值（`>VERSION`、负数）才 `SchemaError`——旧代码开新库 fail closed；`check()` 的 legacy 判据是 `version < VERSION`（旧版返回可迁移报告而不是报错）。`ensure()` 在**一次 `gateway_db.initialize` 写事务**内升级：锁内重读版本防多进程重复升级，校验失败整体回滚；已知旧版在同一事务内补列+抬 user_version，补列全做完才建索引——「索引必须排在 ALTER 之后」的顺序陷阱改由内序结构性保证，不再靠注释钉住。**ALTER 绝不回填**。VERSION 现为 2（ADR-0251 新增 `agent_runs.tool_summaries_json`，已入 `LEGACY_COLUMNS`）：v1→v2 是首个真实版本化迁移，已在 41 生产库由 `ensure()` 自动完成——评审曾把「只认 0/VERSION」的旧逻辑判为部署即启动阻断（钉 v0 的 `historical()` 覆盖不到 v1）；教训：bump VERSION 时旧版本=现网库。
- `gateway_store.py` (_initialize)：只剩 `gateway_schema.ensure(self.path)` + 私文件保护；共用 gateway.db 的各 store 同样委托，per-store `_migrate_*` 已删净——结构变更唯一通道是改 `TABLES`/`LEGACY_COLUMNS` 并抬 `VERSION`。
- `recover_interrupted_jobs`：把 queued/running 收敛到 `failed` + `*_INTERRUPTED_BY_RESTART`，**只走 boot path**（见 [gateway-runtime](gateway-runtime.mdx)）。每次写入仍走该表自己的更新路径，claim-guard 与 retention 照常生效；同时释放会话生成槽位（`ConversationStore.recover_interrupted_turns`）。

## 作业生命周期（async_job_lifecycle.py）

- `JobProfile` = `deadline / completed_retention / interrupted_retention` 三元组；HEALTH_JOB 30s、DIAGNOSIS/QUESTION 15min。
- 三个终态判定分开：`converged(restart)` → failed + `*_INTERRUPTED_BY_RESTART`；`user_stop` → cancelled；`deadline` → expired。`expired` 与 `failed` 同档但语义不同，不要合并显示。
- **retention 永不撤销已交付结果**（ADR-0091）：清扫绝不碰 `completed` 行——曾有 sweep 把已完成改写成"没结果"，94 条历史行因此错误。

## 两本运行账（词汇一致、表不同）

`agent_runs`（Java 节点运行）与 `chat_dify_runs`（Dify 运行）是两张表，状态词汇相同：`issued/running/succeeded/failed/revoked/expired`（`chat_dify_runs` 用同一套语义）。分开是刻意的：Dify 运行没有节点形状字段（`expected_node_id`、`exec_config_state`），共用一张表会让列说谎。`assistant_questions` 是 QA 作业账（`qa_` id），`status_qa_id` 把会话回合链回作业行。
