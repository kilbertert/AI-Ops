# AFK 规划与仓库交付

## 阶段闸

`idea → /grill-with-docs → /to-spec → /to-tickets → implement → review → merge`。澄清完成后报告 `GRILLING_COMPLETE`、请用户确认并结束；确认不自动授权下一阶段。规格、子 issue 和依赖由对应阶段记录；实现按 [交付约定](../../docs/agents/actions-delivery.md) 走任务分支和 PR。合并不等于部署或验收。

## 当前门禁接线

- [`afk-policy.yml`](../../.github/workflows/afk-policy.yml) 通过 `kilbertert/fleet-kit/actions/policy-gate@v1` 保持必需检查名 `Workflow policy`；[`.fleet-kit.json`](../../.fleet-kit.json) 启用 ADR 检查及 [本仓冲突面脚本](../../tools/verification/conflict-surface.mjs)。
- `verify` 来自 [CI](../../.github/workflows/ci.yml)，和 `Workflow policy` 一样不得用顶层 `paths` 跳过。规格树 lint 只作提示；Sync Open PRs 不负责合并。
- [#1833](https://github.com/kilbertert/AI-Ops/pull/1833) 后，旧 `.sandcastle/`、旧宿主 planner 命令及 agent 实现工作流不再随本仓提供。定位门禁先看失败步骤，勿恢复旧脚本或把历史沙箱文档当作当下接线。Runner 标签仍只用于调度，见 [Runner 队列](../../docs/agents/runner-queue.md)。
